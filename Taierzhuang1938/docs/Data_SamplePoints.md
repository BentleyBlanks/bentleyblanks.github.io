# 县城场景采样点（Data_SamplePoints）

> 一句话：**同一批机位、同一套参数，隔一段时间再拍一次**，两批图逐张对位就是这段时间里
> 场景样式的真实变化。这是基线，不是花絮。

## 一、为什么要这套东西

城一直在改：材质换一版、后期改一档、布设加一批家什、地标补一座。
改完「好看了没有 / 退化了没有」靠回忆判不出来 —— 每次随手拍的机位都不一样，
两张图之间的差别里混着机位差、天光差、时段差，看不出哪一份是这次改出来的。

采样点把机位钉死，把变量收敛到一个：**场景本身**。

## 二、四个文件的分工

| 文件 | 职责 |
| --- | --- |
| `Data_SamplePoints.mjs` | 点位表本体（纯数据，不 import three） |
| `Script_SamplePoints.mjs` | 位姿解析、入表校验、出图计划（node 与浏览器共用同一份口径） |
| `Script_EditorSamplePoints.mjs` | 游戏内「采样点编辑器」：逐点预览、微调、增删、导出 |
| `Script_SamplePointShot.mjs` | 一键出图：拍完全部点位 + 逐帧读数 + 清单 + 与上一批对位 |

**位姿只有一处口径**：出图脚本不自己算机位，它开的就是采样点编辑器，逐点调
`Debug.SamplePoint(id)`。所以面板里预览到的就是将来那张图，不存在「编辑器里
好好的、出图出来是另一个角度」。

## 三、位姿字段

```js
{ id, label, group, phase, x, z, h | y, yaw | aim, pitch, fov, far, sky, outsideBounds, note }
```

| 字段 | 含义 |
| --- | --- |
| `x` / `z` | 世界坐标。X 东、Z 南，城心为原点 |
| `h` | 相机离**地面**的高度（米）。默认 1.7 = 站着的人眼 |
| `y` | 绝对高度。写了 `y` 就不查地高 —— 城墙顶（13.2）、空中俯瞰用它。与 `h` 二选一 |
| `yaw` | 弧度。**0 朝北(-Z)、π/2 朝西(-X)、π 朝南(+Z)、-π/2 朝东(+X)** |
| `aim` | `[x, z]`：写了就按「站在这里看那里」算 yaw，比手写弧度好读 |
| `pitch` | 弧度，**正数是抬头**（仰视城楼 +0.2 这一档） |
| `fov` / `far` | 不写就退回本关出厂值。**不写不等于沿用上一个点位** —— 那会让一批图有顺序依赖 |
| `sky` | 覆盖本关天光。夜战关（1/3/6）里的关厢建筑必须覆盖成 `smokyDay`，否则图上只有黑色轮廓 |
| `outsideBounds` | 机位站在本关切片外往回看城。只有空中机位用得着；地面机位站在切片外就是站在没生成的空地上 |

`phase` 选哪一关不是随手写的：**点位必须落在那一关的 bounds 里**
（`Data_Battle.TUNING[*].bounds`），否则那一片根本不生成。当前分工：

| phase | 切片 | 天光 | 覆盖 |
| --- | --- | --- | --- |
| 4 `L4_Chengqiang` | x −360…620 / z −360…400 | smokyDay | 全城 + 四面墙 + 东关，绝大多数点位 |
| 2 `L2_Dongguan` | x 250…620 | smokyDay | 东关关厢细部 |
| 1 `L1_Beishahe` | x −620…−230 | night → 覆盖成 smokyDay | 西关（车站、电灯厂、通信队、师部、交易所） |
| 6 `L6_Beimen` | z −640…200 | night → 覆盖成 smokyDay | 北关（大街、圩门、庙、弘道院） |
| 3 / 5 | — | night / burningStreet | 「关卡时段对照」组：同一机位换一关，记录七关各自的样子 |

## 四、一键记录

```bash
node Taierzhuang1938/Script_SamplePointShot.mjs
```

产物落在 `Taierzhuang1938/_shots/Sample_<YYYY.MM.DD>/`（已 gitignore）：

- `<序号>_<id>.png` —— 基线原图，无损，本地对比用
- `<序号>_<id>.jpg` —— 同一帧的 JPEG，体积约十分之一，发文档用
- `Manifest.json` —— 每张图的**真实位姿**（相机实际落到哪、地高多少）+ 逐帧读数
- `Index.md` —— 分组清单，本身就是记录文档的正文

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--group=Gate` | 只拍某一组 |
| `--only=id,id` | 只拍指定点位 |
| `--phase=4` | 只拍某一关的点位 |
| `--compare=_shots/Sample_2026.08.25` | 与上一批逐点对位，按差异排序 |
| `--jpeg=0` | 不出 JPEG |
| `--out=<目录>` | 落到指定目录。目录里已有 `Manifest.json` 就**合并**：只覆盖这次拍到的那几张，其余原样留着 —— 修好一个点位补拍一张不会冲掉另外八十八张 |
| `--settle=45` / `--warmup=240` | 落定帧数（默认值够用，改之前先想清楚为什么） |

### 让这批图「可比」的四条纪律

1. **机位不在出图脚本里算** —— 见上文，只有一处口径。
2. **一关只建一次城** —— 按关卡分批，关内连着拍完再换关。建一次城十几秒，
   八十多个点挨个重开页面就是二十分钟的纯等待。
3. **世界是停的** —— 编辑器接管期间玩法全停（与过场同一条通道），
   所以同一点位两次拍到的人、火、烟都在同一处。
4. 出图前会把编辑器会话存在 localStorage 里的改动**清掉**：
   一批带着别人未导出改动的图，等于这一批与历史全部不可比。

### 逐帧读数是干什么的

八十多张图靠肉眼比是比不动的。`Manifest.json` 里每张记了平均亮度、对比度、
暗部占比与 4×4 分块均值；`--compare` 把两批逐点做差、按最大分块差排序，
**先筛出「哪几张真的变了」，再拿眼睛去看那几张**。

顺带抓住最常见的一种废图：机位埋进了几何里 —— 那种图对比度接近 0，
出图时就会打上「警」并让脚本以非零码退出。

## 五、编辑器（游戏里按 ` 打开 → 编辑器 → 采样点）

- 左边点一个点位，相机就飞过去；点位不在当前切片里时会自动切关（可关掉）。
- 调机位的主路：**WASD+QE 飞过去看 → 满意了摁「取当前相机」**。
- 「对准目标」只对写了 `aim` 的点位有效：站着不动，把朝向重新对回目标。
- 面板里的改动存在 localStorage（刷新不丢），但**那不是基线** ——
  基线在源码里。改完要按「导出 mjs 片段」誊回 `Data_SamplePoints.mjs`。

## 六、覆盖率是被测试锁住的

`node Taierzhuang1938/Script_SamplePointTest.mjs`（纯 Node，秒级）锁这几条：

- 城里每一座**有名字**的建筑（`LANDMARKS` + 有 `label` 的 `CITY_FEATURES`）
  都有一个点位站在它附近、镜头大致朝着它；
- `STREETS` 里每一条街都有点位压在街面上；
- 四座城门内外各一张；
- id 唯一且是合法文件名、点位落在本关 bounds 里、导出的 mjs 片段能被重新解析。

所以「城里加了一座新地标 / 街网重排多了一条街」会在这里报出来，
而不是等一批记录出完、有人对着八十多张图数「怎么少了一处」。
