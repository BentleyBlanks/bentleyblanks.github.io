# 人物战场反应测试场（?reactions=1）与第一人称近爆反应

2026-10-21 用户要求：新增一个人物战场反应测试关卡，开着扬尘、有壕沟；第一项测试是主角的第一人称爆炸反应——附近炸响时人会歪头、低头、看爆炸的另一边、轻微闭眼一会儿，再加上耳鸣与肢体反应；耳鸣要像真实世界那样；反应的程度跟爆点到人的距离走。

本页管三件事：**测试场**（场地、面板、接口）、**第一人称身体反应**（`Script_BlastFlinch`）、**耳朵受损**（`Script_AudioEarTrauma`）。后两件是跨关卡的共用机制，接在通用近爆反馈那一条链上（[通用近爆反馈](Data_BlastFeedback.md)），由 `phase.blastReaction` 打开；**目前只有本测试场开着，正片默认不开**。

## 一发爆炸落到人头上有多响（`Script_BlastExposure`）

`Combat.BlastFeedback(position, radius, explosiveId)` 在算完遮挡之后，按**装药量**与**到眼睛的距离**算峰值超压：Kinney–Graham 自由场 TNT 拟合式，比例距离 Z = R / W^⅓，地面爆炸按 1.8 倍当量；换成峰值声压级 dB（20 µPa 为零）。遮挡（与震屏同一条射线判据）扣 8 dB；背对爆点那只耳朵被头挡掉最多 7 dB（正侧面满额，正前 / 正后不扣）。装药查 `Data_Explosives`，查不到按杀伤半径的立方反推。

## 第一人称身体反应（`Script_BlastFlinch`，`player.flinch`）

纯规则、零 three；`Combat.BlastFeedback` 经 `Player.BlastReaction(exposure, bearing)` 喂进去，`Player.Update` 推进，关着（`enabled = false`）时什么都不做。每一发是一个事件（最多 6 个），方向性的几项带符号求和再软限幅（连续炮击不会把头越拧越偏），其余取大。数在 `BLAST_FLINCH`。

| 反应 | 做法 | 去向 |
| --- | --- | --- |
| 眨眼 | 冲击到后 35 ms 合上（40 ms）、几乎不停、110 ms 睁开——一刹那（约 0.15 s）；远处只合一部分；闭紧过的近爆在 0.5 s 再眨一次（余颤） | 后期合成 `eyeClosure`（与剧情眼皮取大） |
| 闭紧眼 | 只有八九米内的近爆才有：单发最多闭死约 0.25 s 再睁开，强的之后眯一秒多。**连续炮击才越闭越久**：每发往累积量里加，2.5 s 漏掉，闭死的时长 ×(1 + 1.4·累积)、眯眼 ×(1 + 1.2·累积) | 同上；白天闭眼看到的是眼皮透光的暗红（`lidGlow`，夜里几乎不透；开场导演的闭眼不用它，仍是全黑） |
| 眼皮的边 | 眼皮贴着眼球、就在瞳孔前面两三毫米，视网膜上成不了一条边（过渡 ≈ 瞳孔 4 mm / 距离 3 mm ≈ 75°，比竖直视野还宽）：近爆眨眼是整片暗下去、上面先暗一点，不是一条线扫下来（2026-10-29 用户嫌原来的边太硬） | `Script_EyelidMask`（合成与白盒输出共用一份）；`BLAST_FLINCH.lidEdge`：过渡半宽 0.36 屏高、盖住瞳孔的整体变暗 0.55 × 闭合；开场剧情的眼皮仍是 `OPENING_PERCEPTION.lidFeather` 0.065 画出来的两片 |
| 扭头避开 | 冲击到后 70 ms 起，0.16 s 内转开：**背离爆点**（右边炸往左转），正前方炸按交替序列挑一边，身后炸基本不转 | 相机 yaw，叠在震屏之后，**不改玩家 yaw / pitch 本体**（枪口不被带歪，过后自己回来） |

| 收枪缩肩 | 枪往下压、往胸口收、枪口下垂；头转开时手臂慢半拍、转得少（反向转回 30%），所以枪在画面里往爆点那一侧甩、往下沉，但留在画面里（实拍时幅度翻倍那一档枪整个出了画面，像穿帮） | `Viewmodel.Update` 的 `input.blastFlinch` → `statePivot` |
| 手抖 | 之后几秒 9.5 Hz 生理震颤 + 0.55 Hz 慢晃，按强度衰减；镜头带一点点 | 同上；相机 |
| 恍惚 | 五米内的手榴弹量级才有：发灰、四周发暗、发糊重影，几秒内退；近爆另有 0.35 s 的一下发糊（冲击晃了一下眼） | 后期合成开场那组 `concussion`（取大） |
| 喘 / 心跳 | 强的那一下之后喘粗气 4–14 s、心跳 96–132 次 / 分 6–22 s 慢慢退 | `AudioWiring.BodyFoley`（breathHeavy）/ `AudioWiring.BlastBody`（heartbeat，耳朵被压掉多少就补回一部分音量：那是自己的胸腔） |

## 耳朵受损（`Script_AudioEarTrauma`，`Audio.SetEarModel("trauma")`）

用户嫌原来的耳鸣「不是真实世界的感受」。原来的两套：通用的是一条 4 kHz 正弦 + 总线低通；01–06 的是两条差几赫兹的音互相拍出「嗡嗡」、再一路往下滑 140–260 Hz、底下垫嘶声——都像效果器。真的被炸过的耳朵（暂时性阈移 + 耳鸣）是这样，所以照这几条做：

1. **外界整个小下去、变闷**，不只是一道低通：听阈抬高（每只耳朵一个增益，强度 1 时 −18 dB，炸完那一下再多压 9 dB、0.45 s 内回到平台），高频掉得最多（低通，强度 1 时落到 650 Hz），在耳鸣那个音高附近听力掉出一个坑（peaking −22 dB，4 kHz 一带最容易伤）。恢复时**低频先回、整体响度其次、那个坑最后回**（三样各自按恢复总时长的 22% / 26% / 45% 当时间常数）。
2. **耳鸣是一条稳定的高音**：一局一个音高（3.9–5.2 kHz 里按种子挑），两只耳朵共用同一个振荡器（融成脑袋里的一条音，不互相拍），只带极细的音高起伏（±0.35%）与响度起伏（±7%）；刚炸完音高略高 1.2%、0.35 s 内落定，**不是一路往下滑**。刚炸完是一片宽的「沙——」（窄带噪声 Q 1.6），1.6 s 内收窄成细音（Q 22）。先有一段较快的回落（到一半），再是长尾：强度 1 时鸣二十来秒，弱的几秒。
3. **两只耳朵分开算**：朝爆点那只耳朵挨得重、鸣得久、更闷；另一只被头挡掉一截。所以耳鸣偏在一边，慢慢回到中间再消失。连续近爆按「残余与新的取大，再加较小那份的 30%」累积。
4. 起音期照旧（0.13 s + 传播延迟）：炸的那一声先完整过去，闷与鸣是「之后」的事。耳鸣接在变闷之后（脑子里那声不被自己的耳朵闷掉），走用户音效音量。

总线：trauma 时在 `deafFilter` 与 `outGain` 之间插「固定两声道 → 分声道 → 每只耳朵 低通 / 听力坑 / 增益 → 合声道」（9 个常驻节点，不进 liveNodes 账）；鸣响用时才建、连续近爆复用（14 个节点，进账，预算不够只做变闷不鸣）。legacy 时一个节点都不插，原来的总线与耳鸣一字不动。强度来自 `Combat.BlastFeedback` 算的两只耳朵（随 `AudioWiring.Blast` → `Play({ blastExposure })` 带进 `Reactions`）；没带的（场外近落弹之类）退回 `BlastHearing` 的对称强度；手动 / 剧情的 `Deafen()` 在 trauma 下也走同一副耳朵（两耳对称，剧情档恢复拉长 1.6 倍）。
