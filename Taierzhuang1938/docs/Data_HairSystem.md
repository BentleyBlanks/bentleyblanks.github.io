# 头发与胡子

## 1. 入口与能力边界

`?hair=1` 是独立的头发胡子测试场，菜单「测试场景 → 头发胡子」可进入。与其他测试场共用登记、装配、游戏时钟及后处理；没有另建游戏引擎。31 个台座包含十三张已有光头、人物造型、长短与柔顺程度样本、五种胡子，以及同一造型的三档并排比较。第五排「新增人物」展示冬瓜、幺娃、刘文财、老耿、妮儿、谷寿夫与日军士兵 C，面板默认选中这一组。面板的「短发三档并排」「长发三档并排」会对准比较组。

高档是本项目的 WebGL2 发丝实现：CPU 离线梳导向曲线，GPU 插值成数万根摄像机朝向的细带，使用 R / TT / TRT 三瓣着色近似、黑色素吸收、密度体素透光与随机覆盖率，交给现有 TAA 积分。它借鉴 UE strand 的数据与着色思路，**没有移植完整 UE Groom**。没有实时导向物理、深阴影图、逐发丝多次散射、光线追踪或自动 Groom 导入。柔顺、粗硬与重力影响离线静态造型，头部转动时整体跟随头骨，不模拟甩动。高档画面不能被描述成已达到 MetaHuman / UE 的同等效果。

胡子按本次要求使用发片与透明覆盖率图集；胡茬和头皮染色是贴皮肤的透明层。

## 2. 头部与来源

十三张光头是顺子、罗班长、何有田、日军士兵 A、日兵甲、日兵乙及上述七个新增人物的已有 Tripo 头部，只读来源为 `OneDrive/Sync/饮河/FPS/角色/Tripo`。`_import/Script_HairLabHeads.py` 将独立实验室副本转成米制、Y 向上、脸朝 -Z，量取眉间、鼻、下巴、耳朵、头顶等关键点；来源和缩放记录在 `Hair/Heads/Data_HairHeads.json`。原始模型、参考图与其他角色修模聊天的源目录不变。

实验室胸像是展示用副本；不替换角色游戏身体、帽子、贴图或骨架。

## 3. 离线资产

源表 `Hair/Data_HairStyles.json`：`hair` / `beard` 定义造型，`grooms` 是实验室套装，`gameGrooms` 是绑定到游戏模型的套装。发长、梳向、静态刚度、毛躁、卷曲、发色、密度、胡子部位均从这里读取。

人物展示与游戏挂件通过 `referenceLook` 引用 `Hair/Data_HairReferences.json` 的本人配方。v4 对照原始定妆图、剃净参考与模型正投影，记录两张图的 SHA-256、模型五官校准、分段投影关系、发长及梳向。`landmarks` 覆盖旧自动关键点中偏移的口裂、下巴、耳界和面部中心，`registration` 将原图细须映射到模型。`_import/Script_HairReferenceBake.py` 烘出 `Hair/Data_HairReferenceMasks.json` 的发根采样和发际线，以及共用的 `Texture_HairReferenceMasks.png`，R 为胡须覆盖、G 为额前发根覆盖、B 为分离皮肤色后的发丝灰度。灰须和浓胡须另用 `Texture_HairReferenceBeardLuminance.png` 存胡须区域的原图亮度（人像亮度／中性毛发分离两种采样方式），按本人脸部 UV 读取、校准照片曝光，并随场景光照变化；旧个人套装保留既有颜色路径。发丝和发片都读取局部空间中的原图明暗细节，以浓密毛发区域的中位数归一亮度。发根灰度随场景光照变化，黑色素旋钮保留染色作用；三维发丝保留体积、梳向与覆盖率，胡须发片补充轮廓。二进制同时记录配方、图集与原图哈希，修改校准或配方后重烘相应展示与游戏套装。

二进制 `TXHR` v1：12 字节前缀（magic、版本、JSON 字节数），随后为对齐后的 JSON 头及命名 typed-array 段。头中记录导向、插值、发片、壳、胡茬、头皮、密度体素和量化范围；运行时检查版本和段边界。

## 4. 三档与画质

| 档位 | 几何与着色 | 适用 |
| --- | --- | --- |
| 发丝 | 导向纹理插值、摄像机细带、覆盖率积分、三瓣近似与体素自阴影 | 高画质近景 |
| 发片 | 从同一组导向烘出的条带、共用图集、相同发色与密度体素 | 中景或中档画质 |
| 头发壳 | 短发头皮外壳 / 长发密度等值面、程序化发丝纹理 | 远景或低档画质 |

阈值、过渡时间与 8% 防抖区间以 `Data_Tuning_Hair.HAIR_LOD` 为准。自动档按屏幕包围球像素高度计算，随距离降低发丝数量；游戏画质 low 最高到壳、medium 最高到发片、high / ultra 可用发丝。实验室固定比较组始终保留各自档位，其他组可强制切档。头发与胡子显示开关独立。

## 5. 预通道与生命周期

发丝在顶点着色器中插值并朝相机展开，通用覆盖材质无法重现。几何通过 `mesh.userData.ownPrepass` 提供自己的 MRT 材质：RT0 为视空间法线和正视深，RT1 为无抖动 UV 速度。覆盖率函数、帧号与主画面共用；剪裁孔不写深度。头皮与胡茬透明层不写预通道，深度跟随头部。

头发几何当前不向原生 CSM 投射阴影，只接收场景阴影并做体素自阴影；身体阴影开关保留这一策略，避免把自定义发丝送进普通深度覆盖材质。

`PrepassPass` 在该趟临时换材质并保留原网格和材质的绘制钩子；在**实际绘制**时记录模型、相机在局部空间的位置、像素尺度及模型缩放，帧末推进历史。细带展开使用上一帧的相机与宽度重建上一帧位置。隐藏父节点或被剔除时不虚构历史，重新出现时不带旧物体速度；前景速度归零。造型旋钮变化通知相机切换以清除旧 TAA 历史。

`HairGroom.Dispose()` 只释放实例材质、独立几何外壳并移除节点；共享几何、导向纹理和密度纹理由 `DisposeHairGroomAsset()` 在最后一个消费者退出后释放。`LoadHairAtlas()` 共同持有发片图集和个人参考图集，加载部分失败会回收已完成纹理，释放主图集时一并释放覆盖与胡须亮度图集。实验室退出会回收全部共享资产、头部贴图与 DOM；加载中退出也会释放迟到资源。游戏里的共享 groom / atlas 归 `XBotSkins`，人物先销毁实例，再由 `BlockoutPuppets.Dispose()` 释放共享头发；单个人物消失不能销毁其他人的共用资源。

## 6. 实验室操作

导航遵循 Unity Scene 的常用操作：右键拖动只转向，机位不变；按住右键时 WASD 沿视线前后左右移动，Q/E 沿世界竖直方向升降，Shift 三倍加速，滚轮调节飞行速度。中键（或 Alt + 中键）沿相机屏幕平面平移，Alt + 左键绕选中样本旋转，滚轮或 Alt + 右键拖动拉近拉远。单击胸像选择，双击或 F 聚焦；聚焦保留当前观察方向。鼠标捕获不使用真实指针锁。松开右键、捕获取消、失焦、隐藏或退出均停止飞行；操作面板中的输入和快捷键不移动相机。

面板默认只展开分类、样本选择和观察按钮；外观微调、灯光、高级设置与操作说明各自折叠，切换样本与按钮操作保留折叠状态和滚动位置。发色深浅、凌乱程度、发束聚拢用直观名称和百分比，精细度、卷曲与性能数据收在高级设置，可恢复当前样本的烘焙默认参数。右上角 HUD 用 01–04 对应三档对比、人物参考、发型样本和胡须样本，说明每排用途并可点击定位；场景内同号标记只作提示，不拦截相机操作。窄屏面板改为底部抽屉，留出上方观察画面。

独立测试场通过 `.edThemedSurface` 复用 `Style_Editor.css` 中与主菜单一致的工具主题，包括渐变底、标题字体、旧金选中态、输入框与滑杆。单人观察保留更远机位和相应放大以减少广角变形；全场、并排和自动切档演示保留原镜头。参数只影响当前实例，不存盘；加载错误明确显示。
