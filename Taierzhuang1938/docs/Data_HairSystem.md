# 头发与胡子

## 1. 入口与能力边界

`?hair=1` 是独立的头发胡子测试场，菜单「测试场景 → 头发胡子」可进入。与其他测试场共用登记、装配、游戏时钟及后处理；没有另建游戏引擎。24 个台座包含六张已有光头、人物造型、长短与柔顺程度样本、五种胡子，以及同一造型的三档并排比较。面板的「短发三档并排」「长发三档并排」会对准比较组。

高档是本项目的 WebGL2 发丝实现：CPU 离线梳导向曲线，GPU 插值成数万根摄像机朝向的细带，使用 R / TT / TRT 三瓣着色近似、黑色素吸收、密度体素透光与随机覆盖率，交给现有 TAA 积分。它借鉴 UE strand 的数据与着色思路，**没有移植完整 UE Groom**。没有实时导向物理、深阴影图、逐发丝多次散射、光线追踪或自动 Groom 导入。柔顺、粗硬与重力影响离线静态造型，头部转动时整体跟随头骨，不模拟甩动。高档画面不能被描述成已达到 MetaHuman / UE 的同等效果。

胡子按本次要求使用发片与透明覆盖率图集；胡茬和头皮染色是贴皮肤的透明层。

## 2. 头部与来源

六张光头是顺子、罗班长、何有田、日军士兵 A、日兵甲、日兵乙的已有 Tripo 头部，只读来源为 `OneDrive/Sync/饮河/FPS/角色/Tripo`。`_import/Script_HairLabHeads.py` 将独立实验室副本转成米制、Y 向上、脸朝 -Z，量取眉间、鼻、下巴、耳朵、头顶等关键点；来源和缩放记录在 `Hair/Heads/Data_HairHeads.json`。原始模型、参考图与其他角色修模聊天的源目录不变。

实验室胸像是展示用副本；不替换角色游戏身体、帽子、贴图或骨架。

## 3. 离线资产

源表 `Hair/Data_HairStyles.json`：`hair` / `beard` 定义造型，`grooms` 是实验室套装，`gameGrooms` 是绑定到游戏模型的套装。发长、梳向、静态刚度、毛躁、卷曲、发色、密度、胡子部位均从这里读取。

六个人物展示与游戏挂件通过 `referenceLook` 引用 `Hair/Data_HairReferences.json` 的本人配方，覆盖通用实验造型。每份配方记录 OneDrive 原始头部定妆图的相对路径、SHA-256、观察及独立发际线 / 长度 / 胡须轮廓；原图只读，不复制进运行时。个人胡须区分八字须、唇下须、圆形下巴区域、下颌窄带和脸颊稀疏短茬，避免用矩形或整片下脸代替。二进制和清单同时记录原图身份及配方哈希，改个人配方后必须重烘对应展示与游戏套装。

```powershell
node Taierzhuang1938/_import/Script_HairGroomBuild.mjs HeYoutian_Cast
node Taierzhuang1938/_import/Script_HairGroomBuild.mjs Game_HeYoutian
node Taierzhuang1938/_import/Script_HairGroomBuild.mjs --atlas
```

仅重建本次涉及的套装。构建脚本输出 `Hair/Grooms/Groom_<Id>.bin`、`Hair/Data_HairGrooms.json`，共用发片图集在 `Hair/Textures/Texture_HairCardAtlas.png`。修改资产后更新 `Data_Tuning_Hair.HAIR_ASSET_VERSION`；模块本身由发布系统盖内容戳。

二进制 `TXHR` v1：12 字节前缀（magic、版本、JSON 字节数），随后为对齐后的 JSON 头及命名 typed-array 段。头中记录导向、插值、发片、壳、胡茬、头皮、密度体素和量化范围；运行时检查版本和段边界。

## 4. 三档与画质

| 档位 | 几何与着色 | 适用 |
| --- | --- | --- |
| 发丝 | 导向纹理插值、摄像机细带、覆盖率积分、三瓣近似与体素自阴影 | 高画质近景 |
| 发片 | 从同一组导向烘出的条带、共用图集、相同发色与密度体素 | 中景或中档画质 |
| 头发壳 | 短发头皮外壳 / 长发密度等值面、程序化发丝纹理 | 远景或低档画质 |

阈值、过渡时间与 8% 防抖区间以 `Data_Tuning_Hair.HAIR_LOD` 为准。自动档按屏幕包围球像素高度计算，随距离降低发丝数量；游戏画质 low 最高到壳、medium 最高到发片、high / ultra 可用发丝。实验室固定比较组始终保留各自档位，其他组可强制切档。头发与胡子显示开关独立。

## 5. 预通道与生命周期

发丝在顶点着色器中插值并朝相机展开，通用覆盖材质无法重现。几何通过 `mesh.userData.ownPrepass` 提供自己的 MRT 材质：RT0 为视空间法线和正视深，RT1 为无抖动 UV 速度。覆盖率函数、帧号与主画面共用；剪裁孔不写深度。头皮与胡茬透明层不写预通道，深度跟随头部。

头发几何当前不向原生 CSM 投射阴影，只接收场景阴影并做体素自阴影；身体阴影开关保留这一策略，避免把自定义发丝送进普通深度覆盖材质。

`PrepassPass` 在该趟临时换材质并保留原网格和材质的绘制钩子；在**实际绘制**时记录模型、相机在局部空间的位置、像素尺度及模型缩放，帧末推进历史。细带展开使用上一帧的相机与宽度重建上一帧位置。隐藏父节点或被剔除时不虚构历史，重新出现时不带旧物体速度；前景速度归零。造型旋钮变化通知相机切换以清除旧 TAA 历史。

`HairGroom.Dispose()` 只释放实例材质、独立几何外壳并移除节点；共享几何、导向纹理和密度纹理由 `DisposeHairGroomAsset()` 在最后一个消费者退出后释放。实验室退出会回收全部共享资产、头部贴图与 DOM；加载中退出也会释放迟到资源。游戏里的共享 groom / atlas 归 `XBotSkins`，人物先销毁实例，再由 `BlockoutPuppets.Dispose()` 释放共享头发；单个人物消失不能销毁其他人的共用资源。

## 6. 实验室操作

WASD 沿相机朝向在水平面移动，Shift 三倍加速，斜向速度归一化；拖动旋转、右键平移、滚轮缩放。编辑滑条 / 输入框时不移动相机；点击场景恢复相机操作，窗口失焦、页面隐藏、暂停或退出时释放移动键。点面板条目或台座名牌选样本；正、侧、背、俯视和特写按钮切相机。单人观察采用更远机位和相应放大，减少贴脸广角的鼻部 / 须型变形；全场、并排和自动切档演示沿用原镜头，退出时恢复原相机放大。「走远看切档」沿往返路径展示自动档，手动移动会退出自动演示。面板复用编辑器 `Panel` / `edPanel` / `edBtn` 与全局冷灰、旧金、方角主题，标题固定、内容滚动。太阳方向可调；聚簇、毛躁、卷曲、黑色素、粗糙度与发丝数量只现场改变当前发丝实例，不存盘。资源错误显示在面板内，不能把加载失败当作光头成功。

## 7. 游戏角色消费方

`Data_XBotCharacters` 的可选 `groom` 字段指定人物套装。当前六人均已登记：何有田、日兵甲、罗班长、日军士兵 A、顺子 V5、日兵乙 V2；保留日军三款分配和乙的专用爬行动作。顺子的第三人称实体在 02-4 拖人预演中生成，普通关键帧的单位表没有他。构建器将实验室脸部与只读游戏模型做 trimmed ICP，按皮肤和帽子排除发根，输出 `attach` 矩阵到 `Head` 骨局部；不改模型本身。`XBotSkin` 完成当帧姿势和道具挂接后再选头发档位，预演与白盒试玩 AI 使用同一套消费方。原有角色表和后续新增角色继续保留；未登记 groom 的模型维持原外观。正式战役中尚未采用这些 Tripo 身体的旧人物不会被自动换模。

挂接误差与模型 SHA-256 由资产门禁核对，还必须看正、侧、背与远景，检查帽缘、耳前、后颈、胡须与嘴部；ICP 平均误差不能替代视觉验收。角色模型更新后应重烘其游戏 groom，不能复用旧帽子遮挡。

## 8. 验收

```powershell
node Taierzhuang1938/Script_TestRunner.mjs --only=HairGroomTest,HairReferenceBrowserTest,HairRangeBrowserTest --fail-fast
node Taierzhuang1938/Script_TestRunner.mjs --only=MotionVectorContractTest,CarriagePropVelocityTest --fail-fast
node Taierzhuang1938/Script_TestRunner.mjs --changed=origin/master --profile=prepush --fail-fast
```

通过 TestRunner 使用共用浏览器槽，默认静音、截图 1280×720。`HairGroomTest` 核对二进制段、有限坐标、插值下标、几何索引、密度、人物矩阵与匹配误差。`HairRangeBrowserTest` 检查真实场景、开关与滑条、固定 / 自动切档、三档绘制成本、游戏消费方、实际 RT1 像素、共享实例存活和加载中退出。

`HairReferenceBrowserTest` 验证 WASD 位移、斜向归一化、加速、控件焦点与失焦停移、共用 UI 主题，并将原始个人参考图与实际浏览器渲染并排，另存侧 / 背截图到本地 `tmp/HairLab/ReferenceReview/`。需要本机 OneDrive 原图；`HAIR_REF_SUBJECTS=Luo,HeYoutian` 可限制迭代样本。数字门禁不能替代六人的图像对照复核。

证据只放本地忽略目录 `tmp/HairLab/Verified/`：截图与 `Data_HairVerification.json`。其中逐帧 `StepFrames + gl.finish` 数值是合成帧时成本，不是 rAF 游戏帧率；机器有并行任务时不作独占 GPU 性能承诺。视觉复核、性能实测与部署状态在本次交付记录中分别说明。

2026-11-04 实测：1280×720 输出、high、1024×576 内部渲染，隔离观察何有田一台。每档的 12 个计时帧均确认样本主材质实际绘制 12 次，整条管线共发起 636 次 `renderer.render`。数量是 groom 的启用几何（含胡子、胡茬与头皮层），不含胸像和场地。

| 档位 | 激活三角形 | 合成帧 p50 / p95 |
| --- | ---: | ---: |
| 发丝（46,000 根） | 651,378 | 1.7 / 1.8 ms |
| 发片 | 27,468 | 1.9 / 2.0 ms |
| 头发壳 | 7,378 | 1.5 / 3.2 ms |

三档的绝对时差小于本次负载波动，几何数量的下降已确认；真实游戏帧率需另用 rAF 剖析。完整记录在 `Data_HairPerformance.json`。自动远近演示已实测经过发丝 → 发片 → 壳三档；GPU 检查中发丝 3,316 像素、发片 6,504 像素的主画面 / 预通道覆盖差异均为 0。加载中退出的 30 个头部几何、材质、纹理全部释放；共享实例退出后另一实例可继续绘制，最后释放使 GPU 几何计数由 6 降到 1（剩余为读回用四边形）。
