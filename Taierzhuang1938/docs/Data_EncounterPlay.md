### 本地导入缓存（Library）

用仓库的 `node scripts/Script_LocalPreview.mjs --no-open` 启动预览。编辑器会在当前检出的 `Taierzhuang1938/AdvancedTools/Library/` 中生成两类派生文件。首次导入需要仓库的开发依赖（包括 sharp）；后续只重建输入或导入设置发生变化的产物。Library 已加入 Git 忽略范围，高分辨率 GLB、场景 JSON、高度图和壕沟数据仍在原位置。

| 内容 | 缓存和使用方式 |
| --- | --- |
| 遭遇人物 | `Cast/<内容键>.glb` 与 `Data_Cast.json`。仅在纹理超过 2048 时等比缩小，保留材质槽、骨架、几何、动画、透明通道。现有人物的颜色图使用 WebP，法线及打包数据图使用近无损 WebP。游戏通过清单加载副本；制作工具和第一人称枪、手照常读取自己的资产。 |
| 默认遭遇地形 | `Terrain/<内容键>.bin.gz`。把编辑器原有求解器的数值数组按原类型和精度保存，覆盖高度、地表、节点和预热网格。命中时直接解压使用。浏览器仍可读取已有 IndexedDB 缓存，缺少有效快照时可用 Worker 建场。 |

在工作树根目录运行以下命令可提前导入，或者为普通静态服务器准备快照。可把 `all` 换成 `cast` 或 `terrain`。清空当前工作树的 Library 后，同一命令可完整重建。

```powershell
node Taierzhuang1938/AdvancedTools/Script_EncounterLibrary.mjs all
```

LocalPreview 打开遭遇编辑器时开始监听当前工作树的源文件，保存后自动重新导入，并在读取人物清单时复核。监听随预览服务关闭。地形键由场景、二进制数据、预热焦点和构建模块内容计算。每个产物先写入独立临时文件，再原子替换；旧内容键保留供已打开的页面使用。静态服务器和旧版预览服务使用上一次导入好的快照，可运行同一脚本的 `watch` 命令，在编辑期间自动跟踪源文件变化并重新导入，Ctrl+C 结束监听。压缩是磁盘和加载阶段的处理；显存开销还取决于解码后的尺寸和 GPU 格式。

## 运行边界

- `Script_EncounterPlayPlan`：关键帧开局、触发、数量预算、阶段通过与运行状态；复制输入文档。
- `Script_EncounterPlay`：在游戏宿主已有时钟中下达命令、同步表现与文字、选择 BGM。通过 `Script_SandboxRanges` 登记，主循环不认识具体场景。
- `Script_EncounterPlayView`：同一 WebGLRenderer、两份 PostPipeline 历史与两个显示画布。每帧世界只模拟一次，声音只以玩家相机为听者。观察镜头不另建游戏。两视口人物剔除取并集。
- `Script_EncounterPlayDialogue`：独立于音频的文字行动指令、真实人物头顶气泡与玩家视口底部回退。
- `AdvancedTools/Script_LevelFlowPlay`：编辑快照、播放／暂停／停止、右侧状态、内容指纹与宿主缓存。停止后不运行后台玩法或 GPU 渲染。
- `Script_EncounterPlaySplit`：本地工具运行边界，发布构建替换为 Stub，避免把本地高级工具接回线上游戏包。
