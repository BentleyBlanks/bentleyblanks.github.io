# 数据来源、数据模块只放数据、引用检查

2026-11-02 起的三条数据规矩，各有一个纯 Node 门禁（秒级）。

## 1. 每份数据文件都要登记身份（`Data_DataSources.mjs`，门禁 `DataSourcesTest`）

仓库里的数据文件（`Data_*.mjs`、根目录与内容目录的 JSON：场景、白盒、Timeline、动作、声音、字体、体积、模型清单……）按规则认身份，先匹配先算：

| 身份 | 意思 | 改的时候 |
|---|---|---|
| `source` 源头 | 人或编辑器写的 | 直接改它就是改内容 |
| `generated` 生成的 | 规则里 `by` 写的脚本 / 工具吐出来的 | 改源头再重新生成，别手改（下次生成会冲掉） |
| 退役 | 删掉了，不许再出现 | 删的时候在 `DATA_RETIRED` 记一行：路径、哪天、为什么 |

门禁拦：没被任何规则认出来的数据文件（新加一类数据要先加规则）；生成器 / 编辑入口路径不在仓库里；单独登记成生成的 `.mjs` 开头没写由谁生成；退役的还在；认不到任何文件的死规则。

2026-11-02 登记时 662 份：源头 317、生成的 345。一份都没登记成退役 —— 看起来没人引用的 17 份 JSON（预演动作清单、体积烟雾等）其实是按名字拼路径加载的（如 `Data_${name}Animation.json`），不能按「搜不到文件名」判退役。

白盒场景与正式场景两份并存（用户 2026-11-01 定），都是源头。

## 2. 数据模块只放数据（门禁 `DataJsonTest`）

`Data_*.mjs` 导出的每个值都要能原样写成 JSON 再读回来：普通对象、数组、字符串、有限数字、布尔、null。函数、类、Set / Map / RegExp、three 对象、NaN / Infinity 都不行（对象里值为 `undefined` 的键可以）。这样移植 UE（DataTable）或给表格工具用时能整批转。

- 函数放进同名的 `Script_` 模块（`Data_X.mjs` 的配套函数在 `Script_X.mjs`；重名时 `Script_XData.mjs`）。数据模块自己算数据时要用到的函数留在原处。
- 还不干净的旧模块登记在 `DATA_JSON_DEBT`（只减不增）。2026-11-02 把最近 7 天没人改过的模块里能搬的函数搬了出去；最近还有会话在改的模块先留着，避免和正在进行的工作撞车，等那一块安静了再搬。
- 新数据优先写带版本号的 JSON（`schema` / `format` / `version` 字段之一，照场景文件）。根目录与 `Scenes` / `Blockout` / `Timeline` 下新加的 JSON 门禁会查版本号字段；已有的不带的登记在 `DATA_JSON_UNVERSIONED`。

## 3. 引用只写编号，并且编号要对得上（门禁 `DataRefsTest`）

数据之间互相引用写编号，门禁逐类核对编号真的存在：

- 说话手势按台词编号挂（`FrontObservation.02`），编号要有、说话人要对得上。台词编号是「场 + 第几句」，录音文件名也是同一个编号，所以编号本身不改；中间插一句后面的就挪位，挪位几乎总会换说话人 —— 说话人对不上就红（模拟每处都插一句：59 个手势里 51 个会被拦下；剩下的是同一个人连说两句的地方，靠编号拦不住，插句后要人工核手势表）。
- 台词时间轴、口型挂的台词 / 场编号都要有；每句台词的说话人都在配音选角表里。
- 数据模块里写的文本键（`textKey` / `labelKey` / `titleKey` / `hintKey` / `bootLabel`）都在文本表里。
- 场景文件里的资产编号由 `Script_SceneDoc.ValidateScene` 核对（场景编辑器存盘与场景测试），不在这里重复。

新加一类互相引用（比如预演按标记点编号挂动作）就在 `Script_DataRefsTest.mjs` 加一段。
