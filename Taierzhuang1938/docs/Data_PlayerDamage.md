# 玩家挨打这条链（口径、TTK、受击反馈）

> 起因是一句实话：「AI 会把我打死得太快了，而且基本上直接就死，连红框的晕角提醒好像都没有。」
> 这份文档把那句话拆成三件独立的事，各自记清楚改了什么、为什么、怎么复测。
> 回归口：`node Taierzhuang1938/Script_DamageTest.mjs`（退出码即成败）。

---

## 一、修之前是什么样（实测账，不是估算）

伤害口径原来散在**三个文件的四处魔法数**里，没有任何一处知道合起来是多少：

| 位置 | 数字 | 管什么 |
| --- | --- | --- |
| `Script_Ai.TryFire` | `× 0.55` | 枪伤 → 玩家 |
| `Script_Ai.TryBayonet` | `× 0.5` | 刺刀 → 玩家 |
| `Script_Combat.Blast` | `× 0.7` | 爆炸 → 玩家 |
| `Script_Player.TakeHit` | 头 `× 3.4` / 躯干 `× 1.0` / 四肢 `× 0.62` | 部位倍率 |

乘出来是这样：

- 三八式命中躯干 `72 × 0.55 = 39.6` → 三发一条命；
- **爆头 `72 × 0.55 × 3.4 = 134.6`，满血一枪毙**，而爆头掷骰占 8%
  —— 也就是说任何一次交火，第一发就可能是结局，玩家来不及知道自己在挨打；
- 三个射手（`COMBAT.maxShootersOnPlayer = 3`）在 25 m 上，
  靶场实测从满血打到死 **≈ 5—6 s**（`Script_DamageTest.mjs` 第 2 节会把旧口径重跑一遍做对照）；
- 伤口流血是叠加且几乎不自愈的（衰减 5%/s），四个躯干伤口 = 10.4 HP/s，
  两卷绷带追不上 —— 那不是「慢性死亡」，那是一块十秒的秒表。

而这 5—6 秒里屏幕上**几乎没有事发生**：

- 暗角不透明度写死成 `Clamp01(1 - health/70) × 0.62`。满血挨一发三八式之后
  剩 60.4，算出来是 `0.085`，再乘暗角边缘那层 `0.52` alpha ≈ **0.044**。
  数学上不是零，视觉上就是没有；而 70 到 0 只隔两发。
- 没有任何**事件级**反馈：暗角只是血量的函数，没有「刚刚挨了一下」这件事。
- 没有来弹方位：玩家不知道该往哪边躲。
- **没有声音**。`Audio/Sfx/AudioSfx_Hurt_01.mp3` 与 `AudioSfx_Heartbeat_01.mp3`
  早就烘好了、`Script_Audio` 里 `hurt` / `heartbeat` 两条配方也在，
  但全仓库一行没播过。
- 难度档里的 `aiAccuracy` / `playerDamage` / `suppressionScale` 三个字段
  立在 `DIFFICULTY_PRESETS` 里，**一处都没被读过** —— 换「体验/标准/写实」
  只改得动弹道重力、自由瞄准、铁瞄偏心和过热四件事，挨打的强度纹丝不动。

## 二、口径全部回到数据层：`COMBAT.player`

`Data_Battle.mjs` 里新增一个块，上面四处魔法数与部位倍率一律从它读。
**要调挨打的强度只改这里，别再往逻辑里写第五个魔法数。**

| 字段 | 值 | 说明 |
| --- | --- | --- |
| `accuracyScale` | 0.70 | 命中率单独给玩家一档（见下） |
| `bulletScale` | 0.33 | 枪伤 → 玩家。三八式 72 → 23.8 躯干，四发多一条命 |
| `meleeScale` | 0.42 | 刺刀 110 → 46.2：重，但不是读盘 |
| `blastScale` | 0.55 | 爆炸 → 玩家 |
| `headChance` | 0.035 | AI 打玩家的爆头概率（AI 打 AI 仍是 0.08） |
| `headMultiplier` | 2.0 | 爆头倍率（对 AI 仍是 3.4） |
| `limbMultiplier` | 0.50 | 四肢 |
| `maxBulletDamage` | 62 | **单发对玩家的硬上限：满血挨一枪必活**（安全网，见下） |
| `bleedScale` | 0.50 | 伤口出血速率 → 玩家 |
| `maxBleedPerS` | 5.5 | 流血封顶：伤口叠加不许变成必死的秒表 |
| `firstShotGraceS` | 1.1 | 刚锁上玩家的这段时间内开的枪一律打偏 |

### 为什么命中率另开一档，而不去动 `aiAccuracyBase`

`aiAccuracyBase` 同时决定**日军和中国兵互相怎么打** —— 全场七十个人的消耗速度、
阵地什么时候被啃穿、票池掉多快，全挂在它上面。为了让玩家好受一点去调它，
等于把整场仗的强度一起改了。

玩家这一侧另有理由：他是一个人对一条战线，而且没有「被打中就趴下」的 AI 行为兜底
——同样的命中率落在他身上就是纯粹的秒表。所以 `accuracyScale` 只在
`s.target.isPlayer` 那一支上乘进去，AI 互相打的那一支一个数没动。

### 单发上限：只管小口径，而且是安全网

`maxBulletDamage` 只在 `info.bullet` 时生效。炮弹、集束、掷弹筒照样能一下要命 ——
那是它们应得的，而且它们有啸声、有落点标记、有 1.6—2.6 s 的预警：
玩家是「没躲开」，不是「没看见」。

对小口径来说它平时也不会被触发：现在最重的一发是九二式重机爆头
`92 × 0.33 × 2.0 = 60.7`，刚好在 62 下面。留着它是为了将来谁往 `Data_Weapons`
里加一支更重的枪时，「满血挨一枪必活」这条不会被悄悄推翻。

### 首发必偏（`firstShotGraceS`）

`Soldier.playerLockAt` 只在**从别处切到玩家**那一刻打戳（不是每次 `Think` 都续，
否则窗口无限延长 = 永远打不中）。`TryFire` 在窗口内把 `acc` 直接压成 0。

这一发**照样有枪口焰、有枪声、有近失弹压制**，它买的就是那一下：
子弹先从耳边过、暗角先亮一下，玩家才有得反应。老兵从冷瞄具到第一发本来也不准。

配合出生保护（`spawnGraceS = 3.2`，期间没人会锁玩家），重生之后实际有
**3.2 + 1.1 ≈ 4.3 s** 的找掩体时间。

## 三、受击反馈：把「我中弹了」变成一件看得见听得见的事

三条独立通道，都挂在 `PlayerController` 上，由装配层每帧读走：

| 量 | 谁读 | 表现 |
| --- | --- | --- |
| `player.hitFlash` | `Hud.SetHurt` | 一次中弹的红闪。强度按**这一发的实际伤害**定，与剩余血量无关；自己按 1.7/s 衰减 |
| `player.hitMarks[]` | `Hud.SetHurt` | 来弹方位（存**世界方向**，HUD 每帧按当前 yaw 转成屏幕角，所以转身之后指示器跟着转）。寿命 2.2 s，最多 5 条 |
| `player.hitEvents[]` | `Script_Main.PlayHurtCues` | 一次性事件队列：`hurt`（闷哼）与 `heartbeat`（濒死心跳）。取完即清 |

暗角现在是**三层叠在同一张图上**（前两层取 `max` 而不是相加 ——
相加会让「低血 + 连中」糊成纯红看不见路）：

1. 底噪 —— 剩余血量。从 **90** 开始渗（不是 70），曲线 `(1 - hp/90)^1.6 × 0.78`：
   让「我该包扎了」提前到还有得救的时候；
2. 事件 —— `hitFlash × 0.85`；
3. 濒死 —— 血量 < 40 时 `.hudDamage.low` 上 CSS 搏动动画（`hudPulse`，零 JS 成本）。

CSS 侧两处要点（`Style_Game.css`）：

- 过渡从 `0.25s` 压到 `0.09s` —— 红闪要跟得上枪响；
- 渐变停靠点从 `26% / 66% / 100%` 收到 `17% / 56% / 100%`。
  16:9 上「100%」是**最远那个角**（离中心 734 px），而屏幕上边缘只到 49%；
  停在 26/66 的话红几乎全堆在四个角上，视野正上下那两条带子基本没颜色 ——
  看起来就还是「没有红框」。

来弹指示是 `.hudHitDirs` 这个 SVG（`viewBox -100..100`，五个共用一份几何，
只改 `transform="rotate(deg)"`）。屏幕角 = `atan2(右分量, 前分量)`，
0° 正前、+90° 正右。

音频两条都**不给 position**：闷哼是自己嘴里发出来的，心跳在颅内，
都不该有房间混响与 HRTF 方位（`Script_Audio` 的 `heartbeat` 配方把 `wetGain`
写死成 0 就是这个意思）。一帧只哼一声 —— 一次爆炸的弹片能同帧结算好几下。

## 五、复测（`Script_DamageTest.mjs`）

靶场不去等真实战场自己打起来：那件事取决于撒兵点、院墙和通视，重跑一次就是
另一个数，方差比要测的效果还大。测试把三个日本兵搬到玩家 25 m 上、目标焊死成玩家，
然后**走真的 `ai.TryFire`** —— 命中率、部位掷骰、伤害缩放、`TakeHit`、流血、红闪，
一条都不绕过去。唯一被替换掉的是「多久开一枪」（按武器表算的周期直接推时间），
因为那一段是计时器，不是规则。

靶场开在 **phase=1（`CH1_NanLu` 第一关 · 往南的路）**，且射手**只收持步枪的日军**（三支三八式）：

- phase=0 在任务流程重制后是不撒兵的过场序章，靶场一个射手都收不到。
  测试先「点名」（场上至少三个活着的持步枪日军）再开靶 —— 哪天又有章被改空，
  报出来的是判据不成立，不是 `Range.Run` 里一个看不懂的 TypeError。
- 「前 N 个活兵」拿到什么枪由撒兵顺序决定：混进一挺十一年式（周期 0.82 s 对
  三八式的 2.2 s）TTK 直接塌半，阈值就得跟着章走。焊死成三八式之后换章不动数。

两个采样纪律，踩过才写下来的：

- **时间轴按每一发推进**，不是按「一轮三发」推进。按轮推的话分辨率就是一整个
  射击周期（1.74 s），旧口径两轮死、新口径两轮死，读出来是同一个数，
  效果整个被量化掉（第一版就是这么读到「旧 5.2 s → 新 5.2 s」的）。
- **一组参数至少跑 15 次取中位数**。9 次时同一份代码两趟能读出 9.3 s 与 12.8 s，
  那个跨度比要测的效果本身还大，断言会随机变红。
- **「一枪毙」不能拿靶场里的单发最重去断言**。`worst` 是单发掉血的最大值，
  而只有一局的**第一发**打在满血上，后面的掉血天然被剩余血量截住 ——
  15 局 × 8% 爆头 ≈ 1.2 次，同样会随机变红（实跑遇到过一次）。
  改成拿旧倍率直接打一发爆头，确定性的。

二十四条断言覆盖：点名（本章真撒了兵、且步枪兵够三个）、单发不致死、TTK 新旧对照、
首发必偏（40 发 0 伤害且照样压制）、红闪/暗角/来弹弧角度、闷哼与心跳真的被播、
姿态仍然分得出来、爆炸与白刃仍然重、手榴弹警告的亮/指向/脉冲/消失。

### 落地的数

**基线是在 `CH1_NanLu`（第一关 · 往南的路）上、拿三支三八式量的**，2026-08-29 起。
在这之前靶场挂在旧 `L0_Jiehe` 上；任务流程重制之后 `?phase=0` 是**零敌人的过场章**
（`CH0_Chuchuan`，`cutsceneOnly`、`ijaPool: 0`），在那儿挑不到日本兵，
射击周期算出来是 NaN、整份 TTK 报告变成一串 −1 **而且不报错**。
换章的逐项对照写在 `Script_DamageTest.mjs` 头注里；结论是被测对象没变 ——
CH1 与旧 L0 的 `ijaPressure` / `ijaSpawn` / `ijaSupport` / `ijaForce` 逐字相同。
**`COMBAT.player` 那十一个字段、`aiAccuracyBase`、`Data_Weapons` 的伤害一个数都没动。**

数字每次执行一模一样（按局播种的固定骰序 + 射手焊死成步枪兵）：

| | 旧口径 | 新口径（同一台靶场） |
| --- | --- | --- |
| 三人 25 m 站姿 TTK（15 次中位数） | 6.6 s | **16.1 s**（2.44×） |
| 单发最重 | 100（打死） | ≤ 47.5，在 `maxBulletDamage` 62 之下 |
| 靶场命中率 | ≈ 30% | ≈ 19% |
| 满血挨一发之后的暗角不透明度 | 0（血还在 70 以上） | ≈ 0.53（红闪）→ 0.07（底噪） |

姿态仍然是最大的一根杠杆：**立 16.9 s / 蹲 17.6 s / 卧 29.3 s**（11 次中位数）。
断言阈值：站姿 TTK 落在 8—24 s、新旧比 > 1.5、卧 > 立。

> **为什么比早年混编射手量的 9—13 s 整体长了三成**：那时候靶场收的是「前三个
> 活着的日本兵」，谁排在前面取决于撒兵，于是常混进一挺十一年式（周期 0.82 s
> 对三八式的 2.2 s），TTK 直接塌半。焊死成纯三八式之后一轮 2.2 s，射速与单发
> 伤害都低于混编 —— 这是口径换纯步枪的代价，不是回归，而且**换章不再动数**。
> 断言压的仍然是「卧 > 立」这条**关系**与那条 8—24 s 的宽带，不压绝对值。

> 注意靶场是**最坏情况**：无限弹药、不换弹、不被压制、通视永不中断、
> 三个人从头打到尾。真实关卡里的 TTK 只会比这个长。
