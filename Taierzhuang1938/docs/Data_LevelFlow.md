视口布局右侧的秒表与逐帧图标分别打开 Profiler 与 Frame Debugger。Profiler 记录预览帧的剧情求值、界面更新、各视口的地形、物件、叠层、WebGL2 提交、人物可见性和 GPU 文字与标记。拖动相机或播放时间轴可录制。点击卡点定位到帧和插桩，点击「导出 JSON」下载逐帧数据。每帧 `preview` 记录时间轴位置、剧情拍和实际绘制的视口，包含视角、后端和画布尺寸。

Profiler 导出的 `preview` 保留每个实际重绘视口的眼点、朝向、投影参数和导航状态。`cpuMs` 是本次 Render 工作区间；`beforeRender` 单列本次 rAF 里先执行的调试窗口更新与导航。连续 rAF 的 `interval` 用于帧率统计，跳过重绘的间隔会置零；`redrawIntervalMs` 则保留相邻重绘的实时间隔（含按需等待）。GPU 数值只汇总 WebGL 定时查询，Canvas 合成单列 CPU 插桩。不可用、未完成、失效或只覆盖部分段的查询用空值和 `gpuTiming` 状态表示。

三维视口的 `preview.viewports[].terrainWork` 记录当帧实际工作量。`visitedNodes` 是外层四叉树访问数，`patchNodes` 是细分块内部访问数，`reusedSubtrees` 是直接复用的子树数。`cellIndexBuilds` 统计新生成索引的小格；`patchBuilds`、`patchCellLookups` 和 `patchIndicesWritten` 分别统计发生重建的块、重新查询的小格和为拼块实际写入的索引项。上传和物件开销另看 WebGL2 计时。

本地核对可运行 `node Taierzhuang1938/Script_LevelFlowProfilerAudit.mjs --sample`。它在浏览器内操作右键转镜头、中键平移、W 键与滚轮，从 Profiler 窗口导出 JSON；另以原生 WebGL 调用、计时器返回值与 CPU 样本区间核对每帧和每段，生成 `tmp/EncounterProfilerAudit/After/` 下的录制与核对结果。

编辑器里的 Frame Debugger 点「捕获当前帧」会重绘一次所有可见视口。事件先按「视口 1、2、3、4」分组，再按实际执行次序列出。3D 视口记录 WebGL2 绘制、清除与拷贝，2D 与软件光栅按 Canvas 层记录。点视口组可看该视口完成时的快照；编辑器只保存可见输出，不回放中间 GPU 缓冲，也不会冻结时间轴。进入 Play 后同样的按钮改为调试游戏实例，双视口按玩家／观察视角分组；停止 Play 会关闭游戏调试窗口并恢复编辑器入口。再次点击已打开的工具会聚焦原窗口。

## 通路与多视口

2D 底图读取当前地图范围内的全部场景物件，物件的章节分组用于组织数据。地标直接读取场景 `markers`，保留名称、位置、类型、范围和备注；原有补充标签在同名地标存在时采用场景中的名称与位置。标签沿用视口的场景名称开关、缩放筛选与避让。

立体地表保留场景高度图的坡形、土包、弹坑、田埂和沟岸。地形细分逐格检查原始高度数据，偏离粗网格中心的小起伏也要进入绘制网格。田条读取原空间表并按原朝向铺设，场景及远景的地表涂色、道路和田间小路贴在同一高度表面上。树木采用树干与方块树冠示意，保留原位置、朝向和总高，远景物件读取原有尺寸参数。

空间图统一绘制整个沟岸网络，再统一铺设整个沟底网络，保证支沟口等 T 字交汇处的地面连续。防炮洞、机枪坑、村庄丁字路口等具有独立面积的地点按原始区域画地面。六条折线巷道和村口坡道均接入同一通路网，真实死巷按原始 caps 标记封口。

18 个关键连接点在测试中逐一检查。浏览器测试还在支沟口原误绘位置检查沟底像素，防止后画的沟岸重新封住连接口。

顶部可选单视口、双视口、四视口。每个视口的视角菜单按 2D 和 3D 分组，2D 提供战斗局部，3D 提供 Scene 自由视角、跟拍和玩家视线，使用同一帧人物和遭遇状态。旧金色边框表示活动视口，顶部取景按钮与鼠标操作作用于该视口。各视口可独立缩放、平移、复位和选择顺子／冬瓜／班长／头车作为跟随对象。立体视口的旋转按钮每次转 45°。旧定位及取景按钮沿用的空间总览、立体俯视投影继续兼容，菜单分别选中战斗局部、Scene 自由视角。

视口底部的拍号、时间、玩家坐标与镜头状态读数已删除；左下角图例及比例尺、指北针等地图 HUD 默认隐藏，可在每个视口的“显示 → 地图 HUD”单独开启，随视口定位保存，旧定位缺少该字段时默认隐藏。各视口“显示”菜单中的“人名”控制角色文字，“场景名称”控制空间图的掩体、阵地、道路、建筑、地名及死巷文字。名称开关独立于掩体实体和图标，并随 PNG 帧包与工程里的多视口定位保存和恢复。旧定位数据缺少“场景名称”字段时默认显示。

滚轮支持从全局逐级放大到单位细节，二维及立体俯视的缩放上限为每米 320 像素，跟随、视口恢复和帧包回读沿用同一上限。三维视口右上角的红 X、绿 Y、蓝 Z 方向轴跟随镜头朝向更新，拖动方向轴可环绕旋转，点击轴端可对齐该轴方向。二维视口隐藏方向轴。

默认打开一个手动控制的 Scene 自由视口，俯看全局；顶部布局菜单可切换为双／三／四视口，第二视口默认近地观察。切换时间或播放时保持手动机位，Scene 的“镜头 → 重置镜头”回到当前人物附近的默认机位。其他视角通过下拉菜单手动选择。天空显示蓝色天顶、灰蓝地平线与柔和日光。3D 屋顶顶面及檐口侧面在画面与阴影几何中统一向外延伸 5 毫米，避免与墙柱、门楣共面时产生深度闪烁。Scene 开启自动跟随时保留透视投影、当前机位、朝向与焦点距离，之后相机随目标的三维位移平移；停止跟随则停在当前机位。

相机转向、平移、飞行与缩放期间，地形渲染分辨率和网格细节始终保持与静止时相同精度。文字与编辑标记按原生分辨率绘制。暂停导航时复用未变化视口的画布；播放也保留完整精度。参数位于 `Data_Tuning_LevelFlow.mjs`。

立体视口优先使用 WebGL2 进行地形投影、裁剪、三角形填充与颜色插值，四个视口共享一个离屏 GPU 上下文，最多缓存四组不同尺寸的渲染目标。颜色直接合成到画布，每个视口保留自己的浮点深度纹理，随后的 GPU 叠层从这张纹理判断遮挡。高度采样使用有界精确坐标缓存，地形包围球预计算；软件路径共享地形顶点投影。WebGL2／浮点目标不可用或绘制失败时回退软件光栅，失败的当前帧也完整重绘；软件模式保留静态颜色／深度缓存。`LevelFlow.Inspect().rendering[].backend` 报告 `webgl2` 或 `software`。

双视口复用每个地形单元的不可变顶点／颜色打包数据，保持原网格与接缝。相机固定时，只有保守包围球与该视口相交的战车、驴车及搬运弹药箱才参与背景缓存键；画外车辆移动不触发地形与深度重绘，进入、离开画面及画内移动仍即时更新同一帧颜色与深度。画布只在尺寸改变时重建，时间文字和视口状态只在内容变化时更新，GPU 路径也不再逐帧清空即将被完整覆盖的 CPU 缓冲。门禁包含画外运动不重绘、画内物体不冻结／拖影，以及地形打包逐值一致性。

会话标题下方是三个下拉：本机客户端（Codex / Devin / Antigravity）、模型、思考深度（2026-11-23）。三者都是本机 CLI 调用，由 `scripts/Script_EncounterAgentProviders.mjs` 适配：Codex 沿用 app-server（`turn/start` 的 `model` / `effort`，支持执行中补充要求）；Devin 走 `devin -p --prompt-file … --model <模型>-<深度> --permission-mode dangerous --export`，续聊用 `-r <会话>`，会话编号取自导出的 ATIF `session_id`；Antigravity 走 `agy --input-format stream-json --output-format stream-json --model <模型>-<深度> --dangerously-skip-permissions`，续聊用 `--conversation`。Devin / Antigravity 的模型编号把深度写在后缀里（如 `claude-opus-5-5-high`），列表按后缀拆成模型 + 深度两个下拉；两者一轮一个进程，执行中不能补充要求（发送按钮显示“执行中”，接口回 409），截图以文件路径写进提示词。权限与 Codex 本机配置（`approval_policy = never`、`danger-full-access`）对齐。模型目录接口 `GET /__encounter/codex/providers`（`?refresh=1` 重新探测）分别调用 Codex `model/list`、`devin models`、`agy models`，结果缓存 10 分钟；未安装或未登录的客户端在下拉里标“未就绪”、标题下显示原因并禁用发送，探测失败时给出内置备选模型。Devin CLI 在 ACP 模式不读本机凭据，故用打印模式，需先在终端 `devin auth login`。每条会话记录 `provider`，旧会话视为 Codex；一条会话绑定一个客户端，换客户端须新建会话，模型与深度可逐轮更换，下一轮生效。新会话的最后一次选择保存在浏览器源 `tengxian1938_encounter_agent_v1`。

执行中的公开回复显示在 Codex 气泡里，包含当前执行状态、回复文字与更新时间。会话列表的“删除”将条目移入“已删除”，其中可以查看历史并点击“还原”恢复续聊。删除状态独立保存在会话目录的 `Deleted.json`，会话正文、附件与本机 Codex 转录完整保留，正在执行的任务继续运行。接口为 `DELETE /__encounter/codex/sessions/<id>` 与 `POST /__encounter/codex/sessions/<id>/restore`，均执行本机同源校验，支持重复请求。列表接口分别返回 `sessions` 与 `deletedSessions`。已删除会话须还原后才能发送新需求。

会话列表采用独立圆角卡片，整张卡片包含状态徽标、两行标题、当前活动、更新时间与删除／还原按钮，选中卡片以旧金色描边强调。状态用文字和颜色同时区分“准备中”“进行中”“暂停中”“已暂停”“已完成”“需要处理”。启动和提交需求时由 `progress.phase: preparing` 标记，收到 `turn/started` 后切为 `running`；旧记录兼容已知启动活动，其他运行中的记录显示“进行中”。未知状态显示“状态未知”。列表每两秒更新。

鼠标悬停在人物或车辆上时，该视口通过单位四角高亮、姓名牌描边和手形光标提示可点选。三维视口沿鼠标射线选取最近的角色身体胶囊，平面视口点选单位图标。姓名牌只负责显示。点击人物或车辆会暂停播放，并在右栏显示单位信息和选择方式。单选模式替换当前选择，Ctrl／Shift／Command + 点击可增减单位，多选模式可连续点击增减。所有已选单位在各视口高亮，可逐个取消或清空，再点击“附加 N 个单位”。输入区“＋ 单位”可重新展开选择面板。单位附件独立保存为 `Units.json`，包含附加时的场景、拍号、秒数、单位稳定编号、名称、阵营、世界三维坐标、姿态、人物状态与所属生成组配置。移动时间轴和修改当前选择后，已附加内容保持原样；切换会话随草稿恢复，发送后可在历史气泡展开查看或打开 JSON。本地 CLI 首次执行、续聊与执行中补充要求均会收到单位附件路径。

执行中的会话在标题栏显示“暂停”。点击后通过当前连接中断本轮执行，旧版连接结束对应 CLI 进程树，界面状态依次显示“暂停中”和“已暂停”。对话、截图、定位附件与输入草稿保留，可继续发送需求。接口为 `POST /__encounter/codex/sessions/<id>/interrupt`，沿用本机同源校验。运行记录保存 CLI PID，旧版运行中的会话按会话编号定位对应 CLI 包装进程。中断记录独立保存到会话目录的 `Interrupt.json`，供结束回调及其他预览服务恢复状态。

旧版 CLI 进程在任务完成后可能继续驻留。会话读取会核对对应转录末尾的公开进度与 `task_complete`，恢复最终答复并保存“已完成”，后续续聊按最新用户消息时间核对完成记录。旧会话缺少进度时显示“正在执行”；每次轮询继续读取更新，推理内容不进入会话面板。

“＋ 截图”是截图标注的统一入口，截取当前所有视口并暂停时间轴。支持箭头、矩形、文字、自由画笔、移动、撤销／重做、复制图片与导出 PNG。标注窗口的操作按钮采用图标，悬停提示和无障碍标签保留功能名称。仅在选择文字工具或文字标记时显示颜色和白色描边开关，新增文字默认开启白色描边；拖拽文字框右下角会按比例缩放框和字号。底部操作说明、标记数量和画布尺寸已移除，复制、导出或错误反馈短暂显示。画笔路径随 PNG 元数据和会话截图保存，重新打开后仍可移动、删除及撤销。“添加附件”把当前标注图放入输入区，发送前可继续标注或移除。PNG 的 iTXt 键 `EncounterFrame` 保存完整帧数据、原图与标记，可用 `ReadPngFrameMetadata` 或 Pillow 的 `Image.open(path).info['EncounterFrame']` 回读。截图拍摄时的帧另存 `ScreenshotFrame.json`，截图与定位各自保留附加时的状态。

本地接口由 `scripts/Script_LocalPreview.mjs` 提供，只接受本机同源请求。控制中心启动器按仓库目录和服务端代码指纹复用预览进程，旧进程继续占用端口时会为当前代码另选端口。使用 `node scripts/Script_LocalPreview.mjs --no-open` 启动，再进入本工具。会话与附件保存在当前检出的忽略目录 `tmp/EncounterCodex/`。运行记录保存归属服务 PID，其他预览实例读取时保留存活服务的执行状态，归属服务退出后标记中断。历史执行记录缺少 PID 时保留其状态。CLI 公开进度进入实时回复气泡，思考内容与原始工具事件由桥接层丢弃。服务执行失败时显示固定的错误分类并保留已提交的需求与附件。CLI 原始错误输出和事件中的服务商错误文本直接丢弃，旧记录的原始错误字段读取时会归一化。会话私有目录经静态文件入口访问时返回 403，附件通过本机同源接口读取。桥接层调用本机已安装的 CLI 并继承其现有配置与认证；需求和附件会随 CLI 的模型请求发送到所配置的服务商。

- `Script_LevelFlowTerrain.mjs` 复用实际地形与壕沟采样，构建共享边界的地面网格。弯曲沟岸按高度误差细分至 0.25 米；顶点按世界坐标共享土色与平滑法线，沟沿的平坦区域也保留颜色过渡所需细分。GPU 的投影明暗与环境遮蔽读取同一组平滑法线，地表使用较柔和的遮蔽强度与法线偏移，减少三角扇产生的重复深色棱边。几何遮挡和地面标注使用原始几何深度。2026-11-17 修复墙沿 AO 的“层纹”（同一道墙边出现两三条平行重影）：原先每像素固定 8 方向 × 2 档半径，边缘正好卡在这几圈上。现在 AO 分两趟：第一趟按 4×4 拜耳图案给每个像素不同的射线旋转与步长偏移（8 方向 × 4 步），写入独立的光照系数贴图；第二趟按深度权重对一个 4×4 周期求平均再乘到颜色上，墙边不会把暗色抹到另一个表面。系数贴图随四个视口的离屏目标一起创建与回收，结果逐帧确定、不抖动。同日修复投影边缘的锯齿：阴影贴图由 2048 升到 4096（受 `MAX_TEXTURE_SIZE` 限制），阴影采样改用硬件双线性深度比较（`sampler2DShadow` + `COMPARE_REF_TO_TEXTURE`，3×3 个采样点各自再双线性混合），不再是九次硬阶跃；阴影半径按 1.2 倍分档、中心对齐到整纹素，镜头移动时阴影边不再爬行。
- 三维视口的人物线条、掩体、地标、姓名、对白和墙面文字在 WebGL2 中采样本视口的深度。字形与气泡底图按需栅格化并缓存到纹理图集。GPU 汇总每个人物的可见和被挡片段，控制姓名与对白的透明度；回放、转镜头与角色点选均无需同步读取深度。显式检查遮挡统计、在场景表面放置标注时可以按需读取深度。纯软件视口沿用 CPU 遮挡。
- 有地表贴图的 WebGL 视口按原来的裁剪、误差和接缝规则选块。每个源网格顶点在地形顶点池中保留一份，视口用索引拼出本帧的三角形。地形导入缓存保存可还原的顶点高度、共享法线编号和近区单元拓扑；未预热区域随访问追加。软件回退与 Frame Debugger 可从同一组索引展开几何。
