# 第一关 Encounter Designer

入口为高级工具 → 关卡 → Encounter Designer，独立页面 `Tool_LevelFlow.html`。工作区支持单、双、四视口，底部为共用时间轴，右侧包含会话与原文页签。会话页采用左列会话列表、右列气泡对话与输入框的两列布局。场景 `cover` 标记、`Whitebox/Cover` 材质与工具布设掩体在各视口使用绿色表面、深色轮廓、浅色条纹与盾牌符号，立体标记遵循地形和物件遮挡。“截图与标注”统一在独立弹窗中完成截图、箭头／框／文字标记、复制、导出与附加到会话。

## 通路与多视口

空间图统一绘制整个沟岸网络，再统一铺设整个沟底网络，保证支沟口等 T 字交汇处的地面连续。防炮洞、机枪坑、村庄丁字路口等具有独立面积的地点按原始区域画地面。六条折线巷道和村口坡道均接入同一通路网，真实死巷按原始 caps 标记封口。

18 个关键连接点在测试中逐一检查。浏览器测试还在支沟口原误绘位置检查沟底像素，防止后画的沟岸重新封住连接口。

顶部可选单视口、双视口、四视口。每个视口可独立选择空间总览、战斗局部、立体俯视、跟拍或玩家视线，使用同一帧人物和遭遇状态。旧金色边框表示活动视口，顶部取景按钮与鼠标操作作用于该视口。各视口可独立缩放、平移、复位和选择顺子／冬瓜／班长／头车作为跟随对象。立体视口的旋转按钮每次转 45°，也可选 Scene 自由视角。

各视口“显示”菜单中的“人名”控制角色文字，“场景名称”控制空间图的掩体、阵地、道路、建筑、地名及死巷文字。名称开关独立于掩体实体和图标，并随 PNG 帧包与工程里的多视口定位保存和恢复。旧定位数据缺少“场景名称”字段时默认显示。

默认打开两个手动控制的 Scene 自由视口，左侧俯看全局，右侧近地观察。切换时间或播放时保持手动机位，Scene 的“复位”回到当前人物附近的默认机位。其他视角通过下拉菜单手动选择。天空显示蓝色天顶、灰蓝地平线与柔和日光。

相机转向、平移、飞行与缩放期间，地形渲染分辨率和网格细节始终保持与静止时相同精度。文字与编辑标记按原生分辨率绘制。暂停导航时复用未变化视口的画布；播放也保留完整精度。参数位于 `Data_Tuning_LevelFlow.mjs`。

立体视口优先使用 WebGL2 进行地形投影、裁剪、三角形填充与颜色插值，四个视口共享一个离屏 GPU 上下文，最多缓存四组不同尺寸的渲染目标。颜色直接合成到画布，只回读浮点深度用于人物遮挡与鼠标拾取。高度采样使用有界精确坐标缓存，地形包围球预计算；软件路径共享地形顶点投影。WebGL2／浮点目标不可用或绘制失败时回退软件光栅，失败的当前帧也完整重绘；软件模式保留静态颜色／深度缓存。`LevelFlow.Inspect().rendering[].backend` 报告 `webgl2` 或 `software`。

双视口复用每个地形单元的不可变顶点／颜色打包数据，保持原网格与接缝。相机固定时，只有保守包围球与该视口相交的战车、驴车及搬运弹药箱才参与背景缓存键；画外车辆移动不再触发地形重绘和深度回读，进入、离开画面及画内移动仍即时更新同一帧颜色与深度。画布只在尺寸改变时重建，时间文字和视口状态只在内容变化时更新，GPU 路径也不再逐帧清空即将被完整覆盖的 CPU 缓冲。门禁包含画外运动不重绘、画内物体不冻结／拖影，以及地形打包逐值一致性。

立体视口读取场景的原始高度图与沟底基准，调用游戏共用的 `CompileSceneTrenches` 采样实际地面。自适应网格在沟口、弯道与坡道共享边界顶点，远处延伸到场景背景地面。此前遭遇布设新增的凹口按邻近沟底高度开挖，13 条坡道在实际地形端点之间连续插值，统一进入这张地面网格。透视相机远裁剪为 1500 米。地面、建筑与车辆写入同一深度缓冲。玩家视线将遮挡部分及全遮挡标签完全隐藏。其他立体视口用 20% 透明度显示遮挡部分，全遮挡标签透明度为 22%。立体视口的指北方向随视角旋转。

右键拖动转头，按住右键配合 WASD 飞行，Q/E 升降，Shift 加速。中键拖动平移，Alt + 左键环绕，Alt + 右键或滚轮前后移动，F 聚焦所选对象，未选对象时聚焦顺子。左键点选人物或区域，拖动移动镜头。手动离开玩家视线或跟拍时，视口切换为 Scene 自由视角。暂停仍可导航，松开右键、取消操作或窗口失焦会清理移动输入。PNG 与工程 JSON 保存自由相机位置、朝向、远裁剪和焦点距离，旧帧包继续可读。

老耿的车按 `L0610_LANE`、`L0610_SOUTH_LANE` 的折线弧长采样位置并随路线转向。06 的受阻时段保留停留，村口等待点采用归档坐标 `(104.6,379.3)`。冬瓜在 06C 沿凹路后送并抬上车板，06D 开始时已在车上，与该拍正文一致，老耿、妮儿和毛驴使用车身相对方位。

## 预演与定位

08A 村口按已有原文补回两名逃出院门的村民。到达村口后，两人先后从主街东边院门冲出、转向北跑，北屋现有机枪手转向两人扫射，各自中弹后用 0.85 秒扑倒。遗体留在实际中弹位置，08C 压枪眼和 10 段后送经过时继续保留。人物、射击目标和倒地进度按绝对时间取样，回溯与旧遭遇草稿读取同样生效。具体出门、命中时刻属于创作性预演布设。

右栏提供会话和原文。点选人物、车辆或区域后，当前选择会进入会话的定位附件，F 聚焦该对象。遭遇配置由 `Data_LevelFlow.mjs` 及 `Script_LevelFlowEncounter.mjs` 定义，既有本机草稿继续参与预演和帧包导出。

触发区支持玩家路线进入矩形／圆形，或从指定拍延迟若干秒触发。区内检查使用连续线段求交，移动触发区后会重算实际触发时刻；路线没有经过该区域时，对应生成组等待触发。

生成区可改阵营、总人数、同时在场上限、补充间隔、存续时长、移动速度、射击目标及行为。支持沿路推进、定点压制、掩体间跃进、绕侧、跟车、撤离和我方驻守。跟车组可选择头车或后车，武器可选择步枪或机枪，投弹间隔设为 0 可关闭投弹。数量为总预算，出兵受结束拍与同时在场上限约束。存续时长是预演中从出现到倒下的示例时间。实际射击命中、掩体遮挡、寻路与难度由玩法白盒验收。

启用“整批消灭后补充”时，每批最多为“同时在场”人数，前一批最后一人倒下后才开始下一批，批内仍按补充间隔进入。修改存续时长会同步重算后续批次。旧草稿与导入工程升级西坡默认布设，自改字段和删除状态继续保留。

补充间隔设为 0 且同时在场上限覆盖人数时整批生成。配置 `spawnOffsets` 的组从区域中心加各自偏移的位置出生，再沿各自第一段路线汇入推进路线。区域中心加偏移得到各人的实际出生点。`deployDelay` 控制低姿态隐蔽集结秒数，集结期间不移动或开火。`memberPlans` 按同时在场的单兵槽位配置 `{delay, route}`，`delay` 为集结后额外等待秒数，`route` 为出生点之后的世界坐标路点。配了单兵计划的槽位使用自己的路线，其他槽位沿共用路线移动。地图与立体视图显示各人的实际路线。旧 v2 草稿按字段升级，保留自改人数、路线、开关及已删除的组。

既有遭遇草稿从当前浏览器源的 `tengxian1938_encounter_v2` 读取，并随 PNG 帧包及会话定位附件导出。

每个视口左上方分别提供“当前剧情范围”“整个关卡”“自动跟随”，只调整该视口，悬停可查看说明。“自动跟随”再次点击会停止跟随，拖动镜头也切回手动模式。空间图支持拖动平移与滚轮缩放。跟随按玩家、近敌、战车与接应点的联合范围取景，保留屏幕边距。空格播放，左右键回溯，Shift 配合左右键跳五秒，方括号换拍。阶段、全部 68 拍、滑块和贯穿播放线使用同一条全程时间轴，宽度按真实持续时间分配。镜头动画段用斜纹标记，当前段在播放栏显示拍号与“镜头动画”，悬停可查看每拍原文标题和起始时间。

## 截图与本机会话

界面复用外层控制中心的 `Style_Editor.css` 与 `.edThemedSurface` 主题变量，面板、字段、描边、象牙白文字、衬线标题与旧金选中态均来自同一套菜单样式。按钮和面板保留圆角。

右栏默认宽 390 px，左边缘可拖拽调到 280–720 px，宽度保存在当前浏览器源。聚焦分隔条后方向键每次微调 20 px，Home 恢复默认。会话列表默认折叠，点击对话标题旁的菜单按钮展开左列会话列表与“新建会话”，右列显示当前会话的用户需求气泡与 Codex 最终答复。点击“新建会话”编写需求，首次发送时通过本机 `codex exec --json --output-last-message` 创建独立 CLI 会话。在列表选中既有会话后，后续需求通过 `codex exec resume <id>` 继续。CLI 沿用本机登录、模型与权限配置，按仓库 AGENTS.md 在独占 worktree 中修改源码。执行中可以切换其他会话，刷新后可从列表恢复查看。

输入区的“＋ 定位”附加点击时刻的 `Frame.json` 和 `Location.json`，包含拍号、精确秒数、玩家世界坐标、选中对象、当前遭遇草稿与各视口相机。附件显示在输入框内，可展开查看或移除。移动时间轴后保留附加时的状态，切换会话时随该会话草稿恢复。用户气泡下方可打开对应附件。文字需求可直接发送，定位由用户选择附加。

执行中的公开回复显示在 Codex 气泡里，包含当前执行状态、回复文字与更新时间。会话列表的“删除”将条目移入“已删除”，其中可以查看历史并点击“还原”恢复续聊。删除状态独立保存在会话目录的 `Deleted.json`，会话正文、附件与本机 Codex 转录完整保留，正在执行的任务继续运行。接口为 `DELETE /__encounter/codex/sessions/<id>` 与 `POST /__encounter/codex/sessions/<id>/restore`，均执行本机同源校验，支持重复请求。列表接口分别返回 `sessions` 与 `deletedSessions`。已删除会话须还原后才能发送新需求。

执行中的会话在标题栏显示“中断”。点击后结束该会话的 CLI 进程树，状态依次显示“中断中”和“已中断”。对话、截图、定位附件与输入草稿保留，可继续发送需求。接口为 `POST /__encounter/codex/sessions/<id>/interrupt`，沿用本机同源校验。运行记录保存 CLI PID，旧版运行中的会话按会话编号定位对应 CLI 包装进程。中断记录独立保存到会话目录的 `Interrupt.json`，供结束回调及其他预览服务恢复状态。

旧版 CLI 进程在任务完成后可能继续驻留。会话读取会核对对应转录末尾的公开进度与 `task_complete`，恢复最终答复并保存“已完成”，后续续聊按最新用户消息时间核对完成记录。旧会话缺少进度时显示“正在执行”；每次轮询继续读取更新，推理内容不进入会话面板。

“＋ 截图”是截图标注的统一入口，截取当前所有视口并暂停时间轴。支持箭头、框、文字、移动、撤销／重做、复制图片与导出 PNG。“添加附件”把当前标注图放入输入区，发送前可继续标注或移除。PNG 的 iTXt 键 `EncounterFrame` 保存完整帧数据、原图与标记，可用 `ReadPngFrameMetadata` 或 Pillow 的 `Image.open(path).info['EncounterFrame']` 回读。截图拍摄时的帧另存 `ScreenshotFrame.json`，截图与定位各自保留附加时的状态。

本地接口由 `scripts/Script_LocalPreview.mjs` 提供，只接受本机同源请求。控制中心启动器按仓库目录和服务端代码指纹复用预览进程，旧进程继续占用端口时会为当前代码另选端口。使用 `node scripts/Script_LocalPreview.mjs --no-open` 启动，再进入本工具。会话与附件保存在当前检出的忽略目录 `tmp/EncounterCodex/`。运行记录保存归属服务 PID，其他预览实例读取时保留存活服务的执行状态，归属服务退出后标记中断。历史执行记录缺少 PID 时保留其状态。CLI 公开进度进入实时回复气泡，思考内容与原始工具事件由桥接层丢弃。服务执行失败时显示固定的错误分类并保留已提交的需求与附件。CLI 原始错误输出和事件中的服务商错误文本直接丢弃，旧记录的原始错误字段读取时会归一化。会话私有目录经静态文件入口访问时返回 403，附件通过本机同源接口读取。桥接层调用本机已安装的 CLI 并继承其现有配置与认证；需求和附件会随 CLI 的模型请求发送到所配置的服务商。
