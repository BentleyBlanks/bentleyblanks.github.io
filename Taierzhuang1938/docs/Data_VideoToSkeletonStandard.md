## 来源与恢复

1. 先读取项目规范、交接说明与清单，在本任务独占 worktree 修改仓库脚本。
2. 检查 GPU、显存、驱动、PyTorch/CUDA 和模型依赖；核实 SMPL-X 等授权模型，禁止绕过许可下载。记录研究或商业使用范围。
3. 复用已生成原视频和可验证的观察缓存。没有新的生成授权，不重复付费生成视频。
4. GVHMR 本流程每次恢复一名目标。正式动作素材采用全身完整、四肢清楚、无其他人体干扰的单人视频。多人原片裁剪属于拆分实验，必须保留原片与实际推理输入；裁剪仍含其他人的头、腿等局部时不算严格单人素材。独立推理不恢复可靠的相对间距、共用道具和接触关系，后期组装必须明确注明。先核对二维观察再恢复三维，不让追踪在人物间跳转。
   后续生成视频默认使用约 45° 斜向、半俯视的固定镜头（默认方位角约 45°、向下俯角约 45°），避免纯水平侧视把四肢压在同一投影平面。站立、腾空及倒地时头、手、脚和完整运动范围都须入镜，尽量保持两腿可分辨。斜俯视有助于呈现前后关系，但不消除单目深度歧义；仍须检查二维关键点与三维膝盖方向，不能承诺靠镜头角度保证恢复正确。
5. 用户要求重新转换时，新输出目录必须实际重新执行推理；记录缓存复用范围、原片哈希、推理结果哈希、时间和环境。不可把旧预测改名冒充新版。
6. 保留完整恢复结果，再从原时间线选片段。循环取完整步态周期，只在局部接缝做平滑，不能从整段旋转线性扣除差值改变整个动作。连续跪起等片段共享坐标和边界姿态。
7. 相机内参和摄影机移动无法可靠恢复时，写明假设；区分原地动画与根运动，保留速度和位移信息。
   前进、后退及横移素材必须表现人物相对固定地面的实际位移。先检查动作语义、地面参照和全程入镜，再进入恢复；不能为了避免裁脚自行改成原地踏步，也不能用移动镜头或背景伪造行进。构图不足应扩大拍摄范围、缩小人物画面占比。游戏侧可从真实行进素材提取原地循环，但必须保留原片与恢复位移，在预览中明确区分该循环与根运动；未标定的米制距离仅为单目估计。
8. 左右横移按人物自身的解剖方向验收，用左右髋轴与移动位移的点积辅助确认；生成任务名和屏幕左右不能作为方向证据。发现任务标签写反时更正动作登记，保留原任务 ID、视频与缓存路径，通过配方的 `source` 映射关联，不镜像原片或骨骼凑名称。
9. 失败重做的素材放各来源的 `History`，最终原片从最新 `Data_GenerationResult.json` 的 `result_json.videos[0].path` 取用；不要用目录中第一个 MP4。生成费用按唯一成功 `submit_id` 去重记录，复制收据不能重复计费。约 45° 是生成镜头要求，未标定的实际视频不能登记为精确测量角度。

## 重定向与修正

保留游戏原人物的骨骼层级、绑定姿态、骨名和比例。BlenderMCP 编辑前核对当前工程归属，另存当前版本，避免覆盖历史结果或其他任务场景。

按原视频的支撑阶段和实际模型几何检查：支撑脚滑动、鞋底穿地、膝盖弯曲方向、重心转移、腾空/落地、手掌接触、背枪或持枪稳定、担架前后人的同步与握点。不能通过逐帧把最低鞋底拉到地面消除真实腾空。IK 不可超伸、反膝或破坏原身体比例。

循环检查首尾姿态和速度；转场检查相邻动作最后一帧与第一帧。枪、担架等道具约束随骨骼播放，导出后重新导入核对，避免 Blender 与 glTF 的父级变换差异。

GVHMR 的 22 个身体关节不提供可靠的手指握法和枪械姿态。持枪动作须单独校准枪托、左右掌面、护木握点、食指及拇指；保留手部约束前后的阶段与说明。不能把侧视投影看似正常当作手腕深度可靠，也不能把两腕连线直接视为枪口方向。握点距离为零不证明掌面、手腕弯曲、肘部和手指正确，验收必须查看贴图模型的侧面与斜侧近景。

持枪修正必须保留原动作相对身体的方位：横抱不能被 `lowready` 等通用规则改成向前端枪。先按原恢复的胸口、双腕和肘平面适配目标臂长，再放置共同枪体，最后处理掌面和握点。`gripStyle: recovered` 使用 `_import/Script_MotionRecoveredRifle.py`：根据原枪握点和校准掌面得到局部双腕基线，将其对齐恢复双腕；枪轴仍是独立的局部轴，上方向约束枪的滚转。护木握距在选段内固定，保持刚性枪体；必要的手腕调整及循环末端平滑需量化记录。枪口朝向还须对照原视频和贴图模型，不能只凭双腕方向正确宣布通过。

这类修改只重定向，不重复推理或生成视频。配方用 `recoveryRevision` 显式引用实际复用的原骨骼版本，用 `revisionLabel` 写明本次变化；不复制原预测冒充新版恢复。`_import/Script_MotionRiflePoseVerify.py` 在 Blender 中检查相对身体的双腕方向、接触、循环和身体/下肢不变性，浏览器 `Script_MotionBatchVerify.mjs` 对导出的 GLB 再检查同一方向指标。V5 曾出现握点正确但双腕被强制转向的失败，因此几何接触和动作方位须分别验收。

低位持枪若按恢复手腕放置枪械后超出目标模型的手臂长度，可在配方启用 `fitRifleToArmReach`：先将整支枪的共同位置约束到左右手腕都可达的范围，保留弯肘余量，再解两臂 IK，避免分别截断手腕位置而造成脱手。`rifleDownwardSlope` 控制低位持枪的下倾量，按原片姿态选取。`refineFootAnchors` 可在贴地后按实际蒙皮鞋底标记迭代补偿支撑期水平残差；只作用于重定向侧，仍须检查鞋底高度、膝盖角度与接触切换，不能把数值贴合当作自然度已经通过。

第三人称武器须检查完整装配；若原资产把枪托、机匣等拆进第一人称近景节点（例如 Type38 的 `adsNear`），不能只加载 `body` 后对着缺失的枪体调整握法。死亡动作使用非循环时间线并保留倒地末态；地面接触必须涵盖髋、躯干、肩和手，不能沿用仅按鞋底贴地的步态修正。

### 白刃战恢复保真检查

白刃战 V2 对照原始 NPZ 的身体关节和手腕旋转，骨架对应按解剖关系处理 BIP 与 SMPL 的不同父级，同时保留原绑定矩阵和骨长。握点为零不能抵消手腕被 IK 移走的误差。游戏完整骨姿采用父级相对轨道插值，并用实际导出 GLB 对照生产采样器；检查入口和保真范围见 [白刃战视频验收](Data_MeleeVideoAcceptance.md#v2恢复动作保真修正)。

## 实时预览契约

- `Preview` 是可持续扩展的本地站点。通过本地 HTTP 启动，默认仅绑定 `127.0.0.1`；依赖保存在本地，无需 CDN。
- 默认三栏依次为原始视频、重定向前的原始恢复骨骼、最新重定向模型。模型窗口用 GLTFLoader / AnimationMixer 或等价引擎直接播放 GLB，录制视频不能替代模型。原视频必须直接可见，不能折叠到次要参考区。
- 恢复骨骼直接读取 GVHMR 原始 `worldJoints` 等缓存，不使用重定向、脚部 IK、平滑或循环修正后的轨迹。只允许统一的坐标轴转换与查看用相机跟随；多人独立恢复的展示间距注明为查看摆位。
- 播放、暂停、速度、时间轴和逐帧在三栏同步。用该效果实际选用的原片起止秒数映射恢复帧和模型时间，不能把整段视频与截短动作直接按百分比硬对齐。没有记录对应原片或恢复数据时明确显示缺失，不用其他动作或版本替代。
- 支持动作搜索、阵营选择、正/侧/背视角、轨道查看、地面及模型骨架开关。默认只看当前阵营最新效果；V1/V2 等旧结果收进每个动作的“效果历史”，可按需查看和返回最新，不占据默认对比栏。
- 视频转换动作、多人拆分实验、原模型已有动作分组展示；后两组默认折叠。确认来自原 BIP/FBX 的动作标注“原片/恢复阶段不适用”，不能显示为丢失视频；真正尚未登记来源的条目进入“来源待登记”，不能猜测其来源。实验条目提供实际裁剪推理输入的链接及不符合规范的原因。
- 默认查看朝向按各原片登记，可用 `review.sideCameraYawRadians` 指定侧视相机方向；不能镜像原片或改变关节数据来凑朝向。允许用户自由旋转查看。版本按 `revisionOrder` 或 ID 中的数字版本排序，V10 应排在 V2 之后成为最新。
- 用 `Data_Catalog.json` 登记动作 ID、中文名称、循环属性、每阵营最新版本，以及版本中的阵营、GLB 路径、准确 clip 名、Blender 路径、验收状态和 `review`。`review` 包含 `sourceVideo`、`sourceRangeSeconds`、`recoveryTracks`、`recoveryFps`；每条恢复轨迹指向未经修正的原始数据。后续版本应明确写自己的对应关系，不沿用不匹配的旧选段。新增动作和版本无需修改播放器代码。批量生成目录的脚本必须保留已登记条目或从持久版本清单重建。
- 从 GLB 真正加载、检查随时间变化的骨骼矩阵并人工看姿态；HTTP 200、轨道数量或数值阈值通过都不能单独证明动作自然。

原始关节与来源映射由 `_import/Script_MotionReviewSources.py --root <资产库>` 从现有缓存导出；导出后运行资产库内 `Preview/Script_IndexLibrary.py` 更新目录。三栏播放、原片时间同步、模型运动、效果历史和缺失来源的验收入口为 `_import/Script_MotionLibraryVerify.mjs --root <资产库>`（Node，先启动本地预览）。原始关节 JSON 必须逐值核对其 `sourceCache` 内的数组及 `sourceCacheSha256`，不能只检验网页自洽。

全身接触采用按源片检查的接触权重、支撑平面、躯干接地和末态保持；这些都属于重定向侧修正。配方应记录每个动作的支撑区间、冻结末态帧、持枪/背枪形式。原地跑步原片不能测出可靠行进速度，任何游戏移动速度设定必须另行注明。Python 读取含中文配方或目录 JSON 时明确使用 UTF-8，避免 Windows 默认编码污染标签。

同一动作重新生成原片时，创建独立来源和版本目录，例如 `Video/Sources/RifleCrouchAdvanceV4`、`Models/ReviewV4`、`Models/_Cache/ReviewV4`、`Blender/ReviewV4`。持枪批次的 prepare、register、raw skeleton 脚本通过 `--revision 4` 使用对应原始骨骼和模型版本，prepare / register 另传 `--group ReviewV4`；baker 的效果版本与 `--grip-revision 3` 分开。原始骨骼的工程、GLB 和校验报告也按版本保存，不能覆盖之前的 raw rig 报告。用 `Script_MotionBatchVerify.mjs --root <资产库> --group ReviewV4` 单独验收，用 `Script_MotionBatchProvenance.py --root <资产库> --group ReviewV4 --revision 4 --without-death` 记录该轮来源；不必重新运行其他批次。原地演示同样需要完整、自然的左右步态，任何地面移动的参考速度应标明为估计或后期设定。

低姿步态若在鞋底贴地后支撑膝被拉直，可在该动作配方启用 `preserveSupportKneeBend`：用原恢复的膝弯角和目标人物腿长计算支撑距离，调整髋部高度，保持支撑脚锚点；摆动脚随髋部高度调整。双脚接触按权重协调，髋部修正经过短时间窗平滑，循环采用周期边界，避免接触切换造成高度突变。按左右支撑阶段对照原关节角度并检查实际姿态，不能把此修正默认套到全部动作。原地演示用配方 `travelMeters: [0, 0, 0]` 明确停止预览地面位移。完整入镜验收覆盖人物和枪械等所有导出网格，不能只检验皮肤网格而漏掉枪口。

## 交付与接受状态

### 全库重定向返修（ReviewV7）

`Script_MotionFidelityPrepare.py --root <资产库>` 从目录中每个视频恢复/拆分实验的实际最新效果取得原片、选段和原始关节引用。首次运行保存 `Models/ReviewV7/Data_SourceInventory.json`；续跑从该快照复现，避免把正在生成的新版本当作来源。核验原始 NPZ 的 SHA-256 和 `worldJoints` 逐值相等后才准备运动。此流程不重新生成视频、不重新运行 GVHMR，也不重写原始骨骼。

`Script_MotionFidelityBatch.py --root <资产库> --blender <blender.exe>` 实际重烘焙两军原骨架；`--ids` 限定动作，`--force` 在算法改变后重做。Blender 使用 `--python-exit-code 1`，并检查输出报告及工程、GLB 的存在。不能凭 Blender 普通退出码或旧报告判定新版成功。脚本从仓库运行，近战道具依赖项目 `Model` 和 `_blender` 下的资产及材质模块；资产库 `_Pipeline` 副本用于归档，不能假定它独立包含这些依赖。

此模式优先保持原恢复的身体姿态：按 SMPL 解剖父子关系计算原角色长度的骨段，按 BIP 实际层级写入姿态；保留绑定数据、骨名与层级。不用固定持枪方向拉动手腕，不用鞋底或躯干 IK 改变肘膝和倒地姿态。枪械适配恢复后的手部，普通步枪允许支撑手沿同一刚性枪体改变握点；手指取原角色握枪姿态。手指、掌面和道具姿态属于后期适配，不能当作 GVHMR 跟踪结果。不同角色比例会改变双腕距离，骨段方向相等仍不等于原片武器方向已被可靠恢复。

地面厚度适配只整体升降人体，并保留源关节最低点相对源支撑面的间隙。它不会把身体压平或把摆动腿拉直；原恢复的漂移和接触误差仍可能保留。循环只修改末端最多 0.2 秒，并分别记录未闭合数组与接缝窗口；闭合位置同时拟合末端速度。跪起系列采用共同的源坐标基准。首尾一致、骨段方向吻合与自然度是不同验收项，不能相互替代。

`Script_MotionFidelityPair.py --root <资产库> --faction Nra或Ija` 将重烘焙后的两位担架员装配为实验工程。共同担架用四腕刚性拟合，报告实际接触残差；不为掩盖多人恢复的间距误差再次拉动手臂。多人来源、裁剪输入和不符合严格单人规范的说明必须保留。

登记执行 `Script_MotionFidelityRegister.py` 后运行资产库 `Preview/Script_IndexLibrary.py`。历史保持不变，默认切到 V7。`Script_MotionFidelityVerify.mjs --root <资产库>` 读取实际 GLB 每一帧，核对 21 条解剖骨段方向、原长度、Blender 记录的关节位置、原始恢复在非接缝区的方向及循环首尾。`Script_MotionBatchVerify.mjs --group ReviewV7` 检查两军全部网格完整入镜；继续运行 LibraryDataVerify 与 LibraryVerify 核对原数据、对应时间和播放控件。配方、每模型报告、执行日志与导出保真报告均保存在 `Models/ReviewV7`。

### 大刀刀向与握柄返修（ReviewV8）

大刀不能由双腕连线直接决定刀尖朝向。`Data_DadaoBladeObservations.json` 保存人工查看原片后记录的刀柄到刀尖或可见刀刃线段，使用缓存的 30 fps 输入帧号；出画、遮挡和纵深缩短必须单独记录。原视频若不是 30 fps，应按秒映射，不能拿原生帧号直接套恢复缓存。观测坐标与估计深度分开，单目线段不能证明真实三维刀向或刀刃滚转。

`Script_DadaoBladePrepare.py --root <资产库>` 生成观测平面、深度先验和刀向轨迹；`Script_DadaoBladeBatch.py --root <资产库> --blender <blender.exe>` 从 V7 工程重导出五组大刀动作的两军版本。`--register-only` 仅重新登记已存在的报告与文件。深度分支整段求解，限制相邻帧变化，避免逐帧选择近/远解造成突然翻刀。滚转采用平行传输，仍需在实际模型中查看刀刃方向。

保持 V7 的身体、大臂、手肘和原骨长；先适配刀的可估计深度和柄上握距，再修掌面、拇指和手指。若原恢复双腕与短刀柄不能同时接触，仅将前臂末端投影到固定手肘、固定骨长的最近可握位置，逐帧记录腕点位移和前臂角度。此接触修正不能再标注为双腕完全保真，也不能用零握点残差代替自然度验收。原始恢复及 V7 保持不变。

`Script_DadaoBladeCheck.py` 把烘焙刀向投回原片观测平面；`Script_DadaoBladeVerify.mjs` 检查实际 GLB 每帧的刀向、道具位置、身体矩阵、固定手肘和前臂骨长，另报告腕点修正与相邻帧转角。继续用 `Script_MotionBatchVerify.mjs --group ReviewV8` 检查完整入镜和三栏同步出图。报告、工程和 GLB 只留资产库；仅这五组动作更新为最新 V8，其余保持原版本。刀尖出画和单目深度不确定性应留在审阅说明中。

每轮交付可编辑 `.blend`、包含原人物和动画的 `.glb`、实时预览入口、来源/修正说明与验收记录。历史版本可比较，新版区分“待审阅”“需修正”“已接受”。用户要求先本地看时，不直接替换线上正式动作。得到接入范围后再按项目规则导出游戏动作库、测试和发布。

当前 SMPL-X/GVHMR 研究产物按用户授权仅用于非商业研究和效果验证；正式商业使用前重新核对模型及来源许可。
