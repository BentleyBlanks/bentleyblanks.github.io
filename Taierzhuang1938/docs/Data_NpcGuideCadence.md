# NPC 带路跑通用设计：跑停、喘息与错峰观察

日期：2026-09-10。初版为设计规范；用户随后授权实装为共享小队行进基建，并增加可视化编辑器。当前接入与使用方式见第 8 节，验收范围见第 9 节。复用现有人物与动作，不生成新资产。

Notion 同步：[NPC 带路跑通用设计｜跑停、喘息与错峰观察](https://app.notion.com/p/3d760335331c81dc97e8ddb2dd069de4)，位于项目现有「玩法说明」目录下。

来源：用户对 COD NPC 跑动表现的观察——「跑动几步，停下来喘一下、左右看看，再跑；每个人停下来的时间都错开（除了班长以外）」。这是一条明确采用的表现要求；下述调参起点是本项目建议，不是对 COD 内部实现或数值的实测。

## 1. 适用范围与体验目标

本规则适用于《台儿庄：血战滕县》当前及后续所有关卡中，由 NPC 带路、玩家跟随队伍跑动的移动段，包括接令转移、赶路、战斗间隙转场和脱离即时危险后的撤离。只要进入相应带路跑情境就复用，不依赖第一关、某个阶段、固定路点或某名具名同伴。

玩家应看到一支有呼吸、有警觉、各自调整步伐的队伍：前面的人短停观察时，旁边或后面的人还在跑；有人重新起步，另一个人才准备停。整体方向持续清楚，队伍仍向目的地推进。

## 2. 普通队员的完整循环

1. **跑出几步**：沿实际可通行路线跑向自己的前进位置，保持松散间距；不是全员匀速黏在班长背后。
2. **减速停稳**：到可站立且不堵路的位置，连续减速、收步、落稳双脚；停步必须真实影响世界位移。
3. **短停喘息与观察**：胸肩有短促呼吸，头颈带动小幅上身向左右观察，再把注意力收回前进方向。左右先后、幅度、停留时长允许变化；不能整队机械地按同一顺序摆头。
4. **重新起跑**：视线与身体自然转回路线，重心前移，平顺接回跑动；从当前位置追上队伍，保留个人横向间距。

喘息和观察可以在同一次短停中重叠，不拆成两段冗长演出。不新增体力条、耗尽惩罚或必须看完动作才能继续的交互门槛。

## 3. 个体错峰是行为规则

- 每名普通队员有独立的跑动计时、首次停步偏移、短停时长、观察选择与再次起跑时刻；以稳定的演员身份建立可复现的随机序列，每轮在合理范围内变化。
- 全队同时进入一个任务阶段时，不把所有人的计时清零为同一值；离开镜头、切换远景表现或恢复更新也不能让全员重新同拍。
- 只给同一动画不同播放相位不算达标，必须错开真实的停步与起步事件。也不能每轮固定按甲、乙、丙的顺序轮流，形成另一种队列节拍。
- 独立随机之外，局部队伍还要限制新停步的密度：已有邻近队员短停时，其他人的停步申请适当延后，确保移动段仍有人推进，避免一片人同时刹住。任务集合、真实避险等高优先级导致的集体停步不属于本规则的问题。
- 队伍过度拉长或本人明显掉队时，取消或缩短可选短停，优先赶上；跟上后重新分散节奏，不能靠瞬移、穿过他人或异常加速补偿。

## 4. 班长例外：引导职责决定停走

班长不进入普通队员的随机「跑几步就停下喘息」调度。当前带队者保持可识别的前进方向与合理领先距离，避免玩家误以为路线结束或要在此集结。

班长仍会根据真实情境停下：路口确认方向、回头看队伍、等候掉队玩家、做跟上手势、下达命令、观察威胁或进入掩体。这些停步由引导或战术职责触发，不能被普通队员的随机计时抢占；停等时可以有自然呼吸和扫视，不能被理解为「班长永远不喘气、永远不停」。

职责通过角色配置表达。其他关卡换一个班长或带路者仍适用，禁止只对某个姓名或 `castId` 写特例。发生带路职责交接时，新带路者退出普通错峰调度，接住方向与等候责任。

## 5. 情境优先级与通行保护

- **直接战斗与避险优先**：受击、近爆、压制、必须穿越的暴露区、冲锋、躲避和战术掩护中，取消或中断可选喘息停步；必须先抵达合理安全处，不能在火线上按表演计时罚站。进入战斗交给原战斗 AI，喘息不冒充战术交替掩护。
- **通行优先**：门口、窄壕、车梯、翻越、攀爬、跳跃、坡边及拥堵处不新发起短停；通过后再寻找安全位置。不得偏离导航去墙内、悬空处或危险区找「表演点」。
- **协作动作优先**：同一副担架的两名抬手、搀扶双方、推车与搬运人员保持原协作节奏，不对其中一个人单独插入随机停步。受伤角色保留伤势与专用移动规则。
- **剧情与任务事实优先**：必须完成的交互、真实到位、集合、对白中的必要指令和角色死亡保持原因果。普通喘息不触发「已抵达」、不重播口令、不替玩家完成任务。
- **玩家保持自由**：玩家可以跑快、停留、超前或回头；不锁移动、不强转镜头、不要求玩家跟着 NPC 喘气。班长沿原引导逻辑接应，不能为了展示循环强迫全队等待玩家观看。

## 6. 动画、声音与共享接入

移动系统负责路径、碰撞、贴地与真实速度；行为层负责跑停决策；动画层依据速度和行为状态选择并混合动作。停稳后不能继续跑步滑行，起跑不能弹跳或瞬间转向；头颈扫视保持自然转角，双手与枪械接触连续，脚底不漂移。

现有 [站立待机叠加层](../Script_ActorStandIdle.mjs) 与 [待机参数](../Data_Tuning_ActorIdle.mjs) 已提供呼吸、重心与扫视，可作为表现接入点，但不能替代真实跑停调度。跑步、持枪与停止姿态要结合 [步兵动作说明](Data_InfantryAnimations.md) 和 [人物动作需求](Data_FirstLevelMissionAnimationRequirements.md) 复核可用素材；「有文件」不等于衔接合格。

若播放喘息声，只在真实短停时按距离、个体时机与局部声源预算选择播放，避免全队同一声齐响；对白和战斗关键信息优先。无声或低画质时，动作仍须读得清。新增素材的供应商与授权遵循 [根规范](../../AGENTS.md)，本次不生成。

实现时由跨关卡共享行为控制器与纯数据参数提供能力；关卡只传入路线、角色职责、队伍关系、即时危险和必要情境覆盖。不得把完整循环塞进第一关任务时间轴，再向其他关逐份复制。更新、暂停、重试和角色移除须正确管理个体状态；切换远近景表现不改变行为语义，也不以频繁重寻路或逐帧随机采样实现。

## 7. 验收标准

1. **连续动态观察**：在足够长的正常带路跑段，从玩家视角连续观察班长与至少三名普通队员，每名普通队员完成至少三轮跑停。能读到收步、真实停稳、喘息、左右观察、再起跑，且不会全员同时停走或按固定顺序轮转。必须查看实际动态过程，单张截图不能证明错峰。
2. **事件取证**：记录演员身份、职责、行为状态、停步原因、进出时间与实际速度，核对不同人的首次停步、停留与起跑时间；定种子可复现，不因帧率或远近景切换重置为同步。
3. **班长与玩家节奏**：班长不会因普通喘息计时停步；玩家落后时会等候或接应，超前时仍保持方向可辨，职责交接后新带路者遵守同一规则。
4. **中断与恢复**：覆盖敌人出现、近爆、受击、死亡、门口堵塞、坡地、翻越、暂停恢复和重试；恢复后不会立刻集体喘息。担架、搀扶与搬运不被拆散，任务事实只触发一次。
5. **跨关卡复用**：至少在两套独立关卡配置验证同一共享行为；后续正片关卡尚不可玩时，可用两套本地路线／角色配置验证，明确标记为夹具证据，不能称已完成多关正片验收。更换带路者身份后，普通队员错峰和班长例外仍成立。
6. **表现与预算**：复核近景脚底、持枪与转头衔接，以及远景、低画质、无声模式和原有人群更新预算。素材不足、滑步或只有局部循环通过时记录未完成项，不宣称整体自然化已经上线。

实际执行结果按第 9 节记录；设计标准不能代替实测。

- [纯行为控制器](../Script_SquadMarch.mjs) 处理个体跑停、局部错峰、队形路线、追赶与班长等待；稳定种子重播，不依赖 Three.js、关卡号或人物姓名。
- [AI 接入器](../Script_SquadMarchAi.mjs) 接受已有士兵句柄，走现有 AiDirector 的导航、碰撞、贴地与战斗；[动作接入器](../Script_SquadMarchActor.mjs) 复用正式模型、跑动片段与足底固定的呼吸观察层。
- [可视化编辑器](../Script_EditorSquadMarch.mjs) 使用同一纯行为控制器和正式人物模型，在平地摄影棚预览。平地预览用于调队伍样式；墙体、地形与战斗接入另在实际关卡验证。
- 新版第一关所有 `Guide(route)` 移动段接入共享跑停调度。原有任务路点到位判定、关卡专用路线和战斗优先级保留；不会改变既有剧情人口或替换担架协作系统。

### 最小关卡接入

```js
import { SquadMarchAi } from './Script_SquadMarchAi.mjs';

const squadMarch = new SquadMarchAi(ai, soldiers, {
  leaderIndex: 0,
  seed: 'VillageTransferA',
  preset: 'guided',
  route: [{ x: 0, z: 0 }, { x: 0, z: -20 }, { x: 12, z: -30 }],
});

// Called by the active level update; soldiers are existing, persistent actors.
squadMarch.Update(dt, { player: player.position });
// On level exit:
squadMarch.Dispose();
```

人数由 `soldiers.length` 得到，班长通过名册下标配置；目标默认是路线末点，也可提供 `goal: {x,z}`。`guided`、`walk`、`urgent` 分别为带路跑、步行、紧急转移。可用 `tuning` 覆盖少量共享参数；每个路点可附 `width`；包含窄口的默认队形保守采用纵队，窄处禁止随机短停。开放地面若有人长时间堵路，共享层寻找经过邻人间距和宿主导航检查的局部绕行；静态障碍、碰撞与坡地仍由原 AI 负责。

已有任务编排可以通过 `Move` 回调保留自己的移动装配，并在 `Observe` 提供实时 `route`、`active`、`maxSpeed`、`busy`、`noPause`、`canPause`。`maxSpeed` 传入宿主允许的速度上限，避免把另一层已经减速的结果再次减速。AI 接入器设置 `turnLimited: false`，身体朝后观察不当作行进转弯；真实转身和移动仍由原 AI 处理。玩家沿路线超前过远时，全队优先追赶，暂缓可选喘息与班长的常态慢速领跑；折线后的玩家位置按路线进度判断。

观察和威胁必须来自宿主的真实状态；看不见的敌人记忆本身不持续抢占行进，可见威胁、近期真实开火、受击和压制仍立即中断短停。缺少导航证据时不自行认定可以安全停步。

班长等待玩家时，远处掉队的队员继续归队。原有任务若把远路点裁成短目标，实际卡住后会向现有 AI 交回原始远路点，启用导航；导航仍受挡时，用 `CharacterBody.ProbeMove` 只读探测附近方向，沿可通行边缘短距离移动，保持脱困方向直到能回到原路线。探测不修改人物位置，真正位移仍经过原碰撞与贴地系统；脱困途中不插入喘息，威胁中断和路线变化会清理临时目标。共享层也保留队员与静止玩家的间距。

`AddMember` / `RemoveMember` 接入或移出已有演员，不生成和删除剧情人口；`SetLeader` 交接带路职责。演员死亡退出调度，班长阵亡时由仍存活的队员接替。中途增员不重置原成员的跑停计时。

### 编辑样式

1. 选择 1–24 人（含班长），指定谁带队。快捷人数覆盖单人、小组和大队。
2. 修改随机种子，或点「换一个随机样式」。相同配置和种子可用「同种子重播」复现。
3. 调整速度、横向疏密、前后间距、跑动与喘息时长、停步间隔、个人速度差和观察幅度。
4. 在俯视图中拖动路点；点击空白处追加，右键删除；也可直接编辑 X/Z。末点就是目标，提供直线、折线和窄口预设。
5. 播放、暂停、单帧、半速/倍速；轨道相机可观察全队或跟随选中成员。时间带显示每人的真实跑停状态。
6. 「保存此人数的样式」保存到当前浏览器，每个人数保留一套；导出 JSON 可用于关卡或转移到别的电脑，导入先验证人数、路线、班长和参数范围。

编辑器调整后重新开始预览，不改正在暂停的正式关卡；退出归还人物、相机、舞台和游戏状态。浏览器本地保存与 JSON 导出不等于写回仓库或发布关卡配置。

## 9. 本次验收记录

- 规则：1、3、6、9、12、24 人连续跑动 90 秒；普通队员各至少三轮停跑，班长例外、定种子重放、暂停保留时钟、战斗与死亡释放、接替班长、增删成员、紧急模式、等待玩家、无效配置拒绝。1–24 的每个人数另以不同种子走折线与窄口，180 秒窗口内均到达。
- 已执行 67 项 quick 检查通过；包括新版第一关任务事实、导航路线、现有动画/资产契约与模块图。后续新增修改按受影响范围复核。
- 浏览器编辑器：真实 3／6／12／24 人模型、班长选择、种子、滑杆、路线拖点、按人数保存、JSON 下载与文件导入、退出归还控制通过；无浏览器运行错误。6 人连续模拟 90 秒，5 名普通队员分别完成 9、7、11、9、10 轮，班长 0 轮；逐人时间带与真实位置记录用于验证错峰。
- 动作：停步近景的实际位移为 0，0.1 秒内头部骨骼转角变化约 0.097 弧度，脚底世界坐标漂移小于 0.000001 米。已查看全队与喘息近景截图，复用既有人物与持枪动作；本次没有新增喘息音频。
- 接入器：直接使用真实接入器验证看不见的敌人记忆不抢占行进，可见威胁、近期真实射击、压制、受击、翻越、搬运、伤员与离地会释放；停止接管时保留宿主后来下达的新指令。第一关任务、模块图和测试登记随最终逻辑修正复核通过。
