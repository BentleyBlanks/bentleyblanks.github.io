# Easy Red 2 玩法系统拆解 —— 可落地到 three.js 版《血战台儿庄》的实现级分析

> 对标基准。由调研 agent 检索 Steam News API 全部 165 篇更新日志、官方 wiki、TV Tropes、评测抓取整理。
> **存疑部分已在文末标明** —— 凡是推断值都要实测调参，不要当成 ER2 的实际数值。

> 本文所有结论均来自实际检索：Steam 商店页与 165 篇官方更新日志（经 Steam News API 全文抓取后逐条检索关键词）、官方 wiki（wiki.easyred2.com）、官方 **Scripting API 全量函数清单**（easyred2.com/wiki/scripting.php，这是最硬的一手证据——它等于把 ER2 的对象模型摊开给你看）、Steam 社区两篇长攻略、TV Tropes 条目、以及 Tally-Ho Corner / Phenixx Gaming 两篇评测。查不到的部分统一列在 uncertainties，不编。

## 0. 先说结论：ER2 到底是个什么结构的游戏

ER2 不是「战役 FPS」，它是**一个用 FPS 视角包装的小型战役模拟器**。它的真正内核是一套很小的状态机：

```
Mission = [Phase 0, Phase 1, ... Phase N]
Phase   = { 若干 Objective(占领区) , 双方 Spawn 区 , 可选剧本 }
Objective = { position, radius, progress 0..1, owner, attractor(是否吸引AI) }
Battle  = { invadersTickets, defendersTickets, aiCountPerFaction, difficultyParams }
```

玩家只是这台机器里的一个**可替换零件**——你死了，机器不停，你换一个士兵接着当零件。ER2 全部的「史诗感」都是从这个结构里长出来的，不是从美术或者剧本里长出来的。这一点对我们做《血战台儿庄》至关重要：**这套结构在浏览器 three.js 上完全可以 1:1 复刻，因为它几乎不依赖画面精度，只依赖「同屏很多人在同时做事」这一件事。**

Scripting API 里的这几组函数把整个模型钉死了：

- 全局：`getInvadersTicket()` / `addInvadersTickets()` / `getSettingTicketsMultiplier()` / `countAliveDefenders()` / `countAliveInvaders()` / `getCurrentPhaseId()` / `nextPhase()` / `setVictoryInvaders()`
- 目标：`getProgress()` / `setProgress()` / `getRadius_missionobjective()` / `isInside()` / `setAttractor()`
- 士兵：`getSuppressionValue()` / `isSuppressed()` / `isBleeding()` / `isIncapacitated()` / `isSurrendering()` / `surrender()` / `isOutOfStamina()` / `findCover()` / `isOnCover()` / `carryBody()`
- 班组：`moveTo()` / `attackFromPoint()` / `charge()` / `coverArea()` / `holdFire()` / `fireAtWill()` / `followLeader()` / `setClosestObjective()`

注意一个**反直觉的重大发现**：整个 API 里**没有 morale（士气）这个概念**，450KB 的官方更新日志里 "morale" 出现 **0 次**。ER2 没有士气条。它用 **suppression（压制值）+ 自动投降 + 撤退指令** 三件事，模拟出了别的游戏用「士气系统」才能做出来的效果。这是我认为最值得抄的一条设计——**用一个连续量（压制）+ 一个离散事件（投降）就够了，不需要第二套士气数值**。

## 1. 战场结构：开放战场 + 相位化占领点 + 票数

### 1.1 地图规模与开放性

商店页原话是「large destructible open-world maps」，评测里描述为「spacious affairs studded with unfolding objectives」——山峰、据点、农舍、村庄、镇子、葡萄园在同一张图上。玩家攻略的战术建议直接写「Go around the enemy in case they have too much firepower, **remember that the map is always very large**」。**绕侧是真的可行**，这是它跟走廊关的根本区别。

地图编辑器支持自定义高度图（png/jpg，尺寸不限、会按 mapsize 归一化，但必须是正方形），并且有「Big maps only」才开放的草密度选项——说明存在大小档位。**但官方从未公布过具体 km² 数字**，我没查到，列进 uncertainties。

关键点不是「多大」，而是**开放性的三个具体表现**：
1. 占领点之间有**大段无脚本的空地**，你可以选任意路线接近；
2. 空地上有**可破坏植被**（更新日志反复提到 "Improved vision-blocking system of many vegetation assets"），植被是**真的挡视线**、并且**会被打掉**；
3. 玩家、AI、载具、飞机在**同一张图同一时间**活动（combined-arms），不分关卡段。

### 1.2 占领点机制（这是最该照抄的一段）

从社区攻略的 Gamemodes 章节，机制描述得非常精确：

- 一个 mission 被切成若干 **Phase**；每个 Phase 有一个或多个 **cap point（objective）**。
- **图标语义**：需要打/可以打的点 = **交叉刀剑图标**；已占领的点 = **旗帜图标**。这两个图标同时出现在 HUD 和地图上。
- 占领是**进度条**：评测描述为「a progress bar 由红转蓝」。API 侧就是 `objective.getProgress()` 返回 0..1，`setProgress()` 可写。
- 编辑器里每个 objective 可设 **radius（半径）** 和 **conquer time（占领所需时间）**——所以「大点慢、小点快」是设计者手调的。
- **可以被反夺**：「When multiple cap points are available, **defender can always retake captured cap points**」。注意这条限定——多点时防守方能反夺。
- 全部 Phase 被拿下 → 进攻方胜；防守方**只有一种赢法：把进攻方的票耗光**。

关于「驻守人数」：我**没有查到**明确的「N 人加速占领」规则。ER2 更像是「区内有攻方无守方 → 进度涨；双方都有 → 争夺/停滞」。这条列进 uncertainties。

### 1.3 兵力池 / 票（tickets）—— 消耗规则改过两次，最新版才是对的

这是我认为最值得注意的一段演化史，因为它暴露了设计者踩过的坑：

- **早期**：「Attacker will start with a certain amount of tickets that will be **reduced on each squad or vehicle deployed**（每投入一个班组或载具就扣票）」。
- **后来改成**：更新日志明确写「Changed the way ticket system works, by **counting dead units instead of respawns now**（改为统计阵亡单位而非重生次数）」。
- **再后来**：「Battle Tickets now depends on selected AI amount as well」——票数跟你选的 AI 总量挂钩，避免大兵力局票数不够用。
- **2.0.9 防守模式重做**：「**Captured objectives now have a greater impact on ticket drain speed**（占领的目标对票流失速度影响更大）」「Defender tickets now scale more appropriately with unit count」「**Ticket gains between phases now adjust slightly based on the remaining tickets**（阶段之间的票补给会根据剩余票数微调，形成自动平衡）」。

翻译成设计语言：**票 = 进攻方的耐心额度**。每打赢一个 Phase 会**补票**，而且补多少跟你剩多少票挂钩（打得惨会多补一点，打得顺补少一点）——这是一条**隐形的橡皮筋难度**，非常聪明，值得抄。

信息可见性也是设计：**进攻方只能在出生菜单看到自己的票；防守方必须站在占领区内才能看到敌方剩多少票**。这把「侦察」变成了信息优势，不是白送的 UI。

### 1.4 三种模式

| 模式 | 规则 | 票 |
|---|---|---|
| **Operation** | 一攻一守，攻方按顺序推 Phase | 有，攻方耗尽即败 |
| **Push the Frontline** | 从中间 Phase 开局，双方互为攻方，赢一个 Phase 把对方推后一格；把对方推到最后一个 Phase，或在 (总Phase数×2) 局后赢得更多 Phase 者胜 | **无票** |
| **Defense**（后期加入） | 防守方视角，占领目标加速票流失 | 有 |

**Push the Frontline 就是「动态战线」的最小实现**——不需要真的模拟战线曲线，只要一维的 Phase 索引来回移动，玩家就会感觉到战线在推拉。这个技巧对 web 版极其重要。

## 2. 玩家死亡：「换一个人接着打」

TV Tropes 条目（The Dead Have Names 词条）原文描述得最准确：

> 类似《战地1》序章，每次你在战役中阵亡，你会看到刚才操控的那名士兵的**姓名与生卒年月**，然后接管（或者说重生为）**另一名**士兵。

配套的还有几件事，构成一个完整的设计闭环：

1. **随时换人，不只是死后**：按住 **X** 打开径向菜单，切换到本班组任意成员。API 对应 `setPlayer()`。
2. **死后重生要从暂停菜单手动执行**，并且**每个剩余班组成员都要单独操作**——不是无脑自动接管。
3. **重生消耗票**（早期是投入班组扣票，现在是阵亡计数）。票没了 = 真的没人了 = 输。
4. **尸体有身份**：翻死者背包能看到**狗牌**上的名字，甚至有「收集狗牌」的成就系统。
5. **重生后有几秒无敌**（更新日志：「Player is now invincible for a few seconds after respawning」）——防出生点秒杀。
6. **班长阵亡会移交指挥权**：按 班长 → 无线员 → 机枪手 → 狙击手 → 步枪兵 的顺位自动接替，当前班长身份显示在屏幕左上。

**这个设计对体验的作用（我认为是 ER2 最核心的一招）：**

- **把「你」降级成「一个兵」**。死亡不是失败、不是读档，是**换视角**。战斗的主体是那支部队，不是你。
- **战场尺度感来自「你死了但仗还在打」**。你重生后回到战场，发现刚才你没打下的那个点已经被 AI 拿下了 / 已经丢了——这一瞬间战场就「活」了。这是**用最低成本制造规模感**的办法：不需要更多多边形，只需要让世界在你缺席时继续演进。
- **姓名 + 生卒年月这一屏，成本几乎为零，情绪回报极高**。它把每次死亡从「操作失误」重新框定为「一条命没了」。

> 对台儿庄来说这条是天赐的：中国军队的伤亡叙事、「一个班打光换一个班上」的历史质感，跟这个机制是同构的。名册可以直接用姓名库 + 籍贯 + 部队番号程序化生成。

## 3. 指挥与命令系统

### 3.1 命令轮盘

**按住 TAB** 打开命令菜单（只有班长身份可用，`isSquadLeader()`）。完整指令表（来自社区攻略 Role/Class 章节，与 API 的 Squad 函数一一对应）：

| 指令 | 效果 | API |
|---|---|---|
| **Follow**（默认） | 全员跟随班长 | `followLeader()` |
| **Move and Hold** | 全员前往指定点并固守 | `moveTo()` |
| **Attack Objective from Direction** | 全员**先绕到目标外围某方向的集结点**再进攻——这就是「侧翼包抄」指令 | `attackFromPoint()` |
| **Line / Column Formation** | 跟随时切换横队/纵队 | — |
| **Charge** | 全速冲向指定点；**并且全员会自动上刺刀** | `charge()` |
| **Covert Movements**（1.3.6 新增） | 全员**扣火**潜行接近，直到发出 Fire at Will 或被敌方察觉；**AI 会模仿班长的姿态**（你趴他们也趴），由班长决定潜行程度 | `holdFire()` / `fireAtWill()` |
| **Tank Support** | 呼叫坦克开到指定点（需无线员确认） | — |
| **Artillery Smoke / HE / APHE** | 呼叫炮击指定点（需无线员确认） | — |
| **Spot** | 给敌方单位打标记，持续一段时间 | — |
| **Retreat** | 撤退（更新日志提到过 retreat order） | — |
| **Cover Area** | 定点防御一片区域 | `coverArea()` |

**AI 会不会真执行？** 会，但执行质量是 ER2 争议最大的地方（见第 10 节）。1.3.6 那次「有史以来最大的重做之一」专门修的就是这个：「substantial improvements to how AI **aims before firing**, **takes cover**, and overall, **follows orders** and navigates the environment」。

**Covert Movement 这条我特别想标出来**：它把「潜行」做成了**班组级的姿态传染** + **可见度模型**——蹲下/匍匐降低整个班组被发现的概率，而且「敌人不知道你存在时」才享受这个加成。这是一条**极低成本、极高战术密度**的机制。

### 3.2 支援呼叫链（这是 ER2 最有仪式感的系统）

ER2 没有做成「按 4 呼叫炮击，冷却 90 秒」。它做成了**一条会断的链路**：

**必要条件（缺一不可）：**
1. 班组里得有**活着的无线员**（`isRadioman()`，背上有可见的电台背包模型）。**无线员死了 = 全班失去支援能力**。
2. 地图上得有**可用的己方火炮**（友军炮兵在地图上显示为「蓝色方块中间带圆」的标记）。
3. 班长可以**捡起电台背到自己身上**，从而自己既下令又确认。

**流程：**
- 班长在轮盘上选「Artillery HE / Smoke / APHE」并**瞄准落点**；
- 无线员收到请求提示 → 按 TAB 打开电台界面 → **做一个坐标小游戏**：屏幕给出高亮数字，你要在数字组里逐个点对；**点错就偏靶**。
- 2.0 版本重做后：无线员**可以不等班长指令自行呼叫**；坐标系统改为「converting inputs into **real in-game world coordinates**」；加了**专用的迷你地图 UI 来指定炮击点**；**可以选炮弹类型**。
- 还加了 **cancel artillery fire**（可取消炮击，AI 也会在必要时取消）——说明存在**呼叫→落弹的延迟窗口**。
- 如果你在地图上**亲自操作一门炮**：无线员确认弹着点后，你屏幕上会出现一个**炮弹图标 + 图标下方一个数字**，你把炮口转向图标、把炮的仰角刻度调到那个数字，就打中了。**这是把「间接射击」做成了一个手工操作**，而不是一个按钮。

**烟幕**是独立的一层：迫击炮和火炮都有烟幕弹；步兵个人按 **H** 直接丢烟（只要背包里有）；按住 **G** 开投掷物轮盘（烟幕/炸药/反坦克手雷/TNT/弹药箱/反坦克地雷）。**AI 突击班组会自己放烟掩护推进**——TV Tropes 里把这条列为 AI 少数几个真聪明的行为。

**冷却与限量怎么设计的？** 官方**没有公布数值**。可以确定的是：**限制不是冷却条，而是资源链**——无线员活没活、有没有炮、坐标输没输对。这个设计我强烈建议照抄：**用「链路可断」代替「冷却读秒」，戏剧性高一个数量级**。

## 4. 战斗手感

- **准星是可选项，不是默认**。设置里有「Show crosshair / Show hitmarker / Show armour penetration」三个开关，攻略明确把它们标为「给休闲玩家的」。简单难度**自带准星且免疫压制**。后来还加了 **crosshair size 设置**和**自定义准星**（往 mods/sprites 丢一张 512×512 的 png）。
- **没有自由瞄准（free aim / 武器 deadzone）**。我在全部日志和 wiki 里都没找到 free aim。ER2 的「不好瞄」来自**另外四件事**：
  1. **铁瞄不在屏幕正中**。开发者 Marco 亲自回帖确认这是**故意的**，不是 bug——武器瞄具就是偏的，而且**要等 ADS 动画播完再开枪**。
  2. **视差**：瞄具和枪管不共轴，近距离必须心里做修正。「crosshair 可以帮你预判枪管实际指向」——所以准星在这里的作用是**补偿视差**，不是给你辅助瞄准。
  3. **武器晃动（sway）**：更新日志「**Intense weapon sway is now back for Realistic difficulty**」——写实难度晃得很凶。
  4. **压制会加剧晃动**：「Changes in **suppression sway**」——被打压时准头直接变差。
- **屏息**：ADS 时按住 Sprint（Shift）→ 减少晃动 + 视野轻微放大；**持续时间随难度变化**；写实难度还有专门的屏息音效。
- **归零（zeroing）**：**Page Up / Page Down** 调表尺距离——说明**弹道下坠是真实存在且需要玩家补偿的**，而且难度设置里能直接调「**bullet gravity**」。提前量没有明说，但既然有重力和飞行时间，提前量必然存在。
- **栓动节奏**：拉栓是有动画和时间成本的，更新日志专门优化过「bolt-action animations to **synchronize more accurately with body movement**」和「FPS when cycling bolt」。TV Tropes 直接点出这是「栓动与半自动的过渡期」，M1 加兰德 8 发半自动对 Kar98k 5 发栓动是**真实的火力代差**，不做平衡。
- **后坐**：反复重做过（「Big changes in the recoil system for better and more stable shooting experience」「Reworked camera, recoil and ADS systems」）。机枪必须**架两脚架**才能 ADS（MG42、Browning 30 Cal、Boys 反坦克枪、PTRD-41 等**不架就不能开镜**），架起来后坐力大降。
- **杀伤**：很多步枪**躯干一枪致死**；打不死的也会**直接失能**。TV Tropes 原话：这是个「一两下就会死」的游戏。
- 其它手感细节：**弹匣是逐个追踪的**（提前换弹会在背包里留一个半满弹匣）；可以**手动往空弹匣压子弹**；空枪只有散弹时**可以单发上膛**；按 **0** 切换发射模式；**V** 近战（刺刀一击致命，无刺刀两下）。

## 5. 伤害与生存：压制、伤口、投降

### 5.1 压制（suppression）—— 有专门的数值

API 里 `getSuppressionValue()` 返回**连续量**，`isSuppressed()` 返回布尔。表现层：

- **屏幕暗角（vignette）特效**（「Removed vignette suppression fx at easy difficulty」证明它默认存在）；
- **准星晃动加剧**（suppression sway）；
- **AI 被压制会趴下**——1.3.6：「spend more time prone when under suppression」「duck prone under suppression more often」；
- **AI 有专门的压制反应掩体动画**（「Added new AI cover animation reacting to suppression fire」）；
- AI 参数里有 `allowFindCoverWhenSuppressed()`——**压制驱动寻掩体**是独立可开关的 AI 行为；
- **压制强度是难度滑条之一**（「modify ... suppression effects」），简单难度**玩家完全免疫压制**。

### 5.2 「士气」其实是投降

再强调一次：**没有 morale 数值**。取而代之的是一组**投降触发条件**（TV Tropes + 更新日志交叉验证）：

1. **被压制到一定程度**会投降（`surrender()` / `isSurrendering()`）；
2. **自己所在的占领点刚被对方拿下**，点内的人会投降；
3. **进攻方票耗尽时**，附近敌军会**直接扔枪投降**；
4. 也有单位选择**死战到底**或**撤退再战**；
5. **玩家自己也会自动投降**——更新日志：「Player now doesn't surrender automatically anymore when **heavily suppressed and losing defended capture point** at Easy and Normal difficulty」→ 说明**写实难度下玩家依然会被强制投降**，而且难度设置里有「disable player auto-surrender」开关；
6. **战俘可被解放**：靠近己方投降士兵按 F「liberate」，他们会**掏出手枪继续作战**；
7. 给**受伤的敌人做医疗**会让他**投降**（等于俘虏）；
8. 投降者可以被杀（TV Tropes 的 Video Game Cruelty Potential 词条）。

### 5.3 伤口 / 流血 / 医疗

分两层：

**轻伤（自救层）**
- 中弹后**屏幕变黑白/灰**，并且**不能跑、不能屏息**；
- 按 **B** 直接用绷带（背包有就行，不用开背包）；也可以在载具内用；
- 「If you don't heal you'll die」——**不处理就会流血致死**（`isBleeding()` / `applyBleeding()` / `removeBleeding()`）；
- 消耗品：金枪鱼罐头回约 40% 血，药片回约 90%。

**重伤（失能层，需要医护兵）**
- 被打到**倒地失能**（`isIncapacitated()`）才能被救；
- 医护兵有**三种器械**：注射器、剪刀、医用镊子；
- **必须先诊断**：伤员头顶会浮出一个**器械图标**，你按住 F **选对应的那件工具**才有效，**选错只是浪费时间**，而伤员在**持续倒计时死亡**；
- 可以**先把伤员拖到掩体后**再救（按住 F → carry / drag，`carryBody()`）；
- **职业不锁能力**：医护兵捡起工具箱能修坦克，机械兵捡起手术器械能救人——**只有班长的指挥能力是独占的**。

> 这套「诊断—匹配—计时」的医疗小游戏，是 ER2 把「救人」从按键变成决策的关键。而且它**天然制造队友依赖**：你救不了自己，只能等人来。

## 6. AI

**数量级：官方明确写了「up to 140 concurrent units」**（1.3.6，不含自定义任务里的强制生成，那可以更多）。这个数字是在「CPU 性能改善后」才提上去的，并且**开局前有一个滑条让玩家自选 AI 上限**，可以**按阵营分别设定**。这是我见过最诚实的做法：把「同屏人数」直接交给玩家的 CPU。

**行为层次（从 API 的 AiParams 反推，最可靠）：**

`allowCheckForEnemies`（搜敌）、`allowChangePose`（自动切姿态：站/蹲/趴/爬）、`allowFindCoverWhenSuppressed`（被压制找掩体）、`allowFollowOrders`（听令）、`allowGiveOrders`（自己当班长下令）、`allowMovements`、`allowOpenWindows`（会开门窗进屋）、`allowLeaveVehicle`、`allowDoMedic`（会去救人）、`allowRadioOrders`（会用电台）、`setTargetPlanesOften`（优先打飞机）。

**实际观察到的具体行为：**
- 会**寻掩体**并有**专门的掩体动画**；
- 被压制会**趴下**并保持较久；
- **突击班组会自己放烟幕掩护推进**；
- **你蹲远处狙太久，AI 会呼叫炮击轰你**（这条太狠了，值得抄）；
- **会散开**（1.3.6 专门修「Conga Lines」排队问题）；
- 会**近战/上刺刀**、**投弹**、**撤退**、**投降**、**救治伤员**、**修载具**；
- 蹲/爬会**降低被 AI 发现的概率**；未被发现的班组更难被发现；
- 狙击手 AI **精度更高**（「Sniper have higher accuracy when controlled by bots」）；
- **AI 也开飞机、开坦克、开轰炸机**（2.x 新增轰炸机 AI：飞过前线投弹→撤退→躲高炮→用自卫机枪打战斗机）。

## 7. 载具与重武器

- **坦克**：玩家可以开，有**装甲穿透与弹道模拟**，不同部位装甲值不同，要打弱点。座位制（驾驶/车长/炮手），**但作为「防挫败设计」，玩家控制坦克组时可以同时操作多个成员**——因为来回切驾驶和炮手太烦。炮弹类型：HE / AP / APHE + 车载机枪，**换弹要确认**。车长视角最好、可以**点击敌人打标记**。右下角有**罗盘同时显示炮塔朝向和车体朝向**。
- **火炮**：可以直瞄，也可以**接受无线员的坐标做间接射击**（上文那个「炮弹图标+数字对刻度」的操作）。
- **飞机**：玩家可以开，战斗机/俯冲轰炸机/攻击机都有，带炸弹、机枪、火箭、尾炮手。地图上有**白色飞机图标的补给点**，飞过去补弹药炸弹。落地滑跑加速即可起飞。
- **重武器/固定武器**：51 个条目的「Emplaced Weapons」分类——固定机枪、反坦克炮、海岸炮等，**可以被缴获使用**（「You can often capture enemy weapons such as tanks, cannons and machine guns」）。
- **反坦克**：巴祖卡/铁拳/PIAT/反坦克枪/集束手雷/反坦克地雷/炸药；坦克有**履带、发动机、油箱**分别的损伤（`damageTracks()` / `damageEngine()` / `damageFuelTank()`）。

## 8. 任务结构与节奏

- **战役 = 一组独立任务**，不是连续剧情。基础版 6 个战役 100+ 任务，DLC 再加 80+。单个战役规模例：蒙特卡西诺 **15 个任务**。
- **单局时长**：官方没给数字；玩家自述「一次玩 20–30 分钟」。结合 Phase 结构推断，**一局大约就是 15–30 分钟**。
- **失败条件**：Operation 模式下**进攻方票耗尽**即败；防守方**丢光所有 Phase**即败。
- **动态战线感来自三处**：(a) Phase 推进时敌方增援会到位；(b) **AI 会在你不在场时自己打下占领点**——评测特别提到这点；(c) Push the Frontline 的一维战线来回推拉。
- **有训练战役**教机制。
- 有**观战模式**和**照相模式**。

## 9. UI / HUD

ER2 的 HUD **少得惊人**，这是它的气质来源：

- **没有步兵弹药计数**（只有载具有）——评测把这条同时列为「沉浸感来源」和「偶尔恼人」。你得自己数、自己听、自己看动作。
- **准星、命中提示、装甲穿透提示**全是**可选开关**，默认关。
- **HUD 可以一键全关**（有专门的自定义按键）。
- **目标图标**：交叉刀剑 = 待打/可打，旗帜 = 已占领；出现在 HUD 和地图上。
- **小地图**：显示**班组成员位置**（1.3.6 加的）、被侦察到的敌人。**被侦察的敌方班组标记落在班组几何中心**，不再指向班长——即**你只知道「那边有一个班」，不知道具体是谁在哪**。
- **地图（M）**：自动生成，标出占领区、友军炮兵（蓝方块带圆）、飞机补给点（白飞机图标）。
- **左上角**显示当前班长是谁。
- **敌我识别靠自己**：游戏只提供**班组级标记**，个体士兵要靠制服认——德军和意军都是深色、伞兵盔和意军盔又像，**认错人是常态**，官方把这当特性。
- 各种**径向菜单**：TAB 指令轮盘、G 投掷物轮盘、R 换弹轮盘、I 快捷背包轮盘、X 换人轮盘。
- 炮兵专用：**弹着点图标 + 仰角数字**；坦克专用：**炮塔/车体双指针罗盘**。

## 10. 玩家称赞什么 / 批评什么

### 被称赞（该抄）

1. **规模与开放性**：大图、可绕侧、上百单位同场，一个人 5 欧的价格做出了战地的场面。
2. **零膨胀**：「zero bloat, battle passes or micro-transactions」——没有内购、没有等级解锁，纯玩法。
3. **历史细节的诚实**：不做阵营平衡，各国装备强弱按史实走（意军的 Breda 30 就是很烂）。
4. **不可预测的涌现故事**：评测把 AI 的优点归结为「unscripted adventures」——因为没剧本，所以每局都不一样。
5. **可破坏环境**：树、沙袋、铁丝网、建筑都能打掉，并且**影响视线**。
6. **难度可完全拆解成滑条**：AI 精度、爆炸半径、压制强度、玩家受伤、自动投降开关、体力时长、枪管过热、**弹道重力**……可存预设。这条让同一个游戏既能当模拟器也能当爽游。
7. **持续更新 + 官方编辑器 + 创意工坊 + 脚本 API**。

### 被批评（别抄）

1. **AI 不会守点**（最致命的一条）：AI 前往防御点途中遇到敌人就地停下对射，**根本不进点**。结果是「只要防守方在攻方赶路时看得见攻方，这张图就极其好打」。
2. **AI 城镇战很烂**：不会占楼、不会据守要点。
3. **AI 扎堆**（Conga Line，1.3.6 修过但没根治）。
4. **AI 目标选择反常识**：反坦克炮手旁边有坦克也去打远处步兵；坦克组在挨打时优先修车；AI 不理解「会被坦克碾死」这件事，会排队冲向坦克。
5. **单人重复感**：「main mechanic is capturing points one by one **in a single line**」——一条线推点推到腻。
6. **AI 隔着植被精准命中 / 超远距离发现你**。
7. **载具寻路差、键鼠开飞机几乎不能用**。
8. **UI 粗糙、胜负条件不清楚**（新手常常不知道自己为什么输了）。
9. **没有叙事没有角色**（对我们是双刃剑——台儿庄恰恰需要叙事）。

## 11. 移植到 three.js 版《血战台儿庄》的总体建议

**性能预算（1600×900 / 55fps / 程序化美术）下的取舍，我的判断：**

- **同屏单位目标 60–80，不要追 140**。ER2 是 Unity + C# 多线程 + 原生代码；浏览器单线程 JS 大概能吃 1/2。做法：**近处 8–12 个 SkinnedMesh 走真骨骼动画，中距离用 4–6 关节的简化骨架，远处直接 InstancedMesh + 顶点动画/公告板**。三档 LOD 按距离切。
- **AI 决策分帧**：把 AI 分成 6 组，每帧只跑一组的「感知+决策」，移动和动画每帧都跑。80 个 AI 实际每帧只做 13 次决策，完全吃得下。
- **地图规模建议 1.2km × 1.2km**，高度场 129×129 或 257×257，雾 + 远景卡片把可视距离压到 400–500m。台儿庄是**城镇巷战 + 运河 + 城墙**，天然适合用建筑体块分割视野，这比开阔地更省。
- **占领点 5–7 个，切成 3–4 个 Phase**，单局 15–20 分钟。
- **票数 = 兵力池，用「阵亡计数」而非「重生计数」**，并且**每过一个 Phase 按剩余票反向补给**（打得惨多补），做隐形橡皮筋。
- **压制系统必做，士气系统不要做**。一个 0..1 的 suppression 标量 + 投降触发就够了。
- **「阵亡换人 + 姓名生卒」必做**，这是成本最低、回报最高的一条。

具体每条的移植方案见 items。

## 12. 一句话总结

ER2 的启示不是「怎么做一个好 FPS」，而是：**当你没钱做画面时，就去做「世界在你缺席时仍然运转」这件事**。玩家的规模感、悲壮感、史诗感，全部来自于——他死了，仗还在打；他打下的点，会被别人丢掉；他救不活的人，会真的死掉；他呼叫的炮，会因为无线员中弹而永远打不出来。

这几条在 three.js 上都不贵。贵的是画面，而画面从来不是 ER2 赢的地方。

## 逐条移植清单

### [必做] 相位化占领点（Phase + Capture Zone）

**ER2 怎么做的**：任务切成若干 Phase，每个 Phase 含 1~N 个占领区。占领区是 {position, radius, progress 0..1, owner}，编辑器可单独设半径与占领耗时。HUD/地图上用交叉刀剑图标表示「待打/可打」、旗帜图标表示「已占领」；进度条由红转蓝。多点时防守方可反夺已失点。全部 Phase 打完＝进攻方胜。

**为什么重要**：这是 ER2 全部结构感的来源：它把一张开放大图切成有节奏的推进段落，既保证了「哪里都能走」的自由，又保证了「现在该干什么」的清晰。相比线性关卡，它用极小的数据量（几个圆 + 一个索引）造出了战役推进感；相比全开放，它避免了玩家迷失。

**我们怎么做**：objectives 数组存 {pos:Vector3, radius, captureTime, progress, owner}。每帧对每个区做一次 sphere 内单位统计（用空间哈希网格，不要 O(n²)），attackerCount>0 && defenderCount===0 时 progress += dt/captureTime，双方都有则冻结（或按人数差缓慢移动）。台儿庄建议 3~4 个 Phase、每 Phase 1~2 个点，总计 5~7 个点：西门 / 城墙缺口 / 清真寺 / 车站 / 运河渡口。图标用 CSS/Canvas 的 2D overlay 投影到屏幕，不要用 3D Sprite（省 draw call）。

### [必做] 兵力票池（Tickets）+ 阶段补给橡皮筋

**ER2 怎么做的**：进攻方持有票池，早期版本是「每投入一个班组/载具扣票」，官方后来改成「统计阵亡单位数」，并让票总量随所选 AI 数量缩放。防守方唯一的胜利方式就是耗光进攻方的票。每打赢一个 Phase 会补票，且 2.0.9 起「补给量会根据剩余票数微调」形成自动平衡。信息不对称：进攻方只在出生菜单看得到票，防守方必须站在占领区内才能看到敌方剩余票。

**为什么重要**：票池把「死亡」从个人挫败转成集体资源消耗，是「换人接着打」能成立的经济基础。阶段补给的橡皮筋是隐形难度调节——打得惨多补一点，玩家不会察觉却不会被劝退。信息不对称把侦察变成了真实收益，而不是白送的 UI。

**我们怎么做**：两个整数 attackerTickets / defenderTickets（台儿庄建议日军 180、中国守军 150 起）。每有单位阵亡扣 1。Phase 通过时 tickets += base + (maxTickets - tickets) * 0.25（橡皮筋）。票归零＝败。信息不对称照抄：玩家在占领区内时才显示敌方票数，做成一个「侦察到的情报」文本。

### [必做] 阵亡换人 + 姓名生卒年月

**ER2 怎么做的**：每次阵亡，屏幕显示刚才操控士兵的姓名与生卒年月，然后玩家接管另一名士兵继续战斗。死者背包里有狗牌可查身份（甚至有收集狗牌的成就）。重生要在暂停菜单手动执行、逐个成员操作，消耗票，重生后有数秒无敌。此外按住 X 可随时在班组成员间切换（不必等死）。班长阵亡后指挥权按 班长→无线员→机枪手→狙击手→步枪兵 顺位自动移交。

**为什么重要**：ER2 最核心的一招。它把玩家从「主角」降级成「一个兵」，死亡不是失败而是换视角；战场规模感来自「你死了但仗还在打」——重生后发现刚才那个点已经被 AI 拿下或丢掉，世界瞬间就活了。这是用最低成本制造史诗感的办法：不需要更多多边形，只需要让世界在你缺席时继续演进。对台儿庄尤其契合——「一个班打光换一个班上」的历史质感与这个机制同构。

**我们怎么做**：维护一个 soldiers 池，每个士兵带 {姓名, 籍贯, 生年, 部队番号}，用姓氏表×名字表×省份表程序化生成（几 KB 数据出上万个名字）。死亡时全屏黑底白字 2.5 秒：「张德山 · 山东临沂 · 1915—1938 · 第三十一师九三旅」，然后相机平滑飞到新士兵。切换用 X 键径向菜单。这条几乎零性能成本、情绪回报最高，优先级最高。

### [必做] 班组命令轮盘（按住 TAB）

**ER2 怎么做的**：只有班长身份可用。完整指令：Follow（默认跟随）、Move and Hold（前往并固守）、Attack Objective from Direction（先绕到目标外围某方向集结再进攻＝侧翼包抄）、Line/Column Formation（横队/纵队）、Charge（全速冲锋，全员自动上刺刀）、Covert Movements（扣火潜行，AI 模仿班长姿态）、Cover Area（区域防御）、Retreat、Tank Support、Artillery Smoke/HE/APHE、Spot（敌人打标记，限时）。

**为什么重要**：命令系统是把「一个兵」升级成「一支部队」的杠杆，也是 ER2 让玩家产生指挥官代入感的唯一手段。特别是 Attack from Direction——它把「侧翼包抄」这个战术概念做成了一个可点击的指令，玩家不需要懂战术就能执行战术。Charge 附带自动上刺刀则是把指令和动作表演绑定，极具戏剧性。

**我们怎么做**：按住 Tab 弹出 8 分区径向菜单（纯 DOM/Canvas 2D，零 3D 成本）。台儿庄版建议精简到 6 条：跟随 / 前进占领 / 固守此处 / 侧翼迂回 / 白刃冲锋（自动上刺刀+喊杀声）/ 隐蔽前进。落点用射线拾取地形。AI 侧只需要一个 squadOrder 状态机 + 目标点，别做复杂编队求解——沿路径散开 8~12m 即可。白刃冲锋对台儿庄是文化上的必做项。

### [必做] 支援链路：可断的无线员，而非冷却读秒

**ER2 怎么做的**：呼叫炮击需要三个条件同时满足：(1) 班组有活着的无线员（背上有可见电台模型）；(2) 地图上有可用的己方火炮（HUD 显示为蓝方块带圆）；(3) 坐标输入正确。班长在轮盘选炮击类型+落点，无线员按 TAB 打开电台做一个「点对高亮数字」的小游戏，点错就偏靶。2.0 后无线员可自行呼叫、有专用迷你地图指定落点、可选弹种、可取消炮击（说明存在呼叫→落弹延迟窗口）。班长可捡起电台自己背，从而自呼自确认。官方从未公布冷却或次数上限——限制来自资源链而非冷却条。

**为什么重要**：这是 ER2 最有仪式感的系统，也是我最想让台儿庄抄的一条。用「链路可断」代替「冷却读秒」，戏剧性高一个数量级：无线员中弹倒下的那一刻，你全班永远失去了炮火支援——这比屏幕上转一圈的冷却图标有力一百倍。它还天然制造了保护特定队友的动机，把 AI 队友从背景板变成资产。

**我们怎么做**：squad.radioman 引用一个具体士兵，死了置 null。呼叫流程：轮盘选点 → 若 radioman 存在则进入 3 秒「呼叫中」（可被打断）→ 8~12 秒飞行延迟 → 落弹。数字小游戏建议简化为「按住不动 3 秒完成校射」，鼠标晃动越大落点偏差越大（保留手感但不打断节奏）。台儿庄的支援清单：迫击炮弹幕 / 烟幕 / 集束手榴弹补给。炮击特效用 InstancedMesh 粒子 + 屏幕震动 + 低频音，不要做实时爆破网格。

### [必做] 压制系统（suppression）—— 并且不要做士气条

**ER2 怎么做的**：API 有 getSuppressionValue() 返回连续量、isSuppressed() 返回布尔。表现：屏幕暗角特效、准星晃动加剧（官方称 suppression sway）、AI 长时间趴下、AI 有专门的压制反应掩体动画、AiParams 里 allowFindCoverWhenSuppressed 是独立可开关的行为。压制强度是难度滑条之一，简单难度玩家完全免疫压制。关键发现：整套 API 和 450KB 官方日志里 morale/士气 出现 0 次——ER2 根本没有士气系统。

**为什么重要**：这是本次拆解最反直觉也最有价值的发现：ER2 用「一个连续标量（压制）+ 一个离散事件（投降）」完全替代了别的游戏需要整套士气系统才能做出的效果。少一套数值意味着少一套要调平衡的东西、少一套要向玩家解释的 UI。压制同时解决了三件事：让子弹在没打中时也有意义、让 AI 的卧倒行为有动机、让玩家理解「火力压制」这个真实战术概念。

**我们怎么做**：每个单位一个 suppression:0..1。附近（<3m）有子弹飞过 +0.25，爆炸 <8m +0.5，每秒自然衰减 0.3。玩家侧：suppression>0.3 起加屏幕暗角（后处理或纯 CSS 渐变遮罩，零成本）+ 瞄准晃动振幅按 suppression 线性放大 + 低通滤波的耳鸣音。AI 侧：>0.5 触发卧倒/找掩体，>0.8 触发投降判定。坚决不要再加第二套士气数值。

### [应做] 投降与俘虏（用事件替代士气条）

**ER2 怎么做的**：投降的触发条件是一组离散事件而非数值阈值：被重度压制、自己所在的占领点刚被对方拿下、进攻方票池耗尽（附近敌军直接扔枪）。也有单位选择死战到底或撤退再战。玩家自己在写实难度下也会被强制自动投降（简单/普通难度已取消，且难度设置里有开关）。己方投降士兵可按 F「解放」，他们会掏出手枪继续作战；给受伤的敌人做医疗会让他投降＝俘虏。

**为什么重要**：投降把「击败」从「杀光」变成了「瓦解」，这是战争片质感的关键——真实战斗里大部分伤亡来自崩溃而非精确射击。它还提供了三个额外价值：占领点被拿下时的连锁投降给了玩家即时正反馈；解放战俘让你重新获得兵力（票的另一种来源）；玩家自己会投降则让失败有了叙事而非一个 Game Over 屏。

**我们怎么做**：三个触发器即可：suppression>0.8 且 5 秒内无友军在 20m 内 → 投降；所在占领区易主 → 区内劣势方 40% 概率投降；票池归零 → 全场该方 70% 投降。投降动画只要一个举手 pose + 丢枪。台儿庄语境要慎重处理：中国守军应设计成极低投降率（史实上台儿庄是死守），日军投降率也应偏低但非零——这个不对称本身就是叙事。解放战俘＝回补 1 票。

### [应做] 两层伤害模型：轻伤自救 + 重伤失能诊断

**ER2 怎么做的**：轻伤层：中弹后屏幕变黑白/灰、不能跑、不能屏息；按 B 直接用绷带（不必开背包，载具内也能用）；不处理会流血致死；消耗品分级（罐头回 ~40%、药片回 ~90%）。重伤层：被打到倒地失能后才能被救；医护兵有注射器/剪刀/医用镊子三种器械，伤员头顶浮出一个器械图标，必须选对应工具才有效，选错只是浪费时间而伤员在持续倒计时死亡；可先把伤员拖到掩体后再救。职业不锁能力——医护兵捡工具箱能修坦克，机械兵捡器械能救人，只有班长的指挥能力独占。

**为什么重要**：两层结构解决了「受伤要么没感觉要么直接死」的老问题：轻伤给持续压力（不能跑＝被迫改变战术），重伤给社交依赖（你救不了自己，只能等人来）。诊断小游戏把救人从按键变成决策，并且计时器让掩体位置成为真问题——先拖再救是一个真实且好玩的战术选择。职业不锁能力则避免了「医护兵死了全队完蛋」的脆弱设计。

**我们怎么做**：玩家状态机：Healthy → Wounded(不能冲刺、屏幕去饱和、每秒掉血) → Downed(倒地，30 秒倒计时) → Dead。B 键包扎 3 秒（期间不能开火）。医疗诊断简化为两种工具（止血钳 / 注射器）对两种伤型，头顶显示图标。屏幕去饱和用一个 uniform 控制的全屏 shader（几乎零成本）。拖拽伤员对台儿庄叙事价值很高——「把伤员拖回城墙后」是很强的画面。

### [应做] 无准星的写实瞄准：视差 + 晃动 + 屏息 + 归零

**ER2 怎么做的**：准星/命中提示/装甲穿透提示全部是可选开关，默认关闭，简单难度才自带准星并免疫压制。ER2 没有 free aim（武器 deadzone）——它的「难瞄」来自四件事：(1) 铁瞄故意不在屏幕正中，开发者亲自回帖确认这是设计而非 bug，且必须等 ADS 动画播完再开枪；(2) 瞄具与枪管不共轴的视差，近距离必须心里修正（准星的真正作用是补偿视差而非辅助瞄准）；(3) 武器晃动 sway，写实难度「intense weapon sway is back」；(4) 压制加剧晃动。屏息＝ADS 时按住 Shift，减晃 + 轻微放大，时长随难度变。Page Up/Down 调表尺归零，说明弹道下坠真实存在，难度里能直接调 bullet gravity。机枪不架两脚架不能开镜（MG42/Browning/反坦克枪等）。

**为什么重要**：这套组合让「打中」变成一件需要付出的事，而付出的方式是有层次的：找掩体（减晃）、屏息（减晃但耗体力）、架枪（大幅减晃但失去机动）、估距归零（认知投入）。它没有用「随机散布」这种廉价手段，全部是玩家可控可学的确定性变量——这是写实射击手感的正确做法。

**我们怎么做**：three.js 侧：相机基础 FOV 70，ADS 时 lerp 到 35（栓动）/45（步枪）。晃动＝两条不同频率的柏林噪声叠加驱动武器 group 的旋转（振幅 = base * (1 + suppression*2) * (1 - holdBreath*0.7) * (1 + stamina耗尽*1.5)）。子弹用射线步进 + 重力积分（每步 0.02s，g=9.8，初速 700m/s），台儿庄距离多在 50~200m，下坠可感知但不夸张。刺刀/近战必做。默认关准星，设置里给一个开关照顾新手。

### [必做] AI 行为层次（掩体/卧倒/放烟/绕侧/呼炮）

**ER2 怎么做的**：AiParams 暴露的可开关行为：搜敌、自动切姿态（站蹲趴爬）、被压制找掩体、听令、自行下令、移动、开门窗进屋、下车、施救、用电台、优先打飞机。实际观察到：会寻掩体且有专门掩体动画；被压制会趴下且保持较久；突击班组会自己放烟幕掩护推进；你在远处狙太久 AI 会呼叫炮击轰你；会散开（1.3.6 专门修 Conga Line）；会近战/上刺刀/投弹/撤退/投降/救人/修车；蹲爬降低被发现概率；狙击手 AI 精度更高。

**为什么重要**：AI 的行为层次决定了战场看起来是不是「活的」。ER2 里最有价值的两条是「AI 会放烟掩护推进」和「AI 会对长时间蹲点的玩家呼叫炮击」——前者让 AI 的进攻有战术形状而非直线冲锋，后者直接惩罚了最无聊的玩法（远距离蹲狙），是一个用 AI 行为做关卡设计的漂亮案例。

**我们怎么做**：每个 AI 一个小型行为树/状态机：Idle → Advance(沿路径向目标点，遇火力则) → SeekCover(在半径 15m 内找预标记的掩体点) → Suppressed(卧倒) → Flank(概率触发，绕行 30~60 度) → Assault → Retreat/Surrender。掩体点在关卡烘焙时预标记（每个建筑角、墙、弹坑放一个 coverPoint，带朝向），运行时只做最近查询——不要运行时算遮挡。「AI 呼炮惩罚蹲点」这条必抄：玩家在同一位置开火超过 45 秒且累计击杀 >3，触发一次敌方迫击炮覆盖。

### [应做] 隐蔽机动 + 可见度模型（Covert Movement）

**ER2 怎么做的**：1.3.6 新增的班组指令：全员扣火潜行接近，直到玩家下达 Fire at Will 或敌方察觉（敌人朝你开火、班里有人开枪、班组进入吵闹的载具）。与之配套的侦察系统调整：敌方「未察觉你存在」时，你的班组更难被发现；蹲下或匍匐进一步降低可见度；潜行期间 AI 会模仿班长的姿态——班长趴下全班就趴下，由班长决定潜行程度。

**为什么重要**：这是一条极低成本、极高战术密度的机制。它用一个布尔（是否被察觉）× 一个姿态系数，造出了完整的潜行层，并且「AI 模仿班长姿态」这个细节把指挥感做到了身体层面——你不用下指令，你趴下他们就趴下，这是非语言的指挥。对夜战和渗透场景价值极高。

**我们怎么做**：每个班组一个 awareness 布尔 + 每个单位一个 visibility 系数（站 1.0 / 蹲 0.6 / 趴 0.3，再乘草丛遮蔽 0.5）。敌方 AI 的发现判定 = 距离衰减 × visibility × (awareness ? 2.0 : 1.0)。姿态传染只要一行：AI 每帧把自己的目标 pose 设为班长的 pose。台儿庄非常适合做一个「夜袭日军炮兵阵地」的潜行任务段落——运河、芦苇、断墙都是天然遮蔽物，且成本比白天巷战低（夜间可大幅削减绘制距离）。

### [应做] 极简 HUD（尤其是：步兵不显示弹药数）

**ER2 怎么做的**：ER2 的 HUD 少得惊人：步兵武器没有弹药计数（只有载具有），要靠自己数、听、看动作；准星/命中提示/穿透提示全是可选开关且默认关；HUD 可一键全关。保留的元素：目标图标（交叉刀剑=待打，旗帜=已占领）、小地图（显示班组成员位置、被侦察到的敌人，且敌方班组标记落在班组几何中心而非班长）、按 M 打开的自动生成地图（标占领区、友军炮兵蓝方块带圆、飞机补给白图标）、左上角当前班长是谁、炮兵的弹着点图标+仰角数字、坦克的炮塔/车体双指针罗盘。敌我识别只提供班组级标记，个体士兵要靠制服认。

**为什么重要**：「没有弹药计数」是 ER2 沉浸感的关键单点——它逼你进入角色的信息状态而不是系统的信息状态。「敌方班组标记落在几何中心」同样精妙：你知道那边有一个班，但不知道具体谁在哪，情报是模糊的而不是透视挂。这两条都是用减法制造张力，对我们这种画面预算有限的项目是天赐的——省下的 UI 开发量还能反过来加分。

**我们怎么做**：HUD 全部用 DOM/CSS 层，不进 three.js 渲染（省 draw call 也好调试）。保留：占领点图标（屏幕空间投影）、小地图（Canvas 2D 每 200ms 重绘一次即可，不必每帧）、班长指示、压制暗角、包扎提示。去掉：弹药数（改为「按 R 时角色喊出剩余弹匣数」的语音提示，更沉浸也更省 UI）、击杀提示、准星（默认）。敌方标记只画班组级圆圈，不画个体。

### [必做] AI 数量滑条 + 分帧决策

**ER2 怎么做的**：官方明确写「up to 140 concurrent units」（不含自定义任务的强制生成）。这个数字是在 CPU 优化后才提上去的，并且开局前有一个滑条让玩家自选 AI 上限，可以按阵营分别设定，同时票数也随 AI 数量缩放。

**为什么重要**：把「同屏人数」直接交给玩家的硬件，是这类项目最诚实也最实用的做法。对 web 版尤其重要——浏览器性能差异巨大，与其自己猜一个保守数字，不如给一个滑条让高配玩家吃到规模感、低配玩家还能跑。而且它把性能问题从「技术缺陷」转化成了「玩法选项」。

**我们怎么做**：设置里给「战场规模」三档：小（40 单位）/ 中（70）/ 大（110，标注『需要较好的设备』），默认中。首帧后跑一个 3 秒的性能探针自动推荐档位。实现要点：AI 分 6 组轮流跑感知+决策（每帧只跑 1/6），移动与动画每帧全跑；渲染三档 LOD（近 12 个 SkinnedMesh / 中 简化骨架 / 远 InstancedMesh 公告板）；空间哈希网格做邻近查询。票数跟着规模档位线性缩放，保持局长不变。

### [应做] Push the Frontline：一维战线来回推拉

**ER2 怎么做的**：第二种模式：从中间 Phase 开局，双方互为进攻方。赢下一个 Phase 就把对方推后一格；把对方推到其最后一个 Phase 即胜，或在（总 Phase 数 × 2）局后由赢得更多 Phase 的一方获胜。这个模式没有票。

**为什么重要**：这是「动态战线」的最小可行实现——不需要真的模拟战线曲线或领土占领，只要一个一维的 Phase 索引来回移动，玩家就能强烈感受到战线在推拉。ER2 用一个整数做出了别人用整套战略层才做出的体验，这个技巧对 web 版是决定性的省钱办法。

**我们怎么做**：一个 frontlineIndex 整数 + 一个 Phase 数组。台儿庄的历史叙事本身就是拉锯战（日军突入城内、中国军队巷战反击、反复易手），一维推拉与史实高度吻合。建议做成「台儿庄拉锯」模式：5 个 Phase（西门→北门→清真寺→车站→运河），开局在清真寺，来回争夺。切换 Phase 时不重载场景，只移动双方出生点和激活的占领区——这对 web 尤其关键，避免任何加载中断。

### [应做] 可破坏植被/掩体与视线遮蔽

**ER2 怎么做的**：树、沙袋、铁丝网、建筑都能被打掉（「Forests are leveled, defenses torn apart, and buildings are reduced to rubble」）。关键是官方反复优化的「vision-blocking system of many vegetation assets」——植被是真的挡 AI 视线的，并且打掉之后就不挡了。后来还整体重做了破坏系统「to have much better performance online and to allow more complex destructibility」。

**为什么重要**：破坏之所以重要，不是因为看着爽，而是因为它改变了视线拓扑——打掉一片灌木＝开辟一条射界，炸塌一段墙＝制造一个突破口。这让火力有了地形之外的战术意义。同时「植被挡 AI 视线」是 ER2 让潜行和迂回成立的底层保证；如果 AI 能透视草丛（这恰恰是玩家批评它的一点），整个隐蔽系统就废了。

**我们怎么做**：不要做真实网格破碎。做法：每个可破坏物是一个带 hp 的实例，被摧毁时切换到「残骸」变体（预制的低模碎堆）+ 一次粒子爆发。视线遮蔽用一张低分辨率的 2D 遮蔽网格（比如 256×256 覆盖全图，每格存 0..1 遮蔽度），AI 的视线判定沿网格步进采样，物体被摧毁时更新对应格子——这比逐物体射线便宜两个数量级。台儿庄的土墙、门板、粮垛、芦苇荡都适合做成可破坏遮蔽物。

### [可选] 难度＝一组滑条，而不是三个档位

**ER2 怎么做的**：玩家可完全自定义：AI 精度、爆炸半径、压制强度、玩家受伤倍率、关闭玩家自动投降、体力时长、枪管过热值、弹道重力等，且可存成难度预设。简单难度自带准星、免疫压制、去掉压制暗角、并给被侦察到的敌人加显眼指示器帮新手识别。

**为什么重要**：开发者的原话逻辑是：与其为了迎合休闲玩家把游戏做浅，不如把写实程度参数化，让同一套系统既能当模拟器也能当爽游。这对我们这种要面向不特定 web 访客的项目价值极高——一个通过链接点进来的路人和一个军事迷需要的完全是两个游戏，而滑条让你不必二选一。

**我们怎么做**：一个 difficulty 对象（{aiAccuracy, suppressionScale, playerDamageScale, bulletGravity, autoSurrender, showCrosshair, enemyMarkers}）在所有系统里被读取，不要把难度硬编码进各处逻辑。首次进入给三个预设按钮（体验 / 标准 / 写实），高级选项里展开滑条。台儿庄面向 web 的默认档应该偏「体验」——路人进来 30 秒内要打中人，不然就关掉了。

### [必做] 别抄：AI 不会守点、扎堆、单线推点的重复感

**ER2 怎么做的**：ER2 被批评最狠的几条：AI 前往防御点途中遇敌就地停下对射、根本不进点，导致「只要防守方在攻方赶路时看得见攻方，这张图就极其好打」；AI 城镇战很烂，不会占楼据守；AI 扎堆排队（Conga Line，1.3.6 修过但没根治）；AI 目标选择反常识（反坦克炮手放着旁边的坦克去打远处步兵、坦克组挨打时优先修车、不理解会被坦克碾死）；单人玩法「一条线一个点一个点推」产生重复感；AI 隔着植被精准命中、超远距离发现玩家；载具寻路差、键鼠开飞机几乎不能用；UI 粗糙、胜负条件不清楚导致新手不知道自己为什么输了。

**为什么重要**：这些是 ER2 用了五年也没完全修好的结构性问题，逐条对应到我们的设计上都是可以在第一天就避开的坑。尤其「AI 不会守点」这一条直接摧毁了防守方的可信度，让所有进攻关卡变得平庸；而「单线推点」则是 Phase 结构用得太保守的后果——ER2 有多点分支的能力却很少用。

**我们怎么做**：逐条对策：(1) AI 守点必须写成硬性优先级——占领区内的防守单位除非死亡否则不得离开区域半径，交战只允许在区内换位；(2) 出生时给同班组成员分配不同的横向偏移，且路径跟随加 8~12m 随机侧向抖动，杜绝排队；(3) AI 命中判定必须走同一套遮蔽网格，不给 AI 开透视；(4) 距离 >150m 的 AI 精度按平方衰减并加一个「先打近的」硬规则；(5) 每个 Phase 至少给两条可选进攻路线（例：车站可从铁道正面或从粮栈侧翼），破除单线感；(6) 胜负条件必须每时每刻在 HUD 上可读——一行字「守住车站，剩余兵力 87」，绝不让玩家输了还不知道为什么。

## 查不到 / 靠推断的部分（不要当史实用）

- 地图的具体物理尺寸（km 或 km²）官方从未公布，我在商店页、全部 165 篇更新日志、官方 wiki 和地图编辑器文档里都没找到数字。只能确认：编辑器高度图接受任意尺寸的正方形图片并按 mapsize 归一化，且存在「Big maps only」才开放的草密度选项（说明有大小档位），以及玩家攻略明确说「地图总是非常大、绕侧是可行的」。我给台儿庄建议的 1.2km×1.2km 是基于 web 性能预算的独立推算，不是 ER2 的实际数值。
- 占领区的「驻守人数」规则没有查到明文。我没有找到「N 人加速占领」或「需要至少 X 人才开始计时」这类规则的官方说明。可以确认的只有：编辑器能设置半径和占领所需时间、进度是 0..1 的连续量、多点时防守方可反夺。「双方都在区内则冻结」是我根据进度条描述和常见做法的推断，未经证实。
- 支援呼叫的冷却时间与每局次数上限没有任何官方数值。可以确认的是限制机制是资源链（无线员存活 + 地图上有可用火炮 + 坐标输入正确）而非冷却条，并且存在「呼叫→落弹」的延迟窗口（因为有 cancel artillery 功能），但延迟多少秒、能不能连续呼叫、一局最多几次，全都查不到。我给的 3 秒呼叫 + 8~12 秒飞行是凭常识给的建议值。
- 「free aim / 武器 deadzone」这一条我给的是否定结论，但属于「查不到证据」而非「查到明确否认」。我在全部官方日志、wiki 和社区攻略里都没有出现 free aim / deadzone / 武器惯性 这类表述，且开发者讨论瞄准问题时只谈铁瞄偏心和视差，所以我判断 ER2 没有 RO2/HLL 式的自由瞄准。但不排除存在某种未被文档化的武器惯性。
- 弹道的具体参数（初速、重力常数、归零档位的具体距离刻度）没有公开。只能确认「Page Up/Down 调表尺」和「难度设置里可调 bullet gravity」这两条，据此推断下坠是真实模拟的。提前量机制我没有找到任何直接描述，是从「有重力和飞行时间」推断的。
- 单局时长没有官方数字。「15~30 分钟」是我从玩家自述的「一次玩 20~30 分钟」加上 Phase 结构推断的，不是权威数据。
- 「同屏 140 单位」是 1.3.6（2024 年前后）公布的上限，之后又有多轮性能优化和「Max AI count increased by a lot」的表述，当前 2.x 版本的实际上限可能更高，我没有找到更新的官方数字。
- 医疗诊断的三种器械（注射器/剪刀/医用镊子）与伤型的具体对应关系、以及倒地后的存活倒计时秒数，官方 wiki 只写了「必须匹配头顶图标、选错浪费时间」，没有给出伤型分类和时长。我给的「30 秒倒计时、简化为两种工具」是移植建议，不是 ER2 的实际数值。
- 压制值的具体累积与衰减速率、触发卧倒/投降的阈值，官方完全没有公开（只知道 API 有 getSuppressionValue 返回一个值）。我在 items 里给的 +0.25 / +0.5 / 每秒 -0.3 以及 0.3/0.5/0.8 三档阈值全部是我为 three.js 版设计的起始值，需要实测调参。
- Steam 官方新闻页的正文用 WebFetch 抓不下来（只返回导航壳），我改用 Steam News API 抓到了全部 165 篇的正文，所以更新日志部分的引用是可靠的。但 TV Tropes 和部分评测站返回 403，TV Tropes 是我用带 User-Agent 的 curl 抓下来的，purexbox 那篇始终没抓到，因此该篇评测的观点没有被纳入。
- Fandom wiki（easy-red.fandom.com）返回 HTTP 402，完全没读到，所以本文没有采用 Fandom 的任何内容。
- Reddit r/EasyRed2 的内容我没有直接抓到（搜索结果里没有返回可用的 reddit 链接），玩家褒贬部分主要来自 Steam 社区讨论、TV Tropes 的 Artificial Stupidity/Artificial Brilliance 词条、以及两篇评测。这三个来源的批评高度一致（AI 不会守点、扎堆、单线推点），所以我对结论有信心，但缺少 Reddit 侧的交叉验证。
