## 四个动词，全部长在 E 上（2026-08-16 用户定，照《勇敢的心：世界大战》）

全作只有四个输入，Notion《序 · 那天》第九稿与各章「关卡设计」子页是口径：

| 输入 | 意思 | 代码 |
|---|---|---|
| **E** | 瞬时：拾、说、递、点火 | `type:"use"`（不带 hold） |
| **长按 E** | 保持一个状态（搂紧／托稳／按住），松手就塌 | `hold` + `steady:true`，或 hold 拍的 `sustain:true` |
| **E ＋ ←/→** | 横着做功：推、掰、拨、撕、缠 | `stroke:"left"/"right"` |
| **E ＋ ↑/↓** | 竖着做功：抱起／放下、掀、刨、舀、缝、摇辘轳 | `stroke:"up"/"down"` |

- **光按住 E 不算做功**（`StrokeWork`）：方向不对不涨。键盘读 `input.climb`／`input.moveX`，
  手机走摇杆＋互动钮，**同一条路**。绕圈（`circle`）那一档留着光按住 E 的后备——它没有方向可言。
- **按住 E 的那一帧，方向键归做功，不归走路、也不当爬梯**（MovePlayer 顶上的 `WORK_ACTIONS`）——不锁的话，掀翻板按 E＋↑ 人就顺着梯子爬上去，
  掰红薯干按 E＋← 一下就走出判定区。判据与自动通关驱动器用的是**同一个**（`GetBeatTarget` 报的 action ＋ 走进它的 reach）。
- **键位只写在提示的前缀里，不进正文**（`StrokePrompt` 统一改写，`SplitPrompt` 认「按住 E ＋ ↑ · 掀开草苫」）；
  HUD 把它翻成**两枚键帽**（`#actPrompt .pKeys`：E 加一个方向，涟漪与进度环只长在 E 那枚上）。
  数据里 prompt 只写动词最省心——写了旧前缀也会被 StrokePrompt 换成这一步真正要的那一半。
- **拟物那几套玩法直接读方向键**：每一拍一个 `HeldDir(input, dir)`，分量留在时间里：
  | 拍 | 输入 | 分量／答话 |
  |---|---|---|
  | 掀苇席（`heaveMat`） | 按住 E＋↑ | 角速度上限 `FORAGE.*.lift`，撒手坠回，过重心自己翻 |
  | 扫槽底／刨灰堆（`scoopAsh`） | 按住 E＋↓ 一把一把 | `strokeS[]` 浮灰快硬土慢；第三把 `catchAt` 处**钉住**（闷响＋灰，不上屏一个字），键帽当场换成 E＋↔ |
  | 顺着坛肩抹（同上，`caught` 后） | 按住 E＋↔ 三把 | 抹哪儿露哪儿（`clear`），三把出坛 |
  | 抠泥封＋揭碗片（`unwrapJar`） | 按住 E＋↑ 一路到底 | `unwindS` 三箍一段一段掉（`WrapEdgeAngle` 给指头角度）；同键继续 `peelS` 揭碗片，松手压回 |
  | 掰红薯干（`split`） | 按住 E＋↔（`bendS`）→ E → E | 从你使劲那头断开一长一短；「分进两只碗」「放回她碗里」各是**一按 ＋ 卡上动画**（`sortS`／`swapS`：长的给她、捞出来沥两滴再搁回） |
  | 撕布（`tear`） | 按住 E＋← 三把 | 第一把绷紧弹回、第二把裂口、第三把撕到头；前两把 `recoilS` 缓一口 |
  | 划线（`scribe`） | 按住 E＋→ 三趟 | `passPress` 一趟比一趟深，一趟到头笔抬起来退回（`liftS`） |
  | **缝三针（`sew`）** | **保留原样**（用户点名） | 仍走 `VirtualHand`＋`pointerCard`，`sewAt` 驱动路照旧 |
  提示一律 `StrokePrompt(动词, dir)`（`horiz`＝「↔」，`PROMPT_DIRS`／Main 的 `DIR_KEY`/`DIR_GLYPH` 都认），
  活卡那几拍键帽钉在卡的下沿正中（`SyncActPrompt` 见 `LiveCardOn`）。
  **活卡铺着的那几拍方向键全归卡、脚不走**（MovePlayer 的 `LiveCardOn` 锁）——不锁人就走出判定区、卡从眼前消失。
  触屏摇杆在活卡拍**不收走**（互动钮＋摇杆就是这几拍的全部输入）。
- **新加做功步骤，自动通关驱动器要跟着按方向**（`GetBeatTarget` 报 `holdAt` ＋ `stroke`，一按的报 `interactAt`），
  漏了驱动器会站在原地按一辈子 E。各拍报的 `x` 是**站位**不是物件中心——站位压在"够得着"的边上会一帧内一帧外来回颤，手一松一把作废。
  守着它的：`TestForageIsFourVerbs`／`TestChalkIsThreePasses`／`TestTearIsThreePulls`／`TestSplitIsBreakThenTwoPresses`。

第九稿下线的玩法（机制留在 Core 里没人用，别顺手删）：**修井绳／接绳活卡**（`case "knot"`，`TestKnotIsASheetBend` 已停用）、
**辘轳的墩桶与拽到井沿**（`winch` 步骤写 `simple: true` 就只剩放桶／摇上来两道手）。

## 拟物交互（全作标准，2026-08-07 用户定的）

**凡是"对物体做功"的交互，玩家必须直接操纵那个被动物体本身**——拖它、推它、绕它、按它。
进度条与"长按 E 等它走完"**禁止作为主路径**。

已立住的范式（新动词先对号入座，不够再添，添了写回这张表）。**输入一律先过上一节「四个动词」那张表**：
下表里写着 `pointerWorld`／`pointerCard` 的那几行（掀苫草、拖门板、扒烧土、解扎口、石笔、掰红薯干、撕布）
如今全由「按住 E ＋ 方向」驱动，指针那条路只剩缝三针（用户点名保留）和没人用的接绳／叠衣裳／刨子还认；
这张表留着的是**分量与答话**的判据（有重量、撒手坠回、一把一把、钉住换方向），不是输入通道。

| 交互形态 | 输入 | 范例 |
|---|---|---|
| 攥住拖（工具在指尖） | `input.pointerWorld` 抓住实物 | 辘轳把手、**拖门板**（横拖有摩擦，中途卡在焦椽茬上——得往回让一寸才让得过去） |
| 在特写卡上攥住拖 | `input.pointerCard` 抓住卡上的实物 | 石笔（有摩擦、抓不稳会脱手）、**刨子**（有分量、停半道刨花断、抬手脱柄、到头抬起来回程）、**接绳**（照着**单编结**真挽一遍：穿进弯口→从两股中间钻上来→绕到两股背后→从底下兜回来→从自己那股底下掖出去，最后一把勒到底）、**叠衣裳**（拈住一个角拖到落点；布有分量、撒手塌回去、甩快了整幅弹回原处；折痕自己落在原边与落点的正中）、**解扎口**（逆着缠的方向把绳一道道褪下来，再捏住油布角掀开） |
| 绕着一个铰链掀起来（有重量） | `pointerWorld` 攥住外沿，角度跟着手走 | **掀苫草**（焦草苫子有分量、撒手自己坠回去、手甩得比它快就撕掉一口） |
| 一把一把地扒 | `pointerWorld` 落在那堆东西上，一把够长够斜才算一下 | **扒烧土**（浮灰滑、硬土拖不快、第三把拽到半道**手钉住**——指甲碰上坛肩，一个字不上屏；出路是换方向**顺着坛肩横着抹**，抹哪儿露哪儿。这一把是什么不看按在哪儿，看手往哪儿走；埋着的坛子由 DrawAshMound 画，pickup 步骤声明 `worldDrawn` 不许预摆地面道具剧透） |
| 绕圈（轴） | `pointerWorld` 绕轴心累计转角 | 辘轳（顺放逆收、脱手倒转、**手劲会耗尽**） |
| 笔画做功（一下一下干） | `StrokeWork`：down/up/circle | 挖土、按棉被、顶撑木、拴铃、装引信、撬地沿 |
| 顶住/扶稳（对抗一个持续的力） | `pointerWorld` 攥住实物，稳在容差内才涨 | **扶门扇**（下轴脱窝、整扇自己往外坠；撒手就坠回去、进度往回泄） |
| 竖拽 | `input.pull/pullHeld` | 竖向一把一把拽的活 |
| 攥住绳猛拽一把（一下一下，不是一直） | `pointerWorld` 落在绳的窄走廊里，一把够长够竖才算一下 | **墩桶**（空木桶浮在水面上不吃水，得一下下墩过去；手飘出绳外＝脱手，划得横＝那是绕圈不是墩） |
| 拽弓投掷（攥住手里的石子往后拽开） | `pointerWorld` 攥住 + 松手反向出手 | **石子**（拽的方向定角度、长短定劲；真弹道重力积分，预览弧=同一套物理跑出来的点列；蓄力姿势 throwWind 由拉弓量驱动。**没有键盘后备**，F 键与触屏投掷钮已整个撤掉） |
| 点按 | `input.tap` | 瞬时动作 |
| 拖着一件有物理的东西走 | 走位本身驱动，物体自己解算 | **拉绳定向**（麻绳 verlet 质点链：一路拖在土上，最后两米离地绷直，放到头绳把人拽住） |

规则：

0. **进度条/QTE 轨道禁止出现**。判据：玩家操纵的是**画面里那个东西**，还是一个抽象的量？
   位移驱动（`dragX`）也不够——那只是"拖屏幕"，手并没有落在工具上。四条缺一不可：
   ①按下那一帧手必须落在工具上才攥得住，在别处拖一律无效；②工具有分量（跟手走但有速度上限，甩再快也只能一寸寸挪）；
   ③手飘离工作面会脱手，进度当场断；④反馈全长在工具与工件上（刨花卷落、粉痕、木头变亮），**HUD 上不留任何进度指示**。
   `state.dragTrack` 这个通道已整个删除，别再造。

1. **物体要答话**：每一下笔画/每一段行程都有 Cue + `FlashPose` + 画面变化（刨花卷落、粉痕、绳圈缠上去、土堆变矮）。
   停在半道要有状态或代价——刨刃啃住、辘轳倒转、结松开、功慢慢泄掉。
2. **长按+进度环只保留给"保持一个状态"的动作**（听、憋住别动、别松手）：那量的是时间本身，不是功——声明 `sustain: true`。
   同理，**做功的那一拍画面里不许出现任何可拖的 HUD 轨道**：只要有一根条，玩家就永远去拖那根条，被动道具白做。
   `state.dragTrack`／`#scribeGuide`／`input.dragX` 位移量通道已整体拆除——位移量拖哪儿都涨，本质是根看不见的 slider。
   守着它的：SmokeTest 在划线和刨料两拍逐帧盯着 `!state.dragTrack`。
   进度环（promptFill）只许当**读数**用：输入必须仍是笔画/绕圈/攥拖本身。
3. **手势要贴着做功的方向**：铲土往下、撑木往上、拴绳绕圈（`stroke:` 声明在 step/beat 上）。方向不对不涨——铲子不往上抡。
4. **指尖功夫推特写**（`state.closeUp`：辘轳）；抡膀子的活保持中景。
   能上手的大件够不够大＝一道算术（玩法景别下的像素数，阈值见 SmokeTest 的 `TestGrabbablesAreBigEnoughToRead`）；
   手有没有真落在那件东西上，见 RenderHealthTest 的「手真落在挂点上」。新加玩法就往这两张表里添一行。
   **手指按不着、认不出的东西，推镜头是治不好的**——量的方法：把那件东西的实际尺寸除以画宽，低于十分之一就别指望玩家认得出。
   能过测试和能上手是两回事，别拿测试绿了当验收。这类东西一律改用**铺满画框的手绘活卡**：
   `state.scribeCard` / `state.planeCard` / `state.knotCard` / `state.foldCard` → `Art.DrawScribeCard` / `DrawPlaneCard` / `DrawKnotCard` / `DrawFoldCard`
   每帧重画，`World.SetLiveCard({kind, view, layout}, dt)` 摆位（复用插入特写卡那套铺满逻辑，按 kind 分派画笔），
   手落在卡上的位置由 `World.ScreenToCard` 换算成 `input.pointerCard`（u 沿卡宽 / v 沿卡高）。
   版面各只有一份：Core 的 `SCRIBE_CARD` / `PLANE_CARD` / `KNOT_CARD`，判定与作画共用，绝不许在 Art 里另抄一套坐标。
   **有来回的动作，回程也得由画面说**（刨子到头就抬离料面、鼻子翘起来），不许退回一根会翻方向的轨道。
   构图硬规矩：**握把要在做功方向的后上方**，手不能压住刚做出来的功（拳头盖住刚划出的印子＝又看不见进度了）。
   **活卡的底必须是透明的**（`Art.LiveCardBase`，不是 `CardBase`）：活卡是玩家正在玩的那一拍——镜头只是推近了，村子并没有消失。
   背后是**真景散焦**：`World.Render` 见 `dofOn` 就把世界渲进低分辨率离屏靶、横竖高斯、压暗压暖铺回画面，卡再画在上头。
   **背景板不是玩法机位的截图，要按长焦重拍**：`DOF_ZOOM` 用收窄的相机放大远景、把贴机头那半屏地平线以下的土推出画框；
   `DOF_NEAR_CUT` 把机位与主体之间的近景带（obstacle/clutter 矮掩体、过肩剪影）藏掉——唯独地道剖面近侧那刀土 `dofKeep` 留下，
   藏了它就把脚底下的地道剧透了。zoom 的上限就是 ①里那条"娘也得在画里"。配套三条：
   ① **活卡那一拍的 `cam` 给的是背景的景别**，不是特写（特写归卡管）：贴着台面背后只剩一片天，退到院子的景别才装得下爹、娘、房子。
      （旧规范写的 `TestPlaneBeat` 源码里已不存在——刨料那拍随第九稿下线；新活卡拍照这条配 cam，没有测试守着。）
   ② **世界里的找路 UI 要收掉**（人字标、画框边缘的牌、人头上的标）。判据用 `liveCardOn`，不是景别。
   ③ 定格插卡（过场里那几张画）**不在此列**——它们本来就是一张画，铺满底板是对的。回归断言 `TestLiveCardsKeepTheWorldBehind` 只盯三张活卡。
5. **键盘后备是"能玩下去"，不是"能替代"**——**指尖上的活不给长按后备**。
   判据：这个动作的乐趣**是不是就在手上**？是（打结、缠绳），那就只认手；不是、只是费力气（挖土、顶撑木），可以留按住 E 的慢速档。
   **删掉后备就必须同时给驱动器一条真输入的路**：`GetBeatTarget` 返回专门的动作（接绳是 `knotAt`，把那张卡的版面与两段动作的落点整个交出去；
   投石是 `slingAt`，交出站位、朝向和靶心，驱动器拿 `SlingSolve` 现算该往哪儿拽多远），AutoPlay 照着**真的拖**——漏了这一步自动通关会当场卡死。
   **后备撤了，HUD 上那颗键也必须一起撤**。留一颗按了没反应的键比从来没有更糟——玩家会一直按它，然后认定这玩法是坏的。
   后备也不许替玩家把解算好（照靶心解一条必中弧）——底下的物理再好也没人走得到。
   **失败也要归因**：投空了要说清差在哪一头（没够着＝再拽满些／飞过头＝别拽那么足、手压低点／擦着底下过去＝弧再吊高些）。
   只说一句"擦着边过去了"等于没说，练不出来的玩法就是乱试。
5.5 **玩法要先有由头**：一个互动凭空冒出来，玩家不知道自己在干嘛，做得再拟物也是白做。
   开场三镜的配方——**把毛病演出来**（门自己晃、下轴脱了窝）→ **演一次一个人办不到**（爹伸手托，托到一半又坠回去）→ 他开口叫你搭手。
   到这儿"为什么需要第二双手"已经立住，玩法接得上，一个字的说明都不用。
   演的东西必须和玩法用**同一套状态**（`state.doorLeaf`）：过场里晃的那扇门，就是玩法里要扶的那扇门，不许另画一个只在过场里存在的道具。

6. **动作要对得上被做的那件事**：**绕圈是缠辘轳轴的动作，不是接绳的动作**。
   动词与实物对不上，做得再拟物也是错的——先问"现实里这活儿手怎么动"。
   画法铁律：**绳子不许用 `THREE.Line` 画**（`linewidth` 在多数平台被忽略，绳永远只有一个像素）。两条正路，按尺度选：
   **指尖尺度**（结、缠绕）走逐帧重画的 canvas（接绳那张活卡 `Art.DrawKnotCard`），真笔画真粗细，压叠关系才做得出来——
   麻绳从圈的右缘**底下**钻进去、左缘**上头**钻出来，"穿过去"就是靠这一笔成立的；
   **米级尺度**（定向绳）走**带宽度的 ribbon 网格**（三角带逐帧改顶点，见 World 的 `ropeLineMesh`）——那么长的绳 canvas 画布根本装不下。

7. **绕圈类动作的方向必须有意义，而且三处同向**：判定的方向、绳/绳圈**画**的方向、HUD 若有提示演的方向。
   **换算备忘：世界角度递增（`atan2`，y 朝上）＝ 屏幕逆时针 ＝ CSS `rotate` 递减。**
   辘轳是对的可以照抄：顺时针放绳（`-spin`）配 `gCircle`、逆时针摇上（`+spin`）配 `gCircleCcw`。
   反向转要有代价（打结会一圈圈解开），玩家才学得会方向。
7.5 **「按一下 E 就完」不算交互**。判据不是"有没有 hold"，是**画面上有没有人在干这件事**。三样一起给，缺一样都读不成：
   - **动词姿势**：`use` 步骤上写 `pose:`，进度直接驱动它（`pourBasket`）。姿势里的进度一律走 **`poseU`**，
     并在 `PoseProgress` 里按姿势名登记——用 `poseK` 串会被 0 吃掉（第 12 条那个坑）。
   - **手里那件东西要跟着动**：土筐不在 `ALONG_ARM` 里，`rotation` 恒为 0，不专门扣它，倒土就只是"弯了下腰"。
     扣到 82° 就停，**不许过 90°**：梯形的筐翻过 90° 在侧视里只剩一条边。`SyncCarry` 拿不到 `extra`，所以进度要在 `s.poseProgress` 上留一份。
   - **东西要真的出去、并且留下痕迹**：土从**筐口**落（不是从手心冒），落地由 `freshDirt` 那件 `showFlag` 道具接着演。
     颜色一律**按 sRGB 那条老账压两档**。
   顺带两条通用的：**动手之后才摆姿势、才转身**（一进判定区就钉住，会把只是路过的玩家一把揪住，自动通关更是当场卡死）；
   `StrokeWork` 每一下会 `FlashPose`，不把 `pose` 传给它就会被打回默认的 `bow`。
8. **抽象手势图标已整体拆除，别再造**：`state.gesture` 通道、`#gestureHint` 元素、那一族圆点 keyframes 全部埋了，
   SmokeTest 的 `TestGestureBlobStaysDead` 扫源码盯着。提示只剩两条正路，缺哪条补哪条：
   - **方向写进提示文案**：「顶住门框 · 往上使劲」「往后下方拽开，松手出手」。动词自带方向的（顶、拽）不必重复。
   - **招呼长在实物上**：辘轳的引导圈绕在轴心上、接绳的绳头朝该去的方向蹭、拉弓的预览弧就是弹道本身。
     图形提示必须钉在被操作的东西上，悬空的抽象图形一律不许有。
   每个玩法动词必须配角色动画，不许「人站着不动、字幕替他做」。
9. **一根"绳"要么有物理，要么别叫绳**：拉绳定向是 verlet 质点链（`Core.StepRopeLine`），四条经验写死在这儿：
   - **绳是从盘上放出来的**：`pay` 每帧朝「跨度＋一庹富余」收敛、封顶全长。全部手感来自这一条——放完就没了，放绳有速度上限，跑快了先绷一下。
   - **绷紧的绳靠张力自己吃住重量**：`gEff = G × (1 − taut^24)`。不补这一项，绳拉到了头（`span == pay`）却还整条趴在土里；松弛遍数**不是**瓶颈。
   - **松弛要一来一回换方向扫**：高斯-赛德尔单向一遍只把信息传一个节点。
   - **判定的那一头只许取身位，不许取骨架手心**。手心是姿势的产物，姿势又被绳拽出来（`ropeHaul`），拿它当绳端就是「绳→姿势→手心→绳」的闭环；
     而且 Node 里没有骨架，单测和实机两个结果。绳梢接到真拳头上是**画面**的活（World 里按 `rope.inHand` 把末尾三点朝 `HandPoint` 挪）。
   - **绳到头了就是走不动**：不弹字幕、不锁输入，绳把人拽住（`p.x` 回退）。那是"量到头了"唯一诚实的表达。
10. **做功的东西必须真的够得着**。新动词摆位前先算三笔（`Core.WINCH_HUB_Y` 附近有完整推导，`TestWinchIsACrankNotALever` ⑦ 逐点量）：
    - **够得着**：肩到轴心的距离 + 柄长 ≤ 臂长（按体型算）+ 姿势里那一档身位；
    - **圈不许扫过脸**：转到最左（或最右）那一点要让开脑袋半宽，否则整条胳膊横在自己脸前，读出来是"一只手捂着脸"；
    - **姿势由那件东西的相位驱动**，不是由 `phase` 那条自转的定速相位驱动；手要**真的落在把手上**
      （`Rig.ArmIK` 两骨反解 + `winchView.gripX/gripY`，World 负责把世界坐标换成骨架局部坐标）。取"肘朝下"的那组解。
    配套一条：**会被手挡住的小件要排在人之前**（摇把走 `BAND.obstacle` 的绘制序，位置仍在 `PlaceZ(BAND.loose)` 那条线上），
    排在人之后他一伸手就把整根摇把盖住，画面又成"空划拉"。

11. **费力气的活要有力气这本账**。判据：这个动作在现实里**撑久了会累**吗？会，就得有一条手劲
    （`state.stamina`，HUD 的 `#staminaBar` 是**读数**不是进度条——做功仍然只认手上那圈绕/那下按键）。
    三本账各自记：顺着重量做功几乎不费劲、**硬撑着维持现状最费**、逆着重量做功最费；撒开手回得快，但会掉进度——那口气是拿进度换的。
    **力气见底不许把人卡死**：只降效率或让物体自己缓缓走（空桶一顿一顿往下溜），永远走得完。

12. **跟着人走的东西，人钻地道时得有交代**：一头钉在地面 NPC 手上的绳跟不进地道剖面——硬画就是绳从地面穿进土里。
    所以手一松：绳缩回 NPC 手里（`RopeSlipAway`），链退回"抓住绳头"那一步，toast 说清楚，上来能重拽。
    **凡是"一头连着别处"的携带物，都要先想这一步**；只在手里的道具不受此限。

11. **判定圈钉在渲染层给的挂点上，别自己估**：拿身位加一个写死的偏移与高度估手在哪儿，判定圈会整个浮在实物上方，玩家是在空气里按。
   改法同刨子：渲染层每帧把 `HandPoint(rig)` 回填成 `state.handAt`，Core 的 `HandOf(state)` 优先用它，写死的常量只当无渲染时的兜底。
   攥住那一刻的手记进 `sling.hx/hy` 冻住，整趟拽以它为原点（身子转过去、架势抬起来，原点都不动），不然预览的弧和真出手的弧对不上。

12. **"由进度驱动的姿势"要验证它真的被驱动了**：进度字段由 `PoseProgress(o)` 按**姿势名**挑，不许拿 `??` 把几个进度字段串起来——
   `??` 只在 null/undefined 时才让位，**0 是会吃掉后面所有分支的**（`vaultK` 从建档那一刻就是 0）。纯逻辑测试看不出来（Core 侧的值一直是对的）。
   守着它的：`Script_RenderHealthTest` 里的浏览器断言——同一姿势、进度 0→1，`state.handAt` 必须真的挪地方（≥0.12m）。

### 「摆在地上的东西」认不出来是能抓的（找吃的那次，2026-08-12）

找吃的玩法在 `Core.FORAGE`，三条通用的：

1. **平摊在地上的东西等于没画。** 侧视里平摊的一片只有十来个像素高，和脚底下的影子分不开。
   要么**架起来**（苫子的折痕垫在瓦砾上），要么**斜着**（门板一头架在食槽上）。竖向有东西，玩家才知道那儿有件东西。
2. **明度也要跟周围拉开。** 跟塌下来的椽子、地上的影子一个明度就读不出；抬亮并加深浅两色的草茎，才读得出是"编起来的一片"。
3. **手必须真的落在那件东西上**（同摇辘轳那条）：Core 每帧把挂点发布成 `state.forage.<件>.grip`，World 换算成骨架局部坐标，
   Rig 的 `AimFrontHand` 两骨反解。不反解的话胳膊按姿势表摆在半空，画面上还是"对着东西空划拉"。

活卡那张（解扎口）：**CanvasTexture 上屏会提亮一大截**，所以卡上那几个色号看着"黑得离谱"才是对的。

## 一个动作要多长（打水那次定的，2026-08-10）

**长度是设计的一部分**，不是随手可调的手感参数——它决定这件事在玩家心里有没有分量。六条：

1. **加长靠加"道"，不靠把每一道拉长。** 摇同一个转盘从 4 圈变 12 圈只是变闷。打水是**四道手**，四个不重样的动作：
   放绳（绕摇把）→ 墩桶（攥住井绳往下猛拽）→ 摇上来（绕摇把，沉）→ 拽到井沿（攥住桶横拖）。找吃的照同一条配方。
2. 每道手都得**先问现实里这活儿怎么干**——"空木桶是浮着的，得墩两下它才吃水"这条不是设计出来的，是真事儿，而它恰好就是这一场最有仪式感的一下。
3. **别让相邻两道手用同一个动词**，否则玩家会拿上一道的手法糊弄下一道。墩桶那一道要是绕圈也能墩下去，二道手就白设了——
   所以判定加了两道闸：手必须落在井绳那条窄走廊里（`WINCH_ROPE_R`，绕摇把画的那个圈根本不在这条线上），且一把得够竖（横向位移超过竖向的 0.7 倍当场清零）。
4. **收势那一道不要再加一道墙。** 接在最费力气的几道手后头的收势不许挂体力——挂了，力气见底的玩家会被卡死在最后一步
   （撑不住→桶荡回井心→更没劲，死循环）。最后一下该让人喘上来。
5. 时长写进单测钉住（`TestWinchIsLongEnough`：键盘全速时长下限，四道手一道不能少）。别悄悄调回去。
6. **静场也是一道**：几下手做完之后，卡还停一拍——手撒开、四角再压暗一档，那片印子自己待在画面当中。
   它量的是**时间**不是功（第 2 条），所以是一镜演出，不是进度条；玩家这一下什么都不用做，正因为什么都不用做，那一镜才落得下来。
   别拿它去接一段过场——过场是"镜头替你看"，而这一刻要的是"你自己的手刚把它翻出来"。

## 「找东西」不能排成一条直线（2026-08-15 找吃的第二次退回）

**病根不在某一件道具，在链是一条直线**：走到剧本指定的那一处、做指定的那一下、再走到下一处，那不是找，是照着谱子按琴键。

结构：一个 `type:"searchAny"` 的步骤，底下挂**几处各自独立的小链**（`spots[].steps[]`），**玩家站在哪一处就跑哪一处**，
几处都翻过了这一整步才完。解析写在 `Core.SearchSpotNow`；`StepChain` / `GetBeatTarget` / `BeatHintIcon` **三处都要认它**，
漏一处就是"牌指着甲、路通往乙"。

配方（别的"翻找/搜查"场合照抄这四条）：

1. **每处给的东西不一样，而且都有用。** 食槽＝一小把秕谷壳、苇席底下＝娘留的谷种（全章题眼，不能吃）、墙根烧土＝红薯干（这顿饭的主料）。
   几处都空只剩"找到了没"，几处一样就只剩"再来两遍"。
2. **玩家翻着的那一样，后面要在画面上看得见。** 秕谷壳落成 `flags.chaffGot`，§8 做饭那一镜多一句「又把兜里那点秕谷壳抖进去」——
   **不接出去的收获等于几条 toast**（同「写了没人读的状态字段 ＝ 这个提示不存在」）。
3. **迷路要有兜底，说的是"往哪儿翻"不是"按哪个键"。** 不在任何一处里站够 `idleAfter` 秒就递一条 `idleNote`；
   画框边那张牌同时指向**最近的那一处**（`GetBeatTarget` 返回 `walk`）。两层保底。
4. **动词一处一个，别重样**（同「一个动作要多长」第 3 条）：掀（苇席）／扫（槽底）／刨（灰堆）。几处都用一个动词，玩家会拿第一处的手法糊弄后几处。

实现上两个坑：

- **判定区半宽要留得住 `standGap`。** `scoopAsh` 会把人挪到 `f.x ± standGap`，判定区 w 给得刚好时那个落点正好压在区边上，浮点一抖就掉出区外。
- **"声明了坐标才建档"对读的一侧同样成立**：撤掉一件，渲染层里读它属性的地方当场抛。改 `def.forage` 的构成时，把渲染层里**跨件互相引用**的地方一起 grep 一遍。

## 一个玩法元素的由头，最好长在玩法自己身上（2026-08-12 叠衣裳定的）

同一件事，两种交代：走过去触发一段插入特写，玩家是观众，"剧情到这儿了"；由玩家自己的手在做功时翻出来，玩家是当事人。

判据很好用：**这条信息能不能由玩家已经在做的那个动作顺手带出来？**能，就别再为它单开一镜。
顺带省掉的是一次镜头切换——插入特写会把活卡收走，玩家刚建立的手感断一次，回来还得重新找。

## 罚玩家之前先让他看懂（2026-08-14「匀稠的」整个退回）

三条，都通用：

1. **门的开关必须画在画面上。** 判定按一个状态字段走、画面上却什么都没有，玩家不会把角色的小动作跟自己手上的进度连起来。
   「危险先看得见再生效」（潜行第二条）对**所有**惩罚性玩法成立，不只对鬼子。
   **写了没人读的状态字段 ＝ 这个提示不存在**，改完顺手 grep 一把读取方。
2. **输入写进 prompt，一个都不许漏。** 只说了*什么时候*、没说*怎么做*就罚，不行。要罚，先保证他知道自己在干什么。
3. **同一场戏，一章只演一遍。** 第二遍就只剩机械——"推来推去"的真正来源是重复，跟失败次数无关。

通用判据：**一个玩法如果失败后只剩"原地再来一次"，那它八成不该是玩法，该是一场戏。** 戏的落点要回到章名上。

配套：`StepChain` 里那道通用的 `st.gate`/`st.caught` 分支（全作只有那一拍用过）已删，原地留了病根说明，别再照抄回来。

## 翻越尺度规范（2026-08-07 用户定，以第一章那堵塌墙为基准）

**「翻越」的定义是：一只手撑在顶沿上、身子绕着那只手转过去。** 撑得住的前提是顶沿不高过撑手的人的胯——
高过胯就得先把身子拽上去，那是「攀」不是「翻」，两套动作、两套动画，不许混用一个 vault。

数值全在 `Data_DepthSpec.mjs`，别在别处另立：

| 常量 | 含义 |
|---|---|
| `VAULT_MAX_TOP` | 可翻越物顶沿**硬上限**。基准＝第一章巷口那堵塌墙 |
| `VAULT_MIN_TOP` | 低于此就是"一步跨过去"，不值得占一个按键 |
| `VAULT_HIP_STAND` | 第一章柱子的站立胯高（`BONE.hipY` × 体型）。这张表上的数是**规范**，翻越上限跟着它不跟着人走 |
| `VaultLiftFor(top)` | 该抬多高＝顶沿加一小截余量再减胯高，**算绝对米数不算百分比** |

为什么不用百分比：`lift = top × 系数` 会让矮障碍抬过头、高障碍抬不够，两头都不像撑手翻越。抬升只取决于「顶沿比胯高出多少」。

**动画曲线是带平台的梯形，不是正弦弧**（`Core.VaultArc`）：撑起来 → **停在顶沿高度** → 松手加速落下。
中间那段平台是全动作的题眼：手是支点、胯骑在墙头、腿从顶上扫过，所以看得出他在"撑"。
**对称的正弦弧＝抛物线＝跳跃**，别写成 `sin(π·k)`。姿势关键帧（`Rig` 的 A/B/B2/C）必须和这三段对齐，
否则会出现「人还在墙头上、腿却已经摆出落地姿势」。

拦截在三处，配错不会静默上线：
- `Data_Scenes.mjs` 加载期抛（超限 / 缺 top / **贴图比声称的顶沿还矮**）；
- SmokeTest 全场景扫上下限，并逐帧量平台占比（低于阈值就判成跳跃）；
- 贴图高度也要对得上：`Data_PropArt` 的 `sprite.h − baseline` ≥ `top`，否则画笔画出画布被裁平。

## 交互动词

- 单格物品栏：手里任何道具随时可自由放下（`StepGroundItems`），落地道具自动挂图形气泡提示（`item:标签`）。
  链式步骤不要假设玩家手里还拿着东西——用 `needs` 声明，缺了给图形气泡/提示。
- **换层不许瞬移**（上下梯子 / 以后任何"从一层到另一层"）：`p.level` 当帧翻没问题——碰撞、视线、玩法都该按目的层算，不留半层的中间态；
  但**渲染高度必须自己走完那段路**（`p.lift` 从原来那层插到目的层，见 `StartClimb` 与 MovePlayer 的爬梯分支）。
  配套三件事，缺一件就还是穿帮：
  ① 镜头也读 `lift`（`BaseShot`），否则画面当帧切到井底，人从画框上边掉下来；
  ② 手脚钉在真横档上（见「爬梯」一节），跟横档无关的正弦相位读出来还是平移；
  ③ 跟着走的人（妹妹）同样要上梯子（`a.climbing` + 同一条 lift，落后一档），不然就是"你一格一格爬、她在井底等你"。
  速度按真人给（`CLIMB_SPEED_DOWN`／`CLIMB_SPEED_UP`），每档横档响一声；**梯子上可停可掉头**（见「爬梯」一节）。
  守着它的：SmokeTest 的「爬梯口上下」逐帧盯着高度只降不升、中途有几十帧真在挪、落地归零。

## 收藏品（老物件）与包袱 —— **2026-08-18 整套下线，别顺手打开**

【规矩】总开关只有一处：`Core.RELICS_ON`，现在是 **false**（用户：「把现在的道具收集
功能都干掉 暂时不要这个玩法」）。关着的时候**玩家看不出它存在过**：不出「E · 收进包袱」、
不发 `relicCard`、世界里不摆老物件也不亮那颗星、右上角那枚包袱钮带 `hidden`、纸带不建、
peek 不响、B 键不认；连**专门为它挡在镜头前的 `scene.fore` 前景草也一起不摆**

## 藏身处 = **前景里一件挡得住人的实体**（2026-08-14 两轮退回换来的）

**遮挡是几何，不是画法。** 阴影那一套（`AddWallShade` / `scene.shades`）已整个删除，别再造。横版里"藏"只有一种做法：

1. **一件实体，摆在 `clutter` 带——画在演员之前**，人走到它后面就真的被它挡住。掩体系统本来就是干这个的：
   `Data_PropArt.json` 的 `covers` 里登记，`coverBands.low` 把矮掩体派到 `clutter`。**别登进 `alwaysTall`**——
   那会把它退到 `yard`/`building`，于是它又成了背景里的一张纸片，人照旧杵在街上。
2. **高度是玩法本身，必须实拍量，不许照纸面估。** 前景件被透视放大、地平线还往下掉，纸面上「齐胸」到画面上就是**没顶**。
   判据：蹲下露出脑袋和肩膀一小截、站起来大半个人亮在墙外——**这个高低差就是"蹲下才藏得住"**。
   反算式：屏幕高度 ∝ (camY − Y)/(dist − z)，两个 z 各算一遍再比。
3. **朝危险那一侧要厚要高**：面向敌人那一侧一个更高的门垛封死；墙身矮着让玩家看得见自己。一件东西两个高度，两件事各得其所。
4. **判定区 = 那件东西的足迹**，一米不多一米不少。玩家能在画面上指出那条线，"我明明还藏着"才不会发生。

配套的三件事：

- **镜头一推近，机头前的掩体要让开**（`World.HideNearForInsert`）。前景挡人的东西在玩法景别里是藏身处，可插入特写是"绕到跟前拍"的，
  一堵矮墙会占掉半个画框。判据用**画幅**（`viewW` 阈值）不用节拍类型，阈值与活卡背景板的 `DOF_NEAR_CUT` 共用一个数。
- **`sustain` hold 那几拍不挂落地道具的气泡**（`StepGroundItems`）——玩家屏着气蹲在墙根，画面上不能顶着一颗"可以捡"的招牌。
- **被搂的那个也得蹲**：站着被搂是 `heldTremble`，蹲在怀里那条叫 `tremble`。**借轨道之前先看它注解里写的是站是蹲。**
  **ambient 轨道换幕不清**（`SettleBeat` 只清非 ambient 的那一路），所以"放开她"那一行必须亲手 `track = null`，不撤她会顶着蹲姿站起来走。

## 潜行的四条规则（第二章重做时定的，全作通用）

1. **藏 = 站到掩体背光的那一面**，不是站进掩体范围里（`CoverHides`）。高掩体站着挡得住、矮的得蹲；沟/庄稼地/灌木是"钻进去"的，没有正反面。
   灯绕过去，安全的那一侧就易手——玩家得跟着绕，这才是一维横版里最有得算的一条。
2. **危险先看得见再生效**：巡逻回头扫之前先举灯顿一下（`scanEvery`/`scanLift`）；掩体背光那一侧在画面上铺一条影子（World 的 shadeMeshes），
   "安全在哪儿"不许靠猜。
3. **动得越猛越显眼**：探测速率乘姿势与移动（站着快走更显眼、蹲着更隐蔽）。没有这一档，最优解永远是按住方向键跑过去，蹲下和掩体都成了摆设。
4. **每道关口至少给两条出路**，而且都不是"站着等"：读节奏冲过去 / 跟移动掩体（板车单向驶过，绝不来回横推）/ 用石子把灯引开
   （石子必须落在他**背后**才管用）。同伴（娘）只演示与救急（`state.pressHold`），绝不替玩家决定什么时候能动。

## 潜行的配套与几条通用判据（2026-08-18 从项目记忆并入）

- 【规矩】娘按住你＝`state.pressHold`：她丢下自己的掩体扑回来、手真的落在肩上（Rig 的 `press`/`pressed` 一对姿势），玩家被按成蹲姿、那一下真的走不动、也真的因此没被照见；有冷却；她去引开搜村的人之后这层保险就没了。
- 【判据】潜行段平衡自验：随机化巡逻相位跑 N 局、「傻跑」与「会玩」两个 bot——目标是**傻跑也过得去但要挨抓几次、会玩基本不被抓**；只看 SmokeTest 的「笨玩家能过」抓不到「没牙」这种病。（工具曾在 scratchpad `c2sim.mjs`，丢了照这个口径重写一份进 `Script_*`。）
- 【规矩】潜行重置点不落在任何人视线里、撤退方向必须是空的（`TestStealthEscapable`）；`beat.graceT` 重置后不判定，`def.visionScale` 收视距时判定/娘的决策/渲染光带三处自动同步。
- 【规矩】「重量感」要真动力学：重力恒拉、手是**有上限的**对抗力（弹簧＋阻尼＋力臂）、撒手加速坠、磕停带代价（掉进度＋扬土＋按速度给音量），再配反作用事件、strain 姿势、按转角出粒的吱呀；跟手运动学怎么调参都读成没分量。
- 【规矩】成功要有人接着：玩家做成一件事，画面里得有角色回应（妹妹 cheerHop＋一句话）——与「物体要答话」同级，写角色不写 HUD。
- 【规矩】「玩法要先有由头」也管过场里的动作：撞见由头（画面里真实存在的东西，不是一条 toast）→ 说一句 → 叫人动作 → 才轮到玩法。
- 【规矩】自测不许瞬移玩家：凡「玩家要自己走到某处」的节拍，测试必须只喂 input 走真实路径并断言节拍自己把人送到位；浏览器验证用真 PointerEvent，别直接写 state。
- 【规矩】会打断走路的动作必须由玩家主动按（可翻越物挡路＋头顶徽章，按互动键才翻；提示只在朝着它时出）；可翻越物不许压在跑腿路线上（SmokeTest 有断言）。
