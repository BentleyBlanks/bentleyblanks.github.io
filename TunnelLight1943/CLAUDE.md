## 先用命令行工作台，别一上来就读源码

```bash
node TunnelLight1943/Script_Cli.mjs
```

| 子命令 | 回答什么 |
|---|---|
| `where <片段>` | **这东西在哪**：节拍 / 函数 / 画笔 / 道具登记 / 骨架轨道姿势 / 规范章节 / **中文也认**（台词/提示语/章名/场次/老物件）/ 声音（cue/BGM/混音）/ HUD（DOM id/样式） → `文件:行` |
| `beats [c1]` | 列出全部节拍（章 · 序号 · id · kind） |
| `beat <id>` | 某一拍的全部：步骤/区域/needs/prompt/旗标/台词/源码位置 |
| `state <id> [选项]` | **无头**跑到那一拍、喂真输入、把状态打出来（`--x --level --step --input --flag --frames --trace --json --cues`） |
| `state <id> --cues` | **这一段响了些什么**（哪几种音效、各几声、音量区间）——声音是截图问不出来的那一样 |
| `shot <id ...> [选项]` | 实拍（真浏览器真键盘）→ `_shots/`（`--pre --step --hold --dur --phases --actor --clip --flag --probe --eval`）。**可以一条命令拍好几拍** |
| `shot <id>@line=N,at=T` | **钉到"第 N 句台词的第 T 秒"**那一格（拍过场用这个，别拿 `--dur` 猜）。**微过场也认**：链的某一步 `effect` 里起的那种，配 `step=N,pre=e,cine=keep` 用，数的是 `microCine.i` |
| `shot <id>@zoom=<谁>` | 顺手再裁一张近景（`zoom=sister` / `zoom=player` / `zoom=31.15:0.2`） |
| `doctor` | 分支/上游落后/未提交/缓存戳/端口占用 |

**这是硬规矩，因为代价量过**：翻 12 天会话记录，改这个游戏的 token 七成花在
「定位」上（Read/Grep 打在源码上 ≈149 万），另有 ≈40 万花在**现写一次性探针**
（234 个 scratchpad 脚本 + 319 次 `node -e`）——而跑测试只占 ≈23 万。7000 行的
`Script_Core.mjs` 同一段 300 行被反复读了 19 次，每个新会话都在重新画同一张地图。

- **要问游戏状态，先跑 `state`，不许现写探针脚本**；缺子命令就往 `Script_Cli.mjs`
  里加，加完写回这张表。一次性脚本写完就扔，下一个 agent 还得重写一遍。
- **要拨游戏里的开关，用 `--flag`**（`state` 和 `shot` 都吃）。地道挖通没有、
  门修好没有、车上装了几件料——这些是/否的记号决定画面长什么样，要拍
  「没挖通 / 挖了一半 / 挖通了」三张对比图就得能手拨：

  ```bash
  node TunnelLight1943/Script_Cli.mjs shot "c2_digout@x=42.3,level=under,tunnelDug=0" "c2_digout@x=42.5,level=under,digStarted=1,out=挖了一半" "c2_digout@x=43,level=under,tunnelDug=1,out=通了"
  ```

  `@` 后面**认识的键是参数（x/level/hold/dur/pre/actor/cine/out/clip/phases），
  不认识的一律当开关**——不用再记第二套语法。旗标在跳幕与微过场之后才写进去，
  所以 beat 自己的 `onStart` 盖不掉它。
- **一条命令拍好几拍**，共用一个浏览器；跨章也不用重开页面（`JumpToBeat` 吃章号）。
  实测：6 拍跨 5 个章节 19 秒；一拍一条命令要 40 秒，而且每次都要重写引导代码。
- **要问"画面上这块是哪张网格"，用 `--eval`**（截图前在页面里跑一段 JS 并打印
  结果，拿得到 `tl/state/world`）。页面渲染只在浏览器真的合成帧时才跑，所以
  这类问题**只能走实拍这条路**——`state` 子命令是无头的，`world` 里一张网格都没有。
  排查配方：先 `world.debugLayers().layers.play` 列出可疑区域的 `renderOrder/z/宽高`，
  再把嫌疑网格 `visible=false` 或 `material.color.setRGB(3,0,0)` 重拍一张对比。
  **别按 x 过滤网格**——横贯全场的那几张（地表断面带 230m 宽）中心点在场景正中，
  按"离目标 4 米内"一筛就正好把真凶筛掉了（井那次就绕了这个远路）。
  两条用法细则（2026-08-15 改抱姿时各栽了一次，加起来白跑五六轮）：
  · **`--eval` 收的是一个表达式**（内部是 `return (你写的)`，带 `tl/state/world`
    三个参数），写 `const x = …` 当场 SyntaxError；要写多句就套一个 IIFE。
  · **`--eval` 在 `Settle` 之前跑**，而骨架是渲染侧摆的：拿 `LimbTipsOf` /
    `PlayerLimbTips` 量姿势前，必须自己先在表达式里
    `tl.StepFrames(n), tl.Settle(m)` 把两侧都推够——不推的话量到的是**上一帧**
    的骨架，改了角度也纹丝不动，看着像"改了不生效"。同一条老规矩的新证据：
    **看不到本该变的东西时，先想是不是渲染侧没走够帧。**
  · 顺带：`--dur` 在无头下推不动游戏钟（rAF 几乎不走），想让一条 1.1 秒的
    `FlashTrack` 过期，也得靠 `tl.StepFrames(n)`，别指望 `dur=2.4`。
- **`--probe`**：截图同时报两件**有明确对错**的事——深度带用错没有
  （`DepthViolations`）、手脚离地多少（`PlayerLimbTips`）。**好不好看得自己看图**，
  这个开关不替你判断画面，只是把已有的两个体检数顺手打出来。
- **拍过场里的某一格，用 `@line=N,at=T`，别用 `--dur`**（2026-08-12 睡姿那次为此
  白跑了十几轮）。`--dur` 是从整拍开头算的：改一句台词的时长，后面全错位；而且
  推完之后还要等渲染追上（镜头缓动、立面淡出、光照换挡都要真渲染几帧），
  那半秒里游戏又往前走了——截出来的根本不是你要的那一格。现在 `shot` 在拍之前
  **冻帧**（`TunnelLight.Freeze`：游戏钟停住、渲染照跑），所以 `at` 说几秒就是几秒。
  **"这东西在画面上哪儿"也别再靠猜裁剪框**：`@zoom=sister` 直接给一张近景。
- **要截图，跑 `shot`**。那套引导代码有三个必踩的坑，已经固化在里面：
  `ServeRoot` 的 rootDir 必须 `path.resolve`（正斜杠字符串会 403）、页面 load 完
  `tl.state` 还是 null 得先 `StartGame`、**拍姿势必须真按键**（`FlashPose` 只有
  0.2 秒，`StepFrames` 之后的等待里 rAF 还在跑无输入帧，截出来全是站姿）。
  跳幕之后**等圆形黑幕拉开再拍**（轮询 `TunnelLight.iris`，Script_Main 挂的调试
  钩子）——死等固定秒数会拍到一个圆洞，而且等多久随机器快慢变，猜不准。
- **渲染侧的时间只在 rAF 里走，而无头浏览器没有合成器、rAF 慢到几乎不动**
  （实测 `--hold e --dur 12` 之后游戏钟只走了 0.58 秒）。`StepFrames` 推的只是
  `StepGame`；镜头缓动、立面淡出、**昼夜换挡（2.6 秒）**、光柱亮度吸附全在
  渲染那一侧。所以 `shot` 每拍之前还会调 `TunnelLight.Settle(n)`（2026-08-13 加）
  把渲染侧也推够帧数——不推的话拍到的是**过渡刚开始**那一格：序章那间该黑的
  窖一直拍成亮的，看图的人会判成"光根本没做出来"。
  **看不到本该渐变出来的东西时，先想是不是渲染侧没走够帧，别急着改数值。**
- **声音用 `state <id> --cues` 验，别靠听也别现写探针**。注意 `state.cues` 是
  只进不出的队列，**清空是宿主的活**（`Script_Soundtrack` 每帧 `cues.length = 0`）：
  自己收的时候不照做，就是每帧把整条队列重数一遍——18 秒的序章会报出
  "响了 20951 声"。
- **声音（旁白/音效/配乐）默认是关的**（用户定；2026-08-14 又从"默认开"回归过
  一次，别再改回去）：`Script_Main` 里 `localStorage.getItem(SOUND_KEY) === "on"`，
  没开过就是静的，开关记在本地。`Script_BgmTest` 因此要在 `addInitScript` 里
  先把那面本地开关拨开——它测的是"开了声音之后 BGM 怎么走"。
- `SmokeTest` 的 `TestCliAnswersQuestions` 盯着它——CLI 坏了不会有别的测试变红。

## 场景数据在哪（改东西之前先看这里）

**场景物体不写在代码里**。要挪一个东西、换一张贴图、改一档深度，改 JSON 就够了：

| 文件 | 管什么 |
|---|---|
| `Data_Scenes.json` | 每个物体**在哪**：x / level / w / h / 旗标门 / 区域 / 掩体 / 翻越物 / 窄段 |
| `Data_PropArt.json` | 每一类物体**长什么样、埋多深**：画笔名 / 深度带 / 烘焙画布 / 投影 |
| `Data_DepthSpec.mjs` | 深度带的**数值**（`building` 是 -3.4 这种） |
| `Data_Scenes.mjs` | 加载 + 解析 + **开局校验**（配错立即抛，不静默少画一个物体） |

这套白盒没有图片文件：贴图全由 `Script_Art.mjs` 的手绘矢量画笔实时烘到 canvas，
所以「引用的贴图」= `art` 字段里的画笔函数名，换皮就是换这个名字。

查看与体检（要挪东西、或者"这玩意儿怎么不见了"，先跑它）：

```bash
npm run scene:tunnelLight1943
```

它按场景列出全部物体的坐标/深度带/画笔/贴图尺寸，并交叉校验：剧本里的放置点
压没压掩体、挡人的矮物件是不是真的矮、翻越物撞没撞掩体、行走线上有没有穿插。

**新增一种 kind**：先在 `Data_PropArt.json` 的 `props`（或 `covers`）登记
`art` / `band` / `sprite`，再在 `Data_Scenes.json` 摆位置。漏登记会在加载时报错。
只有**条件绘制**（断了的井绳、露出的绳头、烧过的屋子）才写进 `Script_World.js`
的 `AddProp` switch —— 那是逻辑，不是数据。

## Z 轴深度规范（血泪最多的一条）

画面全是不写深度缓冲的半透明贴图，**前后完全由绘制顺序决定**。规则：

> 绘制序小工具（`LAYER_ORDER`/`DepthOrder`/`FixOrder`/`SetPlayOrder`）、烘焙工具
> （`BakeSprite` 一族）与无状态的地形/影子画笔 2026-08-15 起在
> `Script_WorldPaint.mjs`（从 CreateWorld 闭包抽出，可单独 import）；
> 跟着 state 走的绘制（AddProp/AddUnderground/UpdateOne）仍在 `Script_World.js`。
> 可变雾色走参数（`AddRidgeBand` 的 `hazeTint`），画笔不偷读闭包。

1. **带的数值**在 `Data_DepthSpec.mjs`（`BAND` + `ACTOR_Z/CARRY_Z/NEAR_CLUTTER`），
   **哪类物体用哪个带**在 `Data_PropArt.json` 的 `band` 字段。两处都不许写裸数字。
2. **动态物**（放下的、飞着的、演出用的）用
   `SetPlayOrder(mesh, BAND.xxx, "标签")` 或 `FixOrder(mesh, DepthOrder("play", BAND.xxx))`。
   **禁止在放置代码里写裸数字 z / renderOrder**——历史事故（道具把人吞掉、
   桶被草垛挡住隐形）全是裸数字造成的。
3. **带的语义**：固定在地上的道具 = `walk`；玩家放下/待拾的活动道具 = `loose`
   （压在 walk 之前、演员之后，永远看得见）；**横在路上的矮障碍（可翻越物）=
   `obstacle`**——比演员近一点点，挡得住小腿（挡不住就读成「路边的景」，玩家
   看不出它拦路），又不会像 `clutter` 那样被近景透视放大成一堵大墙；允许挡人的
   矮掩体 = `clutter` 或 `NEAR_CLUTTER` 区间（高过腰 1.2m 的一律退到负带，
   否则会把人整个吞掉）。
4. **落地贴图底边 = 地平线**（地表 `SURFACE_Y`、地道 `UNDER_Y`），y 不许为了
   观感手动抬高——贴地由 `sprite.baseline` 或 `MakeGroundItemMesh` 的 alpha 扫底
   负责。真要抬（挂树上的布巾）走 `yOffset`，那是声明出来的例外。
5. **道具落点不得进掩体足迹**：掩体带专职挡人。玩家/脚本放东西一律走 Core 的
   `DropSpot()`（会自动避开 `scene.covers`/`vaults` 并夹进行走范围）。
6. **校验**：`CheckBandZ` 会对表外 z 发 console.warn；浏览器里
   `TunnelLight.world.DepthViolations()` 可拿告警单，必须为空。
   例外词汇表（不受 BAND 约束）：地道剖面构件（`NEAR_Z`/`BACK_Z` 一族）和
   fx/fore/ots 层的 `LAYER_ORDER` 偏移。
7. **两个人绝不许共用一个绘制序号**（2026-08-15 用户报「柱子还会和娘有
   ZFighting」）。这层全是不写深度缓冲的半透明贴图，所以那不是深度缓冲在打架：
   同一排的人 z 与序号一模一样时，**两具骨架的各块贴图按摄像机距离互相穿插**
   （骨头各有各的局部 z），他的胳膊一会儿在她前面一会儿在她后面，镜头一动就翻。
   治法是**同带内的整数错位**：`SetPlayOrder(obj, z, tag, nudge)` 的第四个参数。
   表在 `Script_World.js` 顶部（`DRAW_NUDGE_PLAYER` 4 / `DRAW_NUDGE_HELD` 5 /
   其余按 id 稳定分 0..3），玩家永远压在乡亲之前，抱在怀里的孩子再压一档。
   两条细则：
   · **不许改 z 去错位**——`CheckBandZ` 只认规范表上那几档，挪 z 当场记一条深度
     违规，而那张单子必须为空；
   · **别拿 `FixOrder` 钉骨架**：它只钉传进去的那一个对象、不往下遍历，钉在
     rig 的 group 上等于没钉（各骨头照旧被 `ApplyDepthOrder` 按局部 z 派号）。
     要遍历的是 `SetPlayOrder` / `SetLayerOrder`。这个坑当天就踩了一次：
     改完实拍毫无变化，看着像"改了不生效"。

## 地平线规范：一条行走线，一个 z（2026-08-09 用户定）

起因是用户截图：「车和人都不在一个水平线」。镜头永远平视，所以**每一档 z 都有
自己的地平线**——深度 z 处 y=0 那条线在屏幕上 ∝ −camY/(dist−z)。也就是说：

> **两件东西只有 z 相同，才踩在同一条线上。**

默认玩法机位（hw 4.45 → dist 9.3m、视平线 1.85m、1600×900），以 walk(0) 为 0：

| building −3.4 | yard −1.6 | nearBack −0.9 | walk 0 | loose 0.3 | 演员 0.6 | obstacle 0.95 | clutter 1.6 |
|---|---|---|---|---|---|---|---|
| −89px | −49px | −29px | 0 | +11px | +23px | +38px | +69px |

推特写会把同一个差再放大几倍（hw 2.2 的插入特写：演员那 0.6 就是 **+76px**）。
2026-08-14 景别收了一档之后，这排数是 hw 6.3 那版的两倍——**"差一点点无所谓"
比以前更不成立**。

规则（数值与 `PlaceZ()` 在 `Data_DepthSpec.mjs`）：

1. **摆位走 `PlaceZ(band)`，排序走 `SetPlayOrder/DepthOrder(band)`。** 深度带
   从此只有绘制顺序这一个职责，不再兼职当位置。
2. 行走线上的一切（演员、影子、携带物、放下的东西、玩家推的车、钉在地上的
   道具＝ walk/loose/facade 带）位置一律压回 **z=0**。
3. z<0 的背景带、z>0 的前景带（obstacle/clutter/掩体）**保留自己的 z**：
   它们本来就站在别的纵深上，地平线不同是对的——但那条线得由画面交代
   （`AddBandEdge` 的路沿田埂、墙根、垄沟）。
4. `Script_DepthAudit.mjs` 逐章扫：play 层里凡是 0<z≤0.85 的元素一律判违规
   （躺平的投影除外）。别再在摆位代码里写裸 z——梯子那个 `0.45` 就是这么
   漏了半年的。

配套一条：**站姿整体抬起一个鞋帮**（`Script_Rig` 的 `SoleLift`）。大腿+小腿
正好等于 hipY，踝就落在 y=0，而鞋是从踝往下画的——不补偿，全场每个人都陷进
地里 9 厘米。**但跪、爬、趴不能抬**：爬行的脚是转过 180° 反铺在地上的，鞋帮
朝上，一抬膝盖就离地。判据是**膝盖高度**不是胯高——猫腰走（胯 0.32）和爬行
（胯 0.31）一样低，膝盖却一个屈在半空、一个跪在地上。改姿势后用
`world.PlayerLimbTips()` 对一遍：站姿脚 ≈ +0.078（＝鞋帮×体型），爬行
手 −0.00 / 膝 0.00 / 脚 −0.02。

## 剖面上"掏出来的洞"怎么画（竖井那次的教训，2026-08-09）

近侧剖面（`NEAR_Z=2.2`）是一张**不透明的土**，玩法空间全靠在它上面
`destination-out` 掏。掏洞有三条要一起满足，缺一条就读成"贴图破了"：

1. **洞的形状要像人挖的**：走廊、洞室都走起伏曲线，唯独竖井以前是一句
   `fillRect`——笔直两壁、方角、井底与走廊硬碰硬地对接。现在井筒也走
   `shaftGeom` 的轮廓：两壁带起伏、井口啃出一圈碎土、井底张成喇叭并进洞顶。
2. **洞沿的墨线一处都不能少**。走廊、穹顶都描了，竖井没描，于是井口那一圈
   就是土层贴图被裁掉的直边。
3. **掏开之后必须有东西填在后面，而且那东西要跟洞口在同一个平面**
   （2026-08-11 用户：「井有点小渲染bug」——井筒里横着一条硬边，上半截是天色）。
   老版把井壁摆在玩家背后（`BAND.nearBack`）再按视差比放大 1.4 倍去"填窗口"：
   洞口在 z=2.2、井壁在 z=−0.9，两个平面各走各的透视，**只在一个机位上对得上**，
   镜头一低（下到地道里往上看）就错开，井口上沿当场漏出天光。放大到多少都治不好，
   错的是平面不是尺寸。现在井壁与洞口同用 `NEAR_Z`、同一套 `toPx/toPy`、同一条
   `g.half(y)` 轮廓剪影——像素级对齐，任何机位都不漏。纵深改由绘制顺序交代。
4. **填在后面的东西，绘制序要压过那条地表断面带**。近处那条断面带
   （`AddGroundBand`，`walk−4`）横贯全场、从地平线往下铺 3.2 米，正好糊在洞口上。
   老井壁排在 `nearBack`(6222) < 断面带(6236)，所以它**从来没在画面上出现过**——
   井里那片灰蓝其实是这条带子，顶上那道亮边是带子顶沿与洞口顶沿的视差缝。
   井壁现在排 `walk−2`（在断面带之后、梯子 `loose` 与演员之前，人照旧从井筒前面
   爬过去）。`Script_RenderHealthTest` 的「井筒内壁」一条同时钉住同平面与这个序。
5. **洞室的穹顶不是券顶**（2026-08-11 用户：「这个傻逼一样的拱形是什么东西」）。
   老版一条三次贝塞尔、两个控制点都摁在洞顶，画出来是横跨全屋、两条腿一直扫到
   地面的砖砌拱。地窖是**近乎直上直下的两面墙＋圆角＋一顶略鼓的土顶**：
   `DomePts` 用超椭圆 `(1−s⁴)^0.4` 立起侧壁，再叠两道手挖起伏。
   还有一条更要紧的：**洞沿墨线只描还挨着土的那一段**。穹顶与走廊连通的地方本来
   就没有边，照着整条轮廓描下去就是在通着的空腔里凭空画一道弧（`InCorridor`）；
   反过来走廊的顶沿走到洞室也要断（`RoofOpen`），否则窖子当中横一条走廊高度的线。
6. **地平线那一刀是"地表被切开的断口"，不是两张贴图的接缝**
   （2026-08-11 用户：「地道口那里为什么有一条分割线一样的」）。剖面上沿原来就是
   `fillRect` 的直边：上头地表土色、下头剖面土色，两块平色贴着一条 razor 直线。
   断口要三样东西一起给：翻耕过的**耕作层**比生土浅一档且**下缘要化开**（不然只是
   把一道缝换成两道）、一条**起伏的墨线**、以及长在沿上的**草茬与土坷垃**——草要
   探出地平线，所以剖面画布往上多留一指（`TURF_RISE`），井口那一圈让开（它自己
   有碎土）。

顺带：井口那道从上面漏下来的光是这作品的题眼（`beam`，白天亮、夜里只剩月色）。

## 画笔的三条通用毛病（2026-08-10 用户三连退回换来的）

「树太丑了」「一点都不像是被擦掉了」——都是同一类病：**画出了"什么东西"，
没画出"这东西是怎么来的"**。逐条治法：

1. **画的顺序要跟事情发生的顺序一致。** 被刷掉的旧标语，老版是先铺一块浅色
   方块、再把字画在方块上——那是"白布横幅上印着字"。现在按现实的先后来：
   字先写在墙上，石灰水**一刷子一刷子横着扫过去**盖住它，刷薄的地方字自己
   透出来，底下再淌两道（`DrawWashedSlogan`）。顺序对了，一个字的说明都不用。
2. **四边笔直＝没有手。** 凡是"抹上去/糊上去/堆起来"的东西，轮廓不许有直边，
   也不许是一条光滑的圆弧。一刷的两头要收尖、上下沿要发毛，几刷的起止**只许
   往外探、探多远各不相同**（都停在同一条竖线上就又叠成方块；允许往里缩则
   一边的字整个露在外头，成了"刷歪了"）。
3. **不许在有内容的画布上用 `destination-out`。** 标语的"墙面坑洼吃掉笔画"
   原来是抠出来的——那张画布上除了字还有整面墙，抠出来的是**穿透墙体的洞**，
   白天看是几个亮点、夜里是几个黑点。要缺口就拿墙色盖回去（`wall` 参数）。

树那一版的具体病根另记一笔，同类形体（草垛、烟、土堆）都适用：
**"一团东西"不能靠一个大椭圆打底。** 老版先画一个盖住全冠、还描了墨边的
大椭圆当"冠底"，轮廓就成了一条光滑圆弧，各枝的叶团再怎么错位也只是在这张饼
里面挪——出来就是西兰花。现在冠**由一簇一簇搭起来**：暗层只在枝根垫着，
轮廓完全交给外圈那几团自己的凹凸，团与团之间留得出天、枝梢从缝里穿出去，
再挂几团小的专门把圆弧咬缺。配套两条：叶团的起伏要有**真正的瓣**
（`lobes`，±20%，光靠 ±8% 的随机抖出来还是正圆）；墨线抖动量要按团的大小走
（写死一个数的话，大树的团照样光溜溜）。骨架也别全交给随机——**中间的枝长、
外侧的枝短**，冠才拱得起来；四根枝一样长就是一张平顶的饼。

## 阅读层那张纸是**程序化画的**（2026-08-15 用户定：「界面里只有一张纸，程序化的在纸上写上文字内容」）

征夫告示的阅读层不再是「左边一张外部成图 + 右边现代排版的转录」，而是
`Art.DrawNoticeSheet` 现画的一张纸——连纸上的字一起（文案＝`Core.ZHENGFU_NOTICE`，
现在存的是**告示原文**而不是简体转录）。`#noticeSheet` 是张 DOM canvas，
`Main.PaintNoticeSheet` 只在**打开时与画框变了时**重画。换来的账：

- **繁体、竖排、自右向左**（全作铁律）。**标题也走竖排**——四个字横着码、按那时候
  的规矩自右向左，今天的人扫一眼读成「示告夫徵」，看着像 bug；竖排没有这个歧义，
  而且跟墙上那张小告示（`DrawNoticeWall`）同款。
- **canvas 的「当前路径」不进 `save`/`restore`**。`ctx.save(); ctx.clip();` 裁的是
  *上一句 `beginPath` 留下的那条路径*——第一版折痕与整层做旧因此裁在一根纤维／
  一粒印泥上，一笔都没落到纸上。实拍看着"纸太干净"，真相是被裁没了，不是画淡了。
  **每次 clip 之前把轮廓重走一遍。**
- **字号要搜，而且起点得给到铁定装不下**：从大往小收，收到刚好塞进版心为止＝
  "装得下的最大一档"，于是纸不论什么形状，字都给到最大、版心也总被填满。
  第一版起点拍脑袋给了 `h*0.040`，头一轮就通过，等于没搜。
- **纸形按画高走，不按"告示该是竖的"走**：竖长（0.72）在 16:9 上正好吃满画高、
  字最大；可横屏手机只有 390px 画高，竖纸只剩 264px 宽，字排到 **6px**——
  实拍量出来的，图上一个字读不出。矮画高那一档把纸摊到跟画框同形（封顶 1.75），
  字回到 17px。**判据用画高不用画宽**（同「拇指落点」那条）。
  守这条的是 `Script_RenderHealthTest` 的「告示的字每档画高都认得出」（下限 12px）。
- **做旧的上限由字定**：黄斑给到 0.26 的褐色压在落款上，「本區公所」当场糊成一片。
  同「盖章是气氛、日期是信息」——纸脏到看不清字就是本末倒置。印章同理：
  它骑着落款盖（挪到旁边空地上就成了"画在纸上的一枚章"），但上沿**刚咬住**署名
  末字就够，整个骑上去红压黑两下都读不出；也不许再往左吃掉日期那一列。
- 外部成图那条流水线（`Script_TypesetNotice.py` 排版 + `Script_TextureKey.py` 抠白底）
  与 `Texture/Texture_NoticeZhengfu.webp` **都还在，只是没人引用了**——
  要清理另说，别顺手删（同视频序章那批遗留资源）。

## 外部成图（Texture/）：白底必须抠掉才算做完

这套白盒的场景贴图全是矢量画笔实时烘的。**告示已经改成程序化的了**（见上一节），
这一节留给以后真要外挂的成图（插画卡之类）。这类图有一条铁律：

- **白底原图放 `Texture/Source/`，游戏只准引用 `Texture/` 这一层的成品。**
- 成品由 `python Script_TextureKey.py Texture/Source/<名字>.jpg --width <显示宽×2>`
  生成：抠掉纯白背景、裁到纸的包围盒、输出**带 alpha 的 WebP**。
- **JPG 没有 alpha 通道**——"我出图时留了纯白背景"这句话，只有配上抠图这一步
  才有意义。直接把白底 JPG 贴进深色面板，玩家看到的就是一块白方框
  （2026-08-10 用户报的原话：「告示的图片为什么没抠掉背景？」）。
- 抠图不是"删掉接近白的像素"：纸本身是浅米色，阈值一高连纸一起吃。脚本只抠
  **从画布四边连通进来的**那片白，再腐蚀一像素啃掉 JPEG 的灰白振铃，
  半透明像素做去白解混。三步缺一，纸边上会挂一圈白毛。
- 格式选 WebP 不选 PNG：纸是连续调，同一张 760px 宽的告示 PNG 要 1.6MB、
  WebP q86 只要 220KB。index.html 用 import map，浏览器底线本来就在
  Safari 16.4+，带 alpha 的 WebP 不存在兼容问题。
- 抠完的图会**长满整个框**（白边没了），版面要跟着复核一遍——竖屏那次就是
  图涨大之后把正文挤成两行才发现 `max-height:38%` 从来没生效。

## 世界内提示（HUD）清晰度

- 默认镜头下屏幕像素密度已是贴图标尺 PPM 的近三倍，特写还会推近——**任何
  会被玩家盯着看的 canvas 纹理必须超采样**：提示类用 `HINT_SS`，道具用
  `PROP_SS`，小件用 `DETAIL_SS`。逐帧重画的 canvas 用 `setTransform(SS,…)`。
- DOM HUD 的字体规矩见 `Style_Game.css` 顶部注释：居中走布局不走 transform、
  text-shadow 收贴身、字体必须真的加载（index.html 的 Google Fonts 四档字重）。

### 拇指落点上不许压着别的东西（2026-08-13 用户报「按钮触发位置偏移」）

DOM 按钮的**画**和**点**是同一个盒子，不可能真的错位——手机上报"触发位置偏了"
只有一个来源：**被别的元素盖住了一半**，剩下那弯月牙还能按，读起来就是触发点
挪了地方。那次的真凶是包袱条：右缘一条竖纸带，`max-height: 76vh`，在 375~430 的
横屏画高里必然长到拇指那一排上去，实测盖掉互动钮 **52%** 的面积；而它拾取时会
自己滑出来探头 3.2 秒，那会儿世界没冻结，玩家正要按互动。三条：

1. **判据用画高不用画宽**：竖着的 HUD 撞的是高度。桌面 1600×900 上同一条纸带
   离按钮还有三百像素，只在手机上才叠——这类 bug 一律是 `@media (max-height:)`。
   包袱条现在在 ≤520px 画高下改成右上角 3×3 的方格（正好九件，不用滚）。
2. **通知不许吃触摸**。滑出来"探头"的东西是通知不是控件：`#bagPanel` 默认
   `pointer-events: none`，只有玩家真打开（`.open`，世界冻结）那一档才接管拇指。
   `show`（滑进来了）与 `open`（打开了）是两个类，别混。
3. **底边也要让开安全区**。左右一直写着 `env(safe-area-inset-*)`，底下漏了：
   横屏 iPhone 的 home 指示条占着最底下 21px，系统先把那一条上的触摸当成上滑
   手势收走，落在盘子/钮下缘的拇指就白按了——同样读作"偏移"。

守这条的是 `Script_RenderHealthTest` 的「拇指控件三态无遮挡」：三档横屏手机
（667/844/932）× 三种状态（玩法 / 包袱探头 / 包袱打开），按圆形按钮的**有效
面积**逐点验，摇杆与两颗钮一格都不许缺。设置面板不在此列——那是玩家自己打开的
模态面板，点面板外面本来就是关掉它。同类旧账：跳过序章键原先在右下角，正压着
这排钮，已挪到左上角（见 `#btnSkipCine` 的注释）。

### 画框边缘的「下一件事」（2026-08-10 用户定，参考勇敢的心）

目标出了画框时，边上立的**不是一个方向键**，是一枚带图的牌（`Art.DrawEdgeHud`）：
**箭头说往哪走，图说去干嘛**，一支箭头说不了两件事。用户原话：「应该是一个 hud
带个 icon 的，表达你接下来要做的事情，不同任务不同人可能都有不一样的提示」。

- 牌面由 `Core.BeatHintIcon` 推出来，跟着 `GetBeatTarget` 那张表走：目标是谁就画谁
  （侧脸＋衣色——本作认人本来就靠这两样），是什么东西就画那件东西的小样，
  上手的活画手势。**挑人的条件必须和 `GetBeatTarget` 一模一样**，否则牌上是甲、
  路却通往乙。剧本可在节拍或链上某一步写 `hintIcon` 覆盖推导。
- 种类是封闭的一张表（`HINT_ICON_KINDS` ↔ `Art.HudGlyph` 的 switch）：新加一种词
  就得同时给一张画法，SmokeTest 的「边缘 HUD 牌面」会扫全八章逐拍验：每拍都推得
  出、种类都有画法、找人带得上 who、拿东西带得上 item，而且全场不许退化成一种图。
- 借世界里的画笔时**照实际尺寸倒推缩放**：`DrawCarry` 是按真家伙画的（长柄锄
  42 单位长、柄才 1.15 粗），原样缩到牌上是一根牙签；`DrawCharacter` 从脚到发顶是
  64×S 而不是 bodyH 的 62×S，照 bodyH 给会把脑袋切在裁剪圈外。牌面一律加圆形裁剪
  兜底，但裁剪是保险不是版面。
- 摆位在 `Script_World.js` 的 `UpdateEdgeHud`：牌贴在 z=0.6，**那一层的画框比
  `viewW` 窄一档**（×(dist−z)/dist），不折算箭头尖就被画框切掉。牌面按 icon 烘一次
  存进 `edgeHudTex`（每帧重画一张 HINT_SS 的大图太贵），一探一探的怂靠挪网格。
- 目标还在画框里时仍是原来那枚小人字标（`DrawMarker`），两者互斥。

### 角上那枚常驻的「下一件事」（2026-08-13 加）

中间那条目标只在**变化时**闪 6.5 秒（`SyncHud` 的 `objectiveT`），闪完玩家再想问
「我这会儿到底要干嘛」就没处查了；可常驻一行字又会把画面读成任务列表。所以常驻的
只有**一枚图**，钉在左上角（`#objectiveTab`）：

- 图与画框边那张牌**同源同画笔**——`Core.BeatHintIcon` 推种类，`Art.DrawHudBadge`
  画（＝`DrawEdgeHud` 去掉箭头：角上的牌不指方向，方向那件事只在目标出框时才有）。
  角上认得的图走到框边还是同一张，玩家只用学一套。新加 icon 种类照旧只改
  `HINT_ICON_KINDS` ↔ `HudGlyph` 那一对，这枚牌自动跟着长。
- **字要看的时候才给**：悬停（CSS）/ 点一下（`SetObjTabOpen`，7 秒自己收回去）
  才展开目标＋那句 hint。换了图只顶一下（`.bump`），**不展开字**——那会儿中间的
  目标条正把全文说着，两处同时说同一句就是重复。
- 过场里整枚藏起来（`inCinematic`），没有 `objective` 的拍也不出。
- 展开走 `grid-template-columns: 0fr → 1fr`，**裁剪壳必须是网格的直接子项**
  （`.clip` 那一层自己 `overflow:hidden`，自动最小尺寸才归零）。把固定宽度写在
  直接子项上，收起来的牌照样是三百多像素宽的一块隐形板子，还照吃点击——第一版
  就是这么量出来的（36×57 才是对的数）。字的宽度钉死在里层，不然展开那 0.28 秒
  里中文会一路重排行。
- 左上角还住着跳过序章那颗钮（现在没有 prologue 拍，机制留着）：两枚同时亮时
  牌让到它下面（`.lower`）。`Script_RenderHealthTest` 的「拇指控件三态无遮挡」
  那条顺带验这两件事：牌自己按得着、跟跳过键不叠。

## 镜头规范（2026-08-08 用户定，参考勇敢的心）

**全作只有一个景别档：玩法景别。** 变化只许来自镜头动画（横移 `pan`、换机位、
推特写做功那一拍），不许来自"把镜头拉远看全局"。

- **景别只有一张表：`Script_Main.js` 的 `PLAY_HW`**（地表 4.45 / 夜 4.35 /
  地道村 5.65 / 据点地道 4.25），`BaseShot` 从它取数，别在别处另写 hw。
- **尺子是「人占画高多少」，不是"看得见多少米"**（2026-08-14 用户拿《勇敢的心》
  的截图退回：「现在太宽了」）。那张图里的大人占画高 21~22%；本作原来地表
  hw 6.3（画高 7.09m），骨架实高 1.37m 的大人只占 19%、柱子（体型 0.80、
  实高 1.10m）只占 15.5%，一屏摆下十二米村街，读出来就是"人小、街长、天多"。
  现在地表画高 **5.01m**：柱子 22%、大人 27%，比那张参考图再大一档
  （第一版收到画高 5.5m／柱子 20%，用户当天回「还可以再大一点（10%）」）。
  **要改景别就改这个比例，别照"这一屏想装下什么"去配 hw**——后者每次都往宽了走。
- **中远景的定点镜跟着同一把尺子收**：`HintShot` 里 `wide`/`shot`/`close` 的
  dist 一律过 `TightenHw`（×0.71，下限 3.8＝本作最宽的那一档特写，封顶 8.5）。
  剧本里一百多处 `dist:` 因此不用逐个改——**也别再逐个改**：全片的景别是一把尺子，
  改尺子改 `HW_TIGHTEN`，某一镜真要例外就把 dist 写到 3.8 以下（特写原样过）。
  `insert`（铺满画框的插入特写）与 `free`（过场自由机位）不在此列，
  那两档是照着卡面与三维走位量出来的。
- **`hw` 是按 16:9 的画框调的**，所以 `ApplyCamera` 对**比 16:9 更宽**的屏幕
  （横屏手机常见 2.16:1、折叠屏更宽）**保画高、往两边加宽**：竖直方向仍是
  16:9 那么多米，`hw` 按 `aspect / (16/9)` 放大。照画宽走的老算法会把上下
  裁掉近两成——天和地各少一截、人贴着画框底边，读起来就是"画面被拉扁了"
  （2026-08-13 用户报的移动端横屏）。比 16:9 窄的（iPad 4:3）不动：那一头
  保画宽、画面往上下长，多出来的是天和地，什么也不会被切掉。
  这条与「不许拉远看全局」不冲突——**人在屏幕上的大小与桌面一模一样**，
  多出来的只是左右两侧的村子。RenderHealthTest 逐比例量着：一米见方投出来
  必须还是正方，超宽那几档的画高必须与 16:9 相等。
- `wide` 这个词在本作里**不是全景**，只是"比玩法机位退一档"：默认 `hw` 9.5
  （过 `TightenHw` 之后 6.7），写多大都在 `HintShot` 里封顶到 **8.5**。
- **绝对不许出现俯瞰全村的机位。** 原来 `wide` 的 hw 是 26——半径 26 米，
  一屏摆完整条村街，连地道剖面和地窖都露出来了。开场用它当第一眼，等于把
  地图和「命藏在脚底下」这个题眼一起剧透（用户原话：「搞得跟剧透一样」）。
- 交代世界靠**一次一处地走过去**：每一镜只给一件东西（一段村街、村口望出去的
  地平线、一副碾子），横移串起来，而不是一镜看完。
- 画面外的后果由角落的照片小窗（pip）兜着——这正是不必把镜头拉远的原因。
  **小窗还有第二个用处：去主相机去不了的地方**（井筒里、地面以下），见
  「地表场景看不到地平线以下」那一节。它同时是这一拍的提示。
- **镜头不自己动**（2026-08-10 用户定）：玩法段镜头只跟着人走。想让玩家看见
  什么，用**固定机位的一拍**或过场去交代，不要做"走到某处画面自己摇过去"。
  已经做过一版窖口自动下沉（走到地窖口把脚底下那间窖带进画框），当天就被
  退回：推着独轮车路过窖口时镜头往下一摇，车头和前面的路一起出画。
  机制还在（`Core.CAM_CELLAR_PEEK` 总开关 + `state.cellarPeek` + `BaseShot`），
  **默认 false**。真要再开自动镜头，两条一起做：
  ① 挂到 `state.steadyCam` 这一个让位判据上（推车 / 被盯上 / 节拍声明
     `steadyCam: true` 时一律不动），别各写各的；
  ② 位移量按**画高**（`world.viewSize.h`）反算，不许写死米数——宽屏手机
     2.16:1 的画高只有 16:9 的八成，同一个米数在手机上会把人头切出画外。
- **戏在屋里演，立面必须半隐**（节拍上声明 `indoorScene: true`，或过场里
  `state.beat.indoorScene = true`）。2.5D 里玩家走的那条线永远在立面之前，
  墙合着的时候屋里的人只有一双脚从墙根下漏出来——玩家根本不知道谁在哪儿
  （用户 2026-08-09 报的）。
  **半隐＝让开，不是变成一层膜。** 第一版只把不透明度降到 0.16、位置照旧压在
  玩法层之前，于是那 16% 糊在所有人和道具上：用户看到的不是"墙半透明"，是
  「门板都半透明了」（2026-08-10）。现在墙一淡到不再挡人（与 `IndoorHidden`
  同一条 0.5 线），`UpdateProps` 就把它的**绘制序**挪到演员之后（`nearBack`）
  ——位置不动（摆位归 `PlaceZ`、绘制序归 `SetPlayOrder`，两个职责本来就分开），
  墙还在、还看得出是一堵墙，人/门扇/工作台却全是实的。不挡人了就画得起实一点：
  半隐从 0.16 提到 0.30。**凡是"盖在玩法层前面的半透明大片"都先问这一句：
  该让开，还是该更透？** 让开永远比更透好——更透只会让整幅画一起发灰。
- **屋子的两头要有山墙内侧**（2026-08-14 加，`Art.DrawRoomWing`）。屋子只画了
  两片：后墙在 `building`(−3.4)、立面在 `facade`(0.4)。**后墙那片按透视只占到
  画框的一小截**——序里「柱子。」那一镜（机位 x=30.88 z=1.96）后墙的东缘落在
  NDC 0.60，右边那两成画框已经在屋外；而过场把第四堵墙整个撤掉，越过那条缝
  就直接望见野地和地平线上的炮楼。**这不是"后墙画短了"，是视差**：后墙比演员
  远四米，同样八米宽的墙在画面上只有演员那条线的一半宽。
  · 老办法是躲：机距收到 1.96、画框右缘钉块前景板、双人镜退成单人镜。现在
    屋子东西两头各挂一片 `roomWing`（Data_PropArt 的 `variants.interior.wingSpan`
    ＝从墙角往外铺多少米），画框往两头开到哪儿都还是墙。
  · **两条闸缺一不可**（`UpdateProps`）：① 只在 `filmic` 那一档现身——玩法景别下
    屋子两头由立面与门框交代，这两片一露就是"院子里凭空立着两堵墙"；②
    **镜头得在屋子足迹±1m 之内**，因为 `state.beat.indoorScene` 是行内 `on()` 拨的、
    一拍之内不会自己撤回去，而同一拍里插得进屋外的镜（c1_open 的水缸/牲口棚/
    鸡笼就在东边 36.6）。**不做渐变**：过场是硬切进来的，跟着立面那条 0.3 秒的
    曲线淡入等于每场屋内戏开头闪一下野地。
  · **摆在 building 带、绘制序挪到 `nearBack`**（跟立面同款的"位置归 PlaceZ、
    序归 SetPlayOrder"）：压过 yard 带那些院里的东西（老榆树、告示墙、鸡笼、
    猪圈——不然它们贴在屋里这道墙上），又稳稳低于行走线与演员。
    **院里 walk 带的杂物（石碾、掩体）压不住**，那是这一档的边界；真碍事再说。
  · **宽度是量出来的不是估的**：`shot ... --eval` 里把 NDC±1 二分回墙面深度上的
    世界 x，逐镜跑一遍取最大（第一章东 4.7／西 5.4）。**一张定宽的贴图由最宽的
    那一镜说了算**，代价是最远的两三镜里墙比屋子长——那是这个做法的已知取舍，
    别当成 bug 去改窄。
- **屋里地面上的固定物（地窖口、下窖的梯子）不要做隐现**：它们在 `loose`(0.3)
  带、立面在 `facade`(0.4) 带，墙本来就排在它们前面——合着的时候地面以上那截
  自然被墙挡住、地下那截照常露着，读出来就是「地窖在屋子底下」。
  这类东西读错位置**九成是坐标不在屋子足迹内**（窖口曾摆在院子里 x=37），
  别拿透明度去治：给它加隐现会把地下那截也灭掉，玩家在院里就找不着自家窖口，
  非得走进屋一米半才冒出来（2026-08-10 用户退回：「攀爬之前都是隐藏状态」）。
- **地表与地下在同一个场景里，所以"摆到画框外"这个说法必须指明是哪个画框**
  （2026-08-10 用户报的「镜头前面两根白白的模糊一坨」）。前景框景层（`fore`）
  的草丛/篱笆锚在 `SURFACE_Y - 4.4`，连层缩放算下来覆盖 y **−4.40→+1.06**，
  而地道内部是 −3.60（地面）→ −1.55（洞顶）——地表机位下它确实压在画框下缘外，
  镜头一沉进地窖就**正对着画面正中**，糊成两根发白的竖条。
  实拍逐像素比对给了判决：这层在地下改动 **2.51%** 的像素，在它本该干活的地表
  中远景上只改动 **0.25%**（平均色差 0.07）＝等于没画。于是内容整个删掉，
  `fore` 层留空，闸门改成 `dist > 7 && camY > SURFACE_Y`。
  以后真要做勇敢的心式的框景：**摆位跟着镜头所在那一层的地平线走**，
  别写死 `SURFACE_Y`；`Script_RenderHealthTest` 的「地下机位无前景层」守着这条。
- **过肩（`ots`）只用在两个人都露脸、面对面的场合**。被越过的那个人由前景
  剪影代表，它必须**被画框下缘切掉**才读得成"贴着镜头的那个人"；浮在半空

  纸面上的百分比。
- **路过的注视不许接管镜头**（2026-08-13 用户退回：出门几步连吃两个黑屏
  过场，「直接打断游戏体验……弱提醒一下不就好了」）。走路途中的 goto 触发点
  **不许起 `StartMicroCine`**——过场第一镜默认 iris 收黑，玩家读到的就是
  "切黑屏+夺操控"。路过要交代的东西（弹孔墙、刮皮秃榆）：道具画在路边

  过场只留给**事件**（车铃一响拉妹妹蹲下）和**玩家自己按 E 换来的**那种

  不能绕到侧面去）：
  ① 偏航/俯仰 ≲25°，roll 只做小幅荷兰角；

  ③ 室内镜头画框顶别越过屋高 2.4m——超了就是把天和远景带进屋里，

     门不能给正脸，给了就是一个透出地平线的空门洞，撞门用声音演。

### 过场三件套（2026-08-14 用户拿勇敢的心截图定的：「做成真正的过场动画」「也有这种左右分的镜头」）

上一版的序章实拍出来是"游戏截图换了个角度"：一屏米黄压米黄、人物占画高三成、
半屏是空墙、画面里没有一处是黑的。差距不在运镜，在**画**。补齐的三件：

1. **过场分级 `SetCineGrade(k)`**（World 的全屏后期）。这套画的贴图全是
   CanvasTexture、没声明 colorSpace，上屏被当线性值提亮两档——单张贴图能靠
   压色号救，**整幅画的调子救不回来**。分级把这两档还回来，且只在过场还
   （玩法段要靠亮度认路）。过场自动满档；玩法拍要跟着分级就写 `grade: 0.82`
   （序那三拍要玩的夹在过场中间，调子不能中途换脸）。
   **这一遍后期只许动明度，不许动色相**（2026-08-15 用户退回：「过场动画的
   后处理变色太严重了，只需要一些 dof、边缘的效果，但不能用大范围的偏色」）。
   分离色调（暗部推冷青灰／亮部推纸黄）**已整个删掉**——它让整幅画从暗到亮
   一路换色相，实测跨影调的红蓝差摆幅 46 个点，是"变色"的正主。连带一条：
   **对比曲线打在明度上、原色按比例缩回去**，别逐通道各跑一遍——逐通道会把
   本就偏暖的色拉得更开（高光比玩法段多出 15 点红蓝差），那也是变色，只是
   来自对比。现在剩下的四件都是各通道等量的：S 曲线对比（**不走直线**，
   直线把 0.12 以下全压成 0，窖底那几拍整幅纯黑）、黑位、晕影、纸纹颗粒；
   唯一动颜色的是 `uSat`，而它只往灰里收——`SetCineGrade(k, sat)` 的第二个
   参数，给 0 就是彩色转黑白（用户明说这一档可以）。要再加风格化就加在明度
   或饱和上，**不许再引入通道差**。
2. **过场框景 `fg: [...]`**（剧本行上声明，画笔 `Art.DrawCineFore`）。参考图
   每一张都有一块压得很暗、被画框切掉的近景：门框柱、房梁、炕沿、瓮肩、
   梯子帮、草茬。它吃掉空画框、给出一个很近的深度、并且是画面里唯一真正黑的
   地方。**摆位按画框给**：`{art,u,v,z,w,h,flip,dim,side}`——z 是离行走线多近，
   u/v 是板心在**它自己那个深度上的画框**里的位置（−1..1）。为什么不写世界
   坐标：贴镜头 0.8m 的那个平面上整个画框才三四十厘米宽，第一版五块板有四块
   落在画框外。u/v 只在换镜头那一下折算一次，之后钉死在世界里（推镜头时它按
   真透视扫过去，不是贴在镜头上的一张纸）。
   画法三条：**不许糊**（糊开读成"镜头脏了"）、**背光那条边要留亮边**（全黑
   的一块就是贴纸）、**里头要有纹理**。色号是跟分级一起算的：画 0.42 上屏
   才落到 0.18；第一版按"近乎全黑"画，出来是黑纸，只好拿一条很亮的边去救，
   那条边又变成一根发光的电线（两轮实拍各错一次）。
3. **左右分屏 `cam:{kind:"split", left, right, gap, fg}`**。两台过场相机各渲
   半屏（scissor），中间一道手绘撕口白缝（`Art.DrawSplitSeam`，比空当略宽，
   要咬进两边的画里才像画在同一张纸上）。一维横版里"同一时刻两个地方"本来
   没法同框，而序章最要紧的两下正是这个：显影时两个孩子各缩在一处；窖底两个
   孩子头顶上是空了的屋子。半屏画幅是竖的（≈0.88），**同一个机距下人物比
   整屏大一圈**，所以两侧机位要各按"这一格装什么"给。
   **两格的画框绝不许互相看见对方**（左格 30.3~31.5、右格 31.9~33.0），
   否则同一个人在两边各出现一次。框景按 `side:"left"|"right"` 挑相机折算。

**机位不许沉到地平线以下**（这一轮实拍抓的两次）：想从窖底仰头看洞口的娘，
机位得摆在窖顶(−1.55)与地表(0)之间——那儿是**实心土**（近侧剖面 NEAR_Z 那刀
只在窖室那块掏了洞），拍出来满屏是土、人不见了。地表机位同理：注视点压到
y<0.5 会把那条近景地面带（z=3.3）整个涨进画框，下半屏糊成一片灰。
窖底那间屋自己可以拍（那儿掏空了），c1_open 头一镜就是。

**微过场也算过场**：立面全隐的判据从「节拍 kind 是 cinematic」改成
「kind 是 cinematic **或** `state.microCine` 在跑」。序里"娘跪在窖口""搂紧她"
"翻板合上"都是链的 effect 里起的 micro-cine，节拍 kind 是 chain——那几镜一直
顶着 0.30 的立面拍，贴到 2.8m 的机位上就是整幅画蒙一层灰白。
是不是过场看的是**这会儿谁在掌镜**，不是这一拍挂在哪个 kind 上。

**配乐可以按拍/按行关掉**（`bgm: null` / `state.bgmOverride`，见
`Data_BgmConfig.EXTRA_BGM`）。剧本第一句就是〔音〕「没有音乐。」，可 BGM 是按
`CHAPTER_BGM[chapterIndex]` 无条件铺的，第一章那首从开机就在响——「吵的都在
墙外」这个设计在实机里一秒都没成立过。现在序的三拍静音，音乐只在收尾那句
「没人来叫。」进来，托过章名卡，画面一回来就交还给章 BGM。`Script_BgmTest`
有断言盯着序不许有配乐。

### 黑屏（`cam:{kind:"dark"}`）：黑要黑到底，长要短（2026-08-14 用户退回）

用户原话：「你现在做的所有的黑屏都不会黑到底啊？……而且很多镜头都很拖拉，
明明一转眼就可以解决的事情结果还在黑屏」。两件事各有病根，一起记下：

1. **黑不到底的真凶是层级，不是数值。** `#fadeOverlay` 在 index.html 里排在
   `#caption` **后面**，谁也没写 z-index 时它就压在字幕上头——于是"黑到底"
   和"看得见台词"只能二选一，老版为此把 `dark` 的 fade 封在 **0.94**，屏幕上
   是一层洗白的深灰。现在罩子 `z-index: 26`（世界、HUD、小窗 24 全在下面），
   字幕 28 / 章名字样 28 / 跳过键 30 / 章节卡·抉择·结束屏 32 在上面，
   fade 给满 `1`，背景色 `#000`。**同理，压在罩子之上的那几层不许带暖调**
   （captionScrim 原来是 `rgba(6,5,4,…)`，全黑画面下缘会留一条更亮的带子）。
2. **指数吸附永远到不了终点。** `fadeLevel += (t−f)·dt·2.4` 要 1.2 秒才走到
   九成，收黑慢、亮回来更慢，而且差着最后几个千分点永远是深灰。现在 6.5/s
   ＋ 贴近终点（<0.01）就**吸住**。
3. **空黑屏是标点，不是一场戏。** 逐句量过：序开场 3.4+2.6＝六秒纯黑，序收尾
   2.8+3.6+3.0+2.6＝**十二秒**连着的黑（一句四个字的旁白、一张章名卡、一句
   "三天后"、一声肚子叫）。现在开场 3.9s、收尾 7.2s。尺子：**没有字的黑
   ≤1.5s，一句短旁白 1.5~2s，章名卡只留它自己淡入淡出要的那点**；剧本里
   titleCard 的 `dur` 要跟着行的 `d` 一起改（差值留 0.2s）。
4. **实拍量黑屏要先推 HUD 这一侧。** 收黑的不透明度长在 `SyncHud` 里，而它
   跟镜头缓动、昼夜换挡一样只在 rAF 里走——`Settle` 原来没调它，无头实拍
   永远拍到"正在收黑"那一格（量出来 0.96）。`Settle` 现在把 `SyncHud` 一起
   推；再遇到类似的"数值明明改了、图上没变"，先问是不是这一侧没推够。
   顺带：`shot --eval` 是在 `Settle` **之前**跑的，拿它读渐变中的量会偏早，
   判黑屏黑没黑得看图（或对 PNG 逐像素量）。

## 过场要正脸/手势：活动插卡（2026-08-10 太君那一镜立的）

全作是侧视骨架，**正脸给不出来**。过场里要"冲着镜头"的画面（日军进村时
从伪军横摇到挎斗摩托上的军官、军官挥手、与伪军头目交头接耳），走**活动插卡**：

- 画笔在 `Script_Art.mjs` 写 `Draw<名>Card(ctx, W, H, seg, t)`，登记进
  `Art.INSERT_LIVE`；剧本行写 `cam: { kind: "insertCard", card: 名, seg: n }`。
- World.SetInsertCard 见到登记过的名字就每帧重画（同一块定格卡画框）；
  动画完全由 `(seg, 本行已走秒数)` 驱动——游戏时钟给的，无头实拍逐帧对得上。
- 一段连续演出拆成几个 seg 挂在相邻几行上，行的 `d` 就是该段时长；音效照旧
  在行的 `on()` 里 Cue。日军讲日语无字幕，这类段落只给同期声（引擎/风/乌鸦）。
- 实拍对时：`shot --dur --phases` 的 **dur 量的是游戏钟**——没按键的拍相位间
  用 StepFrames 把游戏时间推够数（长过场秒拍完），按着键的拍盯着 `state.time`
  等游戏钟走满。别再按墙钟折算（无头合成器上墙钟慢 3~4 倍，按墙钟等只会把
  相位全拍在第一句上）。`beat <id>` 会逐句打出 `[起点s +时长]`，dur 照它给：
  给到总时长再留半秒余量，最后一相位才不会滚进下一拍。
- **人脸只能走插卡**（2026-08-14）：窖底 3.6 米外，一颗脑袋在屏幕上二十来个
  像素，还整具转了 90°——骨架给不出"一张脸"。§9 那声「水。」现在挂在
  `strangerFace` 卡上（seg 0 那张脸／seg 1 张嘴）。画脸的三条账，都是画废了
  才看见的：① **画布 y 朝下**，"脸朝上"的局部坐标 v 要取负号，第一版整张脸
  倒着画；② 一张脸读不读得出来全在**外轮廓**（额→眉骨→鼻根的凹→鼻尖→人中→
  上下唇→颏唇沟→下巴），画个椭圆往里贴五官出来是块石头；③ 轮廓上的起伏
  **要大过笔迹的抖**（InkFill 的 amp）——第三版把这些点排在一条直线上、各
  离线三五个像素，出来是一条毛边。现在整条脸照一条"脸线"算：沿线走 s、
  沿法线推 o，鼻尖 o = 0.10 个头长。另外五官**明暗两遍都要画**（暗的一遍压到
  0.45）：只画在月光条里的话，光条压不到那块脸就还是没有五官。
- **改卡的版面用 `Script_ArtPreview.mjs card:<名字>`**：两段并排渲一张 PNG，
  十秒一轮；跑整拍实拍是三十秒一轮，而卡要改十几轮。
- 画里的经验：正面剪影的兵**两条腿必须分开画**（连成一片读成披袍的）；
  斜背的步枪是一道短斜线加一点刺刀尖，竖着画就成了长矛；骑车的人身下要有
  发动机的黑铁块和踩踏板的脚，否则人浮在半空；挎斗必须贴着车再加两根连杆。

## 人物与队伍（2026-08-09 用户定：「完全看不出来是日军」「2-3人一排」）

**三种兵的剪影必须一眼分得开**，语汇沿用 `TunnelBell1942/Script_Actor.mjs` 立过的
那一套（那边是 3D，这边是侧视手绘，标志物一一对应）。表在 `Script_Art.UNIFORM`：

| | 头 | 身上 | 腿脚 |
|---|---|---|---|
| 日军 `soldier` | 战斗帽 + **帽垂**（脑后垂布，侧视里最硬的标志） | 立领+红领章、武装带、前腰弹药盒、斜背带 | **绑腿** + 短军靴 |
| 军官 `officer` | 大盖帽（硬檐 + **绯红帽墙** + 星徽）、**卫生胡** | 深墨绿将校呢、斜挎武装带、胯后佩刀 | **马靴**（不打绑腿） |
| 伪军 `puppet` | 软布帽、**没有帽垂** | 胯后挎包 | 土布裤脚 + 布鞋（同村民） |

- 伪军**故意卡在日军与村民中间**——他是本乡人，不做丑角，这是人物设定不是偷懒。
- **进村时军官坐在挎斗里**（2026-08-10 用户定：太君坐斗、兵开车），交头接耳
  那一镜之后才下车徒步。队序表里没有他——他 pinTo 在 `motoLead` 上跟车走。
- 腿脚的颜色走 `Art.RIG_LEG(kind)`，小腿走 `Art.DrawShinPart`（绑腿是一圈圈斜缠的）。
  这四个颜色曾经是全场写死的农民褐，日军穿着一双农民的腿——"看不出是日军"有一半在这儿。
- **配色一律往下压两档**：CanvasTexture 没声明 sRGB，全场颜色被提亮两档。帽垂
  第一版用军帽同色（糊成一坨），第二版改晒白的浅布（渲出来跟土墙一个亮度），
  两版都等于没画。深的才立得住——**这类改动必须页内实拍看，别信色值**。

**行军是「排」不是一条线。** 一排 2-3 人，`rank` 声明第几排：
- 一排里的人**错开半个身位**（`ROW_STAGGER` 0.55m）＋后排退一档深度（`RankDz`），
  两样缺一不可：原来后排只错 0.22m，三十多米开外与前排完全重合，十个兵读出来
  就是一条等距长蛇（用户退回的正是这个）。
- 排与排之间空 `ROW_GAP`（2.5m）——是排内错位的四五倍，"排"的边界才立得住。
- 同一排的人**不许给速度微差**，走十几秒就被拉成一前一后。松散只给堆与堆之间
  （伪军 `PUPPET_FILE` 的堆大小 2/3/1/2/2 与不匀的间距）。
- 队序表 `RAID_ORDER` 是唯一真相，`RaidColumnIds()` 从它派生，别另抄名单。

## 昼夜（2026-08-09 用户：「24h切换现在太生硬」）

光照是**一条连续的曲线**，不是进拍即换。曲线全在 `Data_DayCycle.mjs`（纯数据
纯函数，所以能进 node 冒烟测试；渲染层只留"眼下按哪一档烘"那个状态机）：

- **时间只往前走**：`DAY_ORDER` 是个环（拂晓→白天→黄昏→夜→拂晓）。两档之间
  插的那一档是**紧挨目标之前**的时刻——奔夜里先经黄昏、奔白天先经拂晓、
  奔拂晓先过夜。按下标算远近会让太阳从西边升起来（第一版就栽在这儿）。
- **整村重烘推迟到过渡最暗的那一刻**（`DipAt` 那个正弦鼓包的顶点）：`builtKey`
  含光照档，换档就要按新调色板重烘一遍天/地/草/房子，那一下藏在厚罩子里
  才看不出接缝——电影换镜头也是趁黑切。渲染层为此要读 `ShownLight(state)`
  而不是 beat 想要的那一档。
- 压暗罩**是有颜色的**（夜泛蓝、黄昏泛橙、地道泛土黑）。纯黑罩子压出来的"夜"
  只是把白天调暗，看着像蒙了层灰。
- **日伪在村，天色就阴**（2026-08-10 用户："日军的出现 帮我氛围也改的昏暗
  阴森一些"）：World 的 `raidGloom` 把罩子加 0.15 档、颜色朝铅灰蓝拧
  （`MixHex(tint, 0x1c2334, k)`）。判据是**画面里有没有敌人**（soldier/
  officer/puppet 且 visible），不是旗标——队伍撤了颜色自己还回来；
  夜/地道档本来就沉，不叠。渐变 1.6s 指数吸附，进拍不跳变。

## 四个动词，全部长在 E 上（2026-08-16 用户定，照《勇敢的心：世界大战》）

用户原话：**「改掉所有的玩法，全部简化为前后有一定联系的基础的交互」**。全作只有
四个输入，Notion《序 · 那天》第九稿与各章「关卡设计」子页是口径：

| 输入 | 意思 | 代码 |
|---|---|---|
| **E** | 瞬时：拾、说、递、点火 | `type:"use"`（不带 hold） |
| **长按 E** | 保持一个状态（搂紧／托稳／按住），松手就塌 | `hold` + `steady:true`，或 hold 拍的 `sustain:true` |
| **E ＋ ←/→** | 横着做功：推、掰、拨、撕、缠 | `stroke:"left"/"right"` |
| **E ＋ ↑/↓** | 竖着做功：抱起／放下、掀、刨、舀、缝、摇辘轳 | `stroke:"up"/"down"` |

- **光按住 E 不再算做功**（`StrokeWork`）：方向不对不涨。键盘读 `input.climb`／
  `input.moveX`，手机走摇杆＋互动钮，**同一条路**。绕圈（`circle`）那一档还留着
  光按住 E 的后备——它没有方向可言。
- **按住 E 的那一帧，方向键归做功，不归走路、也不当爬梯**（MovePlayer 顶上的
  `WORK_ACTIONS` 那段）。不锁的话，掀翻板按 E＋↑ 正站在窖口上人就顺着梯子爬上去了，
  掰红薯干按 E＋← 一下就走出判定区。判据与自动通关驱动器用的是**同一个**
  （`GetBeatTarget` 报的 action ＋ 走进它的 reach）。
- **键位只写在提示的前缀里，不进正文**（`StrokePrompt` 统一改写，`SplitPrompt` 认
  「按住 E ＋ ↑ · 掀开草苫」）；HUD 把它翻成**两枚键帽**（`#actPrompt .pKeys`：
  E 加一个方向，涟漪与进度环只长在 E 那枚上）。数据里 prompt 只写动词最省心——
  写了旧前缀也会被 StrokePrompt 换成这一步真正要的那一半。
- **拟物那几套玩法（掀苫子／扒烧土／拖门板／掰／撕／缝／抠泥封）没有各写一条
  键盘分支**，而是共用一根**虚拟指尖**（`VirtualHand`）：方向键把"手"落在该攥的
  地方、朝那个方向匀速拖，底下的分量、脱手、卡口、钉住一个字没改。`regrab` 让
  "一把一把"的活（扒土、撕布）在按住时自己重新按下去；`orbit` 给解泥封那种绕圈的。
- 自动通关驱动器跟着按方向（`GetBeatTarget` 多报一个 `stroke`）——**新加做功步骤
  别忘了这条**，漏了驱动器会站在原地按一辈子 E。

第九稿同时下线的玩法（机制留在 Core 里没人用，别顺手删）：**修井绳／接绳活卡**
（`case "knot"`，`TestKnotIsASheetBend` 已停用）、**辘轳的墩桶与拽到井沿**
（`winch` 步骤写 `simple: true` 就只剩放桶／摇上来两道手）。

## 拟物交互（全作标准，2026-08-07 用户定的）

**凡是"对物体做功"的交互，玩家必须直接操纵那个被动物体本身**——拖它、推它、
绕它、按它。进度条与"长按 E 等它走完"**禁止作为主路径**。用户原话：不要玩家
在一个进度条上、或长按互动键就能完成，而是直接拖动、操作被动的道具完成
拟物化的交互。

已立住的范式（新动词先对号入座，不够再添，添了写回这张表）：

| 交互形态 | 输入 | 范例 |
|---|---|---|
| 攥住拖（工具在指尖） | `input.pointerWorld` 抓住实物 | 辘轳把手、**拖门板**（横拖有摩擦，中途卡在焦椽茬上——得往回让一寸才让得过去） |
| 在特写卡上攥住拖 | `input.pointerCard` 抓住卡上的实物 | 石笔（有摩擦、抓不稳会脱手）、**刨子**（有分量、停半道刨花断、抬手脱柄、到头抬起来回程）、**接绳**（照着**单编结**真挽一遍：穿进弯口→从两股中间钻上来→绕到两股背后→从底下兜回来→从自己那股底下掖出去，最后一把勒到底）、**叠衣裳**（拈住一个角拖到落点；布有分量、撒手塌回去、甩快了整幅弹回原处；折痕自己落在原边与落点的正中）、**解扎口**（逆着缠的方向把绳一道道褪下来，再捏住油布角掀开） |
| 绕着一个铰链掀起来（有重量） | `pointerWorld` 攥住外沿，角度跟着手走 | **掀苫草**（焦草苫子有分量、撒手自己坠回去、手甩得比它快就撕掉一口） |
| 一把一把地扒 | `pointerWorld` 落在那堆东西上，一把够长够斜才算一下 | **扒烧土**（2026-08-15 重做：浮灰滑、硬土拖不快、第三把拽到半道**手钉住**——指甲碰上坛肩，一个字不上屏；出路是换方向**顺着坛肩横着抹**，抹哪儿露哪儿。这一把是什么不看按在哪儿，看手往哪儿走；埋着的坛子由 DrawAshMound 画，pickup 步骤声明 `worldDrawn` 不许预摆地面道具剧透） |
| 绕圈（轴） | `pointerWorld` 绕轴心累计转角 | 辘轳（顺放逆收、脱手倒转、**手劲会耗尽**） |
| 笔画做功（一下一下干） | `StrokeWork`：down/up/circle | 挖土、按棉被、顶撑木、拴铃、装引信、撬地沿 |
| 顶住/扶稳（对抗一个持续的力） | `pointerWorld` 攥住实物，稳在容差内才涨 | **扶门扇**（下轴脱窝、整扇自己往外坠；撒手就坠回去、进度往回泄） |
| 竖拽 | `input.pull/pullHeld` | 竖向一把一把拽的活 |
| 攥住绳猛拽一把（一下一下，不是一直） | `pointerWorld` 落在绳的窄走廊里，一把够长够竖才算一下 | **墩桶**（空木桶浮在水面上不吃水，得一下下墩过去；手飘出绳外＝脱手，划得横＝那是绕圈不是墩） |
| 拽弓投掷（攥住手里的石子往后拽开） | `pointerWorld` 攥住 + 松手反向出手 | **石子**（拽的方向定角度、长短定劲；真弹道重力积分，预览弧=同一套物理跑出来的点列；蓄力姿势 throwWind 由拉弓量驱动。**没有键盘后备**，F 键与触屏投掷钮已整个撤掉） |
| 点按 | `input.tap` | 瞬时动作 |
| 拖着一件有物理的东西走 | 走位本身驱动，物体自己解算 | **拉绳定向**（麻绳 verlet 质点链：一路拖在土上，最后两米离地绷直，放到头绳把人拽住） |

规则：

0. **进度条/QTE 轨道禁止出现**。用户为这一条退回过两次（石笔一次、刨子一次），
   原话：「我鼠标要操作的是木刨子本身 不是一个slider！我要代入感！」
   判据很简单：玩家操纵的是**画面里那个东西**，还是一个抽象的量？
   位移驱动（`dragX`）也不够——那只是"拖屏幕"，手并没有落在工具上。
   四条缺一不可：①按下那一帧手必须落在工具上才攥得住，在别处拖一律无效；
   ②工具有分量（跟手走但有速度上限，甩再快也只能一寸寸挪）；③手飘离工作面
   会脱手，进度当场断；④反馈全长在工具与工件上（刨花卷落、粉痕、木头变亮），
   **HUD 上不留任何进度指示**。`state.dragTrack` 这个通道已整个删除，别再造。

1. **物体要答话**：每一下笔画/每一段行程都有 Cue + `FlashPose` + 画面变化
   （刨花卷落、粉痕、绳圈缠上去、土堆变矮）。停在半道要有状态或代价——
   刨刃啃住、辘轳倒转、结松开、功慢慢泄掉。
2. **长按+进度环只保留给"保持一个状态"的动作**（听、憋住别动、别松手）：
   那量的是时间本身，不是功——声明 `sustain: true`。
   同理，**做功的那一拍画面里不许出现任何可拖的 HUD 轨道**：只要有一根条，
   玩家就永远去拖那根条，被动道具白做。`state.dragTrack` 和它的 #scribeGuide
   元素/CSS 已整体拆除（2026-08-07，用户明令），`input.dragX` 位移量通道也一并
   废了——位移量拖哪儿都涨，本质是根看不见的 slider。SmokeTest 在划线和刨料
   两拍逐帧盯着 `!state.dragTrack`，一根都别加回来。
   进度环（promptFill）只许当**读数**用：输入必须仍是笔画/绕圈/攥拖本身。
3. **手势要贴着做功的方向**：铲土往下、撑木往上、拴绳绕圈（`stroke:` 声明在
   step/beat 上）。方向不对不涨——铲子不往上抡。
4. **指尖功夫推特写**（`state.closeUp`：辘轳）；抡膀子的活保持中景。
   **这一条有测试守着**（别再靠人记）：能上手的大件够不够大＝一道算术
   （玩法景别 184px/米，低于 128px 就认不出），见 SmokeTest 的
   `TestGrabbablesAreBigEnoughToRead`；手有没有真落在那件东西上，见
   RenderHealthTest 的「手真落在挂点上」。新加玩法就往这两张表里添一行。
   **手指按不着、认不出的东西，推镜头是治不好的**——量一下再决定：
   石笔在 1.9m 特写下只有十来个像素；刨子在 2.05m 特写下、844×390 的手机上
   也只有 **90×45 像素**，一块木头色的方块压在木头色的台面上。刨子那一版
   用真触摸事件测过：机制通的、偏 20px 也抓得住、三趟推得完——**但玩家认不出
   那是能抓的东西**，被退回。能过测试和能上手是两回事，别拿测试绿了当验收。
   **接绳（2026-08-10）是第三个栽在这上头的**：1.5m 半宽的井口特写下，整个结
   横过来才 0.23m ——屏幕上八分之一个画宽，用户的原话是「谁看得出来这是打结」。
   量的方法一样：把那件东西的实际尺寸除以画宽，低于十分之一就别指望玩家认得出。
   这类东西一律改用**铺满画框的手绘活卡**：
   **叠衣裳（2026-08-12）是第四个**：地窖的玩法机位半宽 5.65m，一件褂子摊开才
   0.55m ——十分之一个半宽，比接绳那个结还小。不用再试，直接上活卡。
   `state.scribeCard` / `state.planeCard` / `state.knotCard` / `state.foldCard`
   → `Art.DrawScribeCard` / `DrawPlaneCard` / `DrawKnotCard` / `DrawFoldCard`
   每帧重画，`World.SetLiveCard({kind, view, layout}, dt)` 摆位（复用插入特写卡
   那套铺满逻辑，按 kind 分派画笔），手落在卡上的位置由 `World.ScreenToCard`
   换算成 `input.pointerCard`（u 沿卡宽 / v 沿卡高）。版面各只有一份：Core 的
   `SCRIBE_CARD` / `PLANE_CARD` / `KNOT_CARD`，判定与作画共用，绝不许在 Art
   里另抄一套坐标。
   **有来回的动作，回程也得由画面说**（刨子到头就抬离料面、鼻子翘起来），
   不许退回一根会翻方向的轨道。
   构图有一条硬规矩：**握把要在做功方向的后上方**，手不能压住刚做出来的功
   （拳头盖住刚划出的印子 = 又看不见进度了，那正是拿掉进度条要换来的东西）。
   **还有一条：活卡的底必须是透明的**（`Art.LiveCardBase`，不是 `CardBase`）。
   活卡是玩家正在玩的那一拍——镜头只是推近了，村子并没有消失。老版三张活卡
   都铺了一整块渐变色底板，一推近整个世界被色板盖掉，用户 2026-08-10 的原话：
   「镜头在打刨花的时候 为什么后面的场景不拍出来？搞的像在玩一个独立的游戏
   一样，为了沉浸感你大可以远景做DOF嘛，但你搞了个纯色背景算什么」。
   现在背后是**真景散焦**：`World.Render` 见 `dofOn` 就把世界渲进一张 40%
   的离屏靶、横竖各来一遍 9 抽头高斯、压暗压暖铺回画面，卡再画在上头
   （代价反而更低——世界只按 16% 的像素渲一遍）。
   **背景板不是玩法机位的截图，要按长焦重拍**（2026-08-10 用户：「你不能直接
   拍现成的游戏截图……把当前物体之前的东西都隐藏吧，然后背景的FOV要搞大点，
   不然哪里像是一个低FOV聚焦在前景上的样子」）：`DOF_ZOOM`(1.5) 用收窄的相机
   放大远景、把贴机头那半屏地平线以下的土推出画框；`DOF_NEAR_CUT`(0.85) 把
   机位与主体之间的近景带（obstacle/clutter 矮掩体、过肩剪影）藏掉——唯独
   地道剖面近侧那刀土 `dofKeep` 留下，藏了它背景板就把脚底下的地道剧透了。
   zoom 的上限就是 ①里那条"娘在 x37.2 也得在画里"。配套三条：
   ① **活卡那一拍的 `cam` 给的是背景的景别**，不是特写（特写归卡管）。
      贴着台面 2.9m 会让背后只剩一片天；退到院子的景别（4~5m 半宽）才装得下
      爹、扫院的娘、房子。SmokeTest 的 `TestPlaneBeat` 卡着这个区间。
   ② **世界里的找路 UI 要收掉**（人字标、画框边缘的牌、人头上的标）：糊成一团
      的黄三角比不画还糟。判据用 `liveCardOn`，不是景别。
   ③ 定格插卡（过场里那几张画）**不在此列**——它们本来就是一张画，铺满底板
      是对的。回归断言 `TestLiveCardsKeepTheWorldBehind` 只盯三张活卡。
5. **键盘后备是"能玩下去"，不是"能替代"**——**指尖上的活不给长按后备**。
   2026-08-08 用户对接绳打结的原话：「你为什么还支持长按交互按钮的模式？干掉」。
   判据：这个动作的乐趣**是不是就在手上**？是（打结、缠绳），那就只认手；
   不是、只是费力气（挖土、顶撑木），可以留按住 E 的慢速档。
   **删掉后备就必须同时给驱动器一条真输入的路**：`GetBeatTarget` 返回专门的
   动作（接绳是 `knotAt`，把那张卡的版面与两段动作的落点整个交出去；投石是
   `slingAt`，交出站位、
   朝向和靶心，驱动器拿 `SlingSolve` 现算该往哪儿拽多远），AutoPlay 照着**真的拖**——
   漏了这一步自动通关会当场卡死（接绳、投石两次都是这么处理的）。
   **后备撤了，HUD 上那颗键也必须一起撤**（2026-08-10 投石：F 键、触屏投掷钮、
   物品栏那枚投掷键帽全删）。留一颗按了没反应的键，比从来没有更糟——
   玩家会一直按它，然后认定这玩法是坏的。
   投石那条后备是最坏的一种：站位落在 3~10.5m 里就照着靶心**解**一条必中的弧，
   角度不用调、劲不用调，按一下就赢。用户原话：「他妈的角度不用调力度不用调……
   你当我是弱智？」——底下那套拽弓物理其实一直是好的，只是没人走得到。
   **失败也要归因**：投空了要说清差在哪一头（没够着＝再拽满些／飞过头＝别拽那么足、
   手压低点／擦着底下过去＝弧再吊高些）。只说一句"擦着边过去了"等于没说，
   玩家不知道下一次该改什么，练不出来的玩法就是乱试。
5.5 **玩法要先有由头**：一个互动凭空冒出来，玩家不知道自己在干嘛，做得再拟物
   也是白做。用户退回过修门那一场：「我希望有一个过场动画能交代父亲在修窗户/门
   的原因（在摇晃）」。开场三镜的配方是——**把毛病演出来**（门自己晃、下轴脱了
   窝）→ **演一次一个人办不到**（爹伸手托，托到一半又坠回去）→ 他开口叫你搭手。
   到这儿"为什么需要第二双手"已经立住，玩法接得上，一个字的说明都不用。
   演的东西必须和玩法用**同一套状态**（`state.doorLeaf`）：过场里晃的那扇门，
   就是玩法里要扶的那扇门，不许另画一个只在过场里存在的道具。

6. **动作要对得上被做的那件事**（2026-08-08 用户退回接绳：「链接麻绳为什么
   也是转圈圈？不太合理」）：**绕圈是缠辘轳轴的动作，不是接绳的动作**。
   动词与实物对不上，做得再拟物也是错的——先问"现实里这活儿手怎么动"。
   **而且要问到底**：接绳后来又被退回一次（2026-08-10：「井里绳子打结的打结
   玩法一点都不符合直觉 哪有打结是这样的」）。那一版是"把绳头塞进一个圈里，
   再倒手拽三把"——**那压根不是个结**：绳头虚搭在圈里，一拉就出来。
   照抄一条判据备用：**做出来的东西得真的成立**。绳结成立的条件是绳自己咬住
   自己（绕住对方两股 + 掖到自己底下），少一样就是"套着"不是"结着"；
   拿着这条回头看，"塞进去再拽"缺的正是那两样。
   现在打的是**单编结**（水手结，专治两根粗细不一样的绳，正是井绳粗、麻绳细
   这个情形）：五道关口一条连贯的路走下来，最后一把勒到底。两条细则——
   - **绕的是那两股，不是那个弯**。绕着弯的闭口兜一圈，绳圈会顺着弯滑到开口
     那头脱出去。第一版就画错在这儿，实拍才看出来。
   - **勒紧是一把抻到底，不是倒手三次**。倒手三次是拿次数凑分量（游戏味儿）；
     分量该从**阻力**来：勒紧那一把绳走得比挽结时慢七倍，而且越勒越难拽
     （`cinchSpeed × (1 − 0.5·cinch)`）。撒手它自己往回泄——半截的结会松。
   - 顺带一个坑：**绳长（`reach`）要留得住勒紧那一把的行程**。最后一道关口
     沿勒紧方向还得走得完 `cinchLen`，不然绳头先被绳长卡住，剩下的进度全靠
     贴着圆弧蹭——实测那一次，一把变成了四秒半的磨。
   顺带一条画法铁律：**绳子不许用 `THREE.Line` 画**，`linewidth` 在多数平台
   被忽略，绳永远只有一个像素，贴在辘轳那堆木色上根本看不见。两条正路，按
   尺度选：**指尖尺度**（结、缠绕）走逐帧重画的 canvas（接绳那张活卡
   `Art.DrawKnotCard`），真笔画真粗细，压叠关系才做得出来——麻绳从圈的右缘
   **底下**钻进去、左缘**上头**钻出来，"穿过去"就是靠这一笔成立的；
   **米级尺度**（定向绳十八米长）走**带宽度的 ribbon 网格**（三角带逐帧改顶点，见 World 的 `ropeLineMesh`）——那么长的
   绳按 48px/米要三千多像素宽的画布，canvas 那条路根本走不通。

7. **绕圈类动作的方向必须有意义，而且三处同向**：判定的方向、绳/绳圈**画**的
   方向、HUD 若有提示演的方向。打结曾经三处不一致——判定取 `Math.abs(d)`
   两边都算涨（那不是缠绳，是"在这儿画圈满一定角度"），绳圈按世界角度递增画
   （屏幕上**逆时针**），而 CSS 的 `rotate(0→360deg)` 在屏幕上是**顺时针**
   （y 轴朝下），于是提示和绳子当场打架。
   **换算备忘：世界角度递增（`atan2`，y 朝上）＝ 屏幕逆时针 ＝ CSS `rotate` 递减。**
   辘轳是对的可以照抄：顺时针放绳（`-spin`）配 `gCircle`、逆时针摇上（`+spin`）
   配 `gCircleCcw`。反向转要有代价（打结会一圈圈解开），玩家才学得会方向。
7.5 **「按一下 E 就完」不算交互**（2026-08-10 用户退回倒土：「倒土的话好歹有个
   配套的动作啊」）。判据不是"有没有 hold"，是**画面上有没有人在干这件事**：
   倒土原来是裸的 `type:"use"` + 一句 prompt，按一下 E，人杵在原地空手，土也不知
   去向。改法是三样一起给，缺一样都读不成：
   - **动词姿势**：`use` 步骤上写 `pose:`，进度直接驱动它（`pourBasket`）。
     姿势里的进度一律走 **`poseU`**，并在 `PoseProgress` 里按姿势名登记——
     用 `poseK` 串会被 0 吃掉（第 10 条那个老坑）。
   - **手里那件东西要跟着动**：土筐不在 `ALONG_ARM` 里，`rotation` 恒为 0，
     不专门扣它，倒土就只是"弯了下腰"。扣到 **82° 就停，不许过 90°**：
     梯形的筐翻过 90° 在侧视里只剩一条边，实拍 118° 那版读出来是"举着块板子"。
     `SyncCarry` 拿不到 `extra`，所以进度要在 `s.poseProgress` 上留一份。
   - **东西要真的出去、并且留下痕迹**：土从**筐口**落（不是从手心冒），
     落地由 `freshDirt` 那件 `showFlag` 道具接着演。颜色一律**按 sRGB 那条老账
     压两档**——第一版 `#5b4a33` 实拍是几粒发白的点，跟土墙一个亮度。
   顺带两条通用的：**动手之后才摆姿势、才转身**（一进判定区就钉住，会把只是
   路过的玩家一把揪住，自动通关更是当场卡死）；`StrokeWork` 每一下会
   `FlashPose`，不把 `pose` 传给它就会被打回默认的 `bow`。
8. **抽象手势图标已整体拆除，别再造**（2026-08-10 用户看到扶门那拍的小黑饼——
   暗圆盘里一粒点按方向做动画——原话：「明明是按键交互 非要装自己是个圈
   还给个方向？你这叫提示？」）。`state.gesture` 通道、`#gestureHint` 元素、

   - **方向写进提示文案**：「顶住门框 · 往上使劲」「往后下方拽开，松手出手」。
     动词自带方向的（顶、拽）不必重复。
   - **招呼长在实物上**：辘轳的引导圈绕在轴心上、接绳的绳头朝该去的方向蹭、
     拉弓的预览弧就是弹道本身。图形提示必须钉在被操作的东西上，

9. **一根"绳"要么有物理，要么别叫绳**（2026-08-09 用户退回拉绳定向：
   「拉绳子量距离的玩法 在绳子拉直之前应该都有一些物理的效果」）。老版是一张
   拉伸旋转的窄条：人走多远它就直多远，从来没垂过、没拖过地、也从不吃劲，
   于是"量距"只剩走过去按个键。现在是 verlet 质点链（`Core.StepRopeLine`），
   四条经验写死在这儿：
   - **绳是从盘上放出来的**：`pay` 每帧朝「跨度＋一庹富余」收敛、封顶全长。
     全部手感来自这一条——放完就没了，而且放绳有速度上限，跑快了先绷一下。
   - **绷紧的绳靠张力自己吃住重量**：`gEff = G × (1 − taut^24)`。不补这一项，
     绳明明拉到了头（`span == pay`，几何上必须是直线）却还整条趴在土里——
     十八米跨度只要多出二十七厘米，中间就垂下去一米多，而松弛解算的残余正好
     是这个量级。松弛遍数**不是**瓶颈（22→90 遍只从 18.87 收敛到 18.77）。
   - **松弛要一来一回换方向扫**：高斯-赛德尔单向一遍只把信息传一个节点。
   - **判定的那一头只许取身位，不许取骨架手心**。手心听着更准，但它是姿势的
     产物，而姿势又被绳拽出来（`ropeHaul` 把胳膊收到身后半米），拿它当绳端
     就成了「绳→姿势→手心→绳」的闭环：实机里人在离七叔家还有两米多的地方
     被自己的胳膊卡死，而且 Node 里没有骨架，单测和实机两个结果。
     绳梢接到真拳头上是**画面**的活（World 里按 `rope.inHand` 把末尾三点朝
     `HandPoint` 挪，越靠末端挪得越多）。
   - **绳到头了就是走不动**：不弹字幕、不锁输入，绳把人拽住（`p.x` 回退）。
     那是"量到头了"唯一诚实的表达。
10. **做功的东西必须真的够得着**（2026-08-10 用户："角色的动作也太蠢了"）。
    辘轳那一拍的老账：轴心定在 1.43m，而第一章那个孩子头顶才 1.13m、肩高
    0.82m、一条胳膊伸直 0.39m ——摇把画的那个圈他一辈子也够不着，动画只能
    让两条胳膊在半空按一条**自转的定速相位**画圈，跟屏幕上那根摇把毫无关系。
    新动词摆位前先算三笔（`Core.WINCH_HUB_Y` 附近有完整推导，
    `TestWinchIsACrankNotALever` ⑦ 逐点量）：
    - **够得着**：肩到轴心的距离 + 柄长 ≤ 臂长（体型 × 0.49m）+ 姿势里那一档身位；
    - **圈不许扫过脸**：转到最左（或最右）那一点要让开脑袋半宽 0.09m，否则
      整条胳膊会横在自己脸前，实拍裁下来是"一只手捂着脸"；
    - **姿势由那件东西的相位驱动**，不是由 `phase` 那条自转的定速相位驱动；
      手要**真的落在把手上**（`Rig.ArmIK` 两骨反解 + `winchView.gripX/gripY`，
      World 负责把世界坐标换成骨架局部坐标）。取"肘朝下"的那组解。
    配套一条：**会被手挡住的小件要排在人之前**（摇把走 `BAND.obstacle` 的绘制
    序，位置仍在 `PlaceZ(BAND.loose)` 那条线上）——排在人之后的话，他一伸手
    就把整根摇把盖住，画面又成了"空划拉"。

11. **费力气的活要有力气这本账**（2026-08-10 用户："放下水桶这个过程角色一点
    力好像都不需要用，还可以坚持着不放下去"）。判据：这个动作在现实里**撑久了
    会累**吗？会，就得有一条手劲（`state.stamina`，HUD 的 `#staminaBar` 是
    **读数**不是进度条——做功仍然只认手上那圈绕/那下按键）。三本账各自记：
    顺着重量做功几乎不费劲、**硬撑着维持现状最费**、逆着重量做功最费；撒开手
    回得快，但会掉进度——那口气是拿进度换的。**力气见底不许把人卡死**：只降
    效率（辘轳留 22%）或让物体自己缓缓走（空桶一顿一顿往下溜），永远走得完。

12. **跟着人走的东西，人钻地道时得有交代**（同上，用户：「如果玩家下了地道，
    手里拿着的绳子也应该断回到npc手里」）。一头钉在地面 NPC 手上的绳跟不进
    地道剖面——硬画就是绳从地面穿进土里。所以手一松：绳缩回 NPC 手里
    （`RopeSlipAway`），链退回"抓住绳头"那一步，toast 说清楚，上来能重拽。
    **凡是"一头连着别处"的携带物，都要先想这一步**；只在手里的道具不受此限。

11. **判定圈钉在渲染层给的挂点上，别自己估**（2026-08-10 投石查出来的）：
   投石要求"按下那一帧手落在手里那颗石子上"，判定却是拿 `p.x + 朝向×0.24` 和一个
   写死的高度估的。第一章的柱子按 0.80 身量：垂手拎石子的手在 **0.47m**，
   带出蓄力架势才到 0.6~0.7m——写 1.12 的话判定圈整整浮在石子上方**大半米**，
   玩家是在空气里按。改法同刨子：渲染层每帧把 `HandPoint(rig)` 回填成
   `state.handAt`，Core 的 `HandOf(state)` 优先用它，写死的常量只当无渲染时的兜底。
   攥住那一刻的手记进 `sling.hx/hy` 冻住，整趟拽以它为原点（身子转过去、
   架势抬起来，原点都不动），不然预览的弧和真出手的弧对不上。

12. **"由进度驱动的姿势"要验证它真的被驱动了**（2026-08-10，同一次查出来的老毛病）：
   Rig 里刨料/投石都写着"姿势由进度直接驱动"，渲染层却把三个进度字段用 `??`
   串了起来——`p.vaultK ?? p.poseU ?? p.poseK`。而 `vaultK` 从建档那一刻就是 **0**，
   `0 ?? x` 取的正是 0，于是**刨料的推程和投石的拉弓量从来没走到画面上**，
   两个姿势一直冻在起手那一格。纯逻辑测试看不出来（Core 侧的值一直是对的），
   `assert.ok(state.player.poseK > 0.4)` 也照样绿。
   现在由 `PoseProgress(o)` 按**姿势名**挑字段，`Script_RenderHealthTest` 里加了一条
   浏览器断言：同一姿势、进度 0→1，`state.handAt` 必须真的挪地方（≥0.12m）。
   教训写在这儿：`??` 只在 null/undefined 时才让位，**0 是会吃掉后面所有分支的**。

### 「摆在地上的东西」认不出来是能抓的（找吃的那次，2026-08-12）

用户退回第一章找吃的：「居然是长按一个按钮？一点都不拟物，交互程度好低一点
也不沉浸」。老版三步全是 `use + hold`，站着按住 E 等进度环走完。重做成四道手
（掀苫草／拖门板／扒烧土／解扎口，玩法在 `Core.FORAGE`）时撞出三条通用的：

1. **平摊在地上的东西等于没画。** 侧视里一片 1.6m 的苫子只有十来个像素高，
   和脚底下的影子分不开——实拍第一版读出来是"人对着一摊黑影伸手"。
   要么**架起来**（苫子的折痕垫在瓦砾上 0.5m，剪影 1.14×0.50m），要么**斜着**
   （门板一头架在食槽上，仰角 0.22rad）。竖向有东西，玩家才知道那儿有件东西。
2. **明度也要跟周围拉开。** 焦草苫子第一版 `#4a3d24`，跟塌下来的椽子、地上的
   影子一个明度。抬到 `#6d5c3a` 并加深浅两色的草茎，才读得出是"编起来的一片"。
3. **手必须真的落在那件东西上**（同摇辘轳那条）：Core 每帧把挂点发布成
   `state.forage.<件>.grip`，World 换算成骨架局部坐标，Rig 的 `AimFrontHand`
   两骨反解。不反解的话胳膊按姿势表摆在半空，画面上还是"对着东西空划拉"。

活卡那张（解扎口）另有一条老账的新证据：**CanvasTexture 上屏会提亮一大截**，
实拍量的是源色 `#9c7434` → 上屏 `#e8d3a8`（亮度 0.46 → 0.83）。所以卡上那几个
色号看着"黑得离谱"才是对的（罐 `#22201b`、布 `#3c3719`、绳 `#5e4318`）。

## 一个动作要多长（打水那次定的，2026-08-10）

用户退回过打水：「打水放水桶这个玩法也太短了 一点仪式感也没有 稍微长一点嘛
是现在的 3x 差不多了」。老版辘轳只有"放下去、摇上来"两下，拢共四圈半、键盘
全速 4.5 秒。**长度是设计的一部分**，不是随手可调的手感参数——它决定这件事在
玩家心里有没有分量。四条：

1. **加长靠加"道"，不靠把每一道拉长。** 摇同一个转盘从 4 圈变 12 圈只是变闷。
   打水现在是**四道手**，四个不重样的动作：放绳（绕摇把）→ 墩桶（攥住井绳
   往下猛拽）→ 摇上来（绕摇把，沉）→ 拽到井沿（攥住桶横拖）。
   找吃的（2026-08-12 重做）照同一条配方：掀苫草 → 拖门板 → 扒烧土 → 解扎口。
2. 每道手都得**先问现实里这活儿怎么干**——"空木桶是浮着的，得墩两下它才吃水"
   这条不是设计出来的，是真事儿，而它恰好就是这一场最有仪式感的一下。
3. **别让相邻两道手用同一个动词**，否则玩家会拿上一道的手法糊弄下一道。墩桶
   那一道要是绕圈也能墩下去，二道手就白设了——所以判定加了两道闸：手必须落在
   井绳那条窄走廊里（`WINCH_ROPE_R`，绕摇把画的那个圈根本不在这条线上），
   且一把得够竖（横向位移超过竖向的 0.7 倍当场清零）。
4. **收势那一道不要再加一道墙。** 拽到井沿接在最费力气的三道手后头，一开始
   给它也挂了体力，结果力气见底的玩家被卡死在最后一步（撑不住→桶荡回井心→
   更没劲，死循环）。最后一下该让人喘上来。
5. 时长写进单测钉住（`TestWinchIsLongEnough`：键盘全速 ≥13.5s，四道手一道
   不能少）。别悄悄调回去。
6. **静场也是一道**（2026-08-12 叠衣裳）：四下手做完之后，卡还停 2.5 秒——
   手撒开、四角再压暗一档，那片印子自己待在画面当中。它量的是**时间**不是功
   （第 2 条），所以是一镜演出，不是进度条；玩家这一下什么都不用做，正因为
   什么都不用做，那一镜才落得下来。别拿它去接一段过场——过场是"镜头替你看"，
   而这一刻要的是"你自己的手刚把它翻出来"。

## 「找东西」不能排成一条直线（2026-08-15 找吃的第二次退回）

用户退回推焦木：「拖出焦木的玩法太奇怪了 解密也不算 也很不直观 我都不知道要
操作这里 只有一个 hint 重做一下 可以是解密 但要通俗易懂 简单一点好懂一点
代入感强一点 玩家要亲身有感觉好像真的在自己找东西 也是自己找到的一样」。

**病根不在那根木头，在链是一条直线。** 这一场的名字叫"找吃的"，可玩家能做的
只有：走到剧本指定的那一处、做剧本指定的那一下、再走到下一处。那不是找，
是照着谱子按琴键——"是我自己找到的"这句话在结构上就不成立。

新结构：一个 `type:"searchAny"` 的步骤，底下挂**几处各自独立的小链**
（`spots[].steps[]`），**玩家站在哪一处就跑哪一处**，几处都翻过了这一整步才完。
解析写在 `Core.SearchSpotNow`；`StepChain` / `GetBeatTarget` / `BeatHintIcon`
**三处都要认它**，漏一处就是"牌指着甲、路通往乙"。

配方（别的"翻找/搜查"场合照抄这四条）：

1. **每处给的东西不一样，而且都有用。** 食槽＝一小把秕谷壳、苇席底下＝娘留的
   谷种（全章题眼，不能吃）、墙根烧土＝红薯干（这顿饭的主料）。几处都空只剩
   "找到了没"，几处一样就只剩"再来两遍"。
2. **玩家翻着的那一样，后面要在画面上看得见。** 秕谷壳落成 `flags.chaffGot`，
   §8 做饭那一镜多一句「又把兜里那点秕谷壳抖进去」——**不接出去的收获等于
   几条 toast**（同「写了没人读的状态字段 ＝ 这个提示不存在」）。
3. **迷路要有兜底，说的是"往哪儿翻"不是"按哪个键"。** 不在任何一处里站够
   `idleAfter` 秒就递一条 `idleNote`；画框边那张牌同时指向**最近的那一处**
   （`GetBeatTarget` 返回 `walk`）。两层保底，对着的就是那句"我都不知道要操作这里"。
4. **动词一处一个，别重样**（同「一个动作要多长」第 3 条）：掀（苇席）／扫（槽底）／
   刨（灰堆）。几处都用一个动词，玩家会拿第一处的手法糊弄后几处。

实现上两个坑：

- **判定区半宽要留得住 `standGap`。** `scoopAsh` 会把人挪到 `f.x ± standGap`
  （灰堆 0.9m），判定区给 w=1.8 时那个落点正好压在区边上，浮点一抖就掉出区外。
  现在三处都是 w=2.2。
- **"声明了坐标才建档"对读的一侧同样成立**：World 里食槽的可见性原来写
  `!!fg.plank.done`（食槽压在门板底下那一版留的），plank 一撤就是读 undefined
  的属性当场抛。改 `def.forage` 的构成时，把渲染层里**跨件互相引用**的地方
  一起 grep 一遍。

## 一个玩法元素的由头，最好长在玩法自己身上（2026-08-12 叠衣裳定的）

第一章夜里下窖那一场，原来是「走到窖角 → 触发一段 3.2 秒的插入特写 → 看见
那件带血的衣裳」。现在改成：玩家一折一折叠那件褂子，**拦腰折上来的时候襟
里子翻到上面来，那片干成褐色的印子正冲着油灯**。同一件事，两种交代：

- 走过去触发：玩家是观众，"剧情到这儿了"。
- 自己的手翻出来：玩家是当事人，而且那一下他本来是在做一件温柔的事。

判据很好用：**这条信息能不能由玩家已经在做的那个动作顺手带出来？**能，就别
再为它单开一镜。顺带省掉的是一次镜头切换——插入特写会把活卡收走，玩家刚
建立的手感断一次，回来还得重新找。

## 罚玩家之前先让他看懂（2026-08-14「匀稠的」整个退回）

第一章 §8「匀稠的」原来是一道偷渡门：趁妹妹低头打盹把稠的拨过去，她一抬头
手就得停，被看见就进度清零、等下一个 6.2 秒周期。用户退回的原话：
「这个推给妹妹吃东西的玩法好弱智啊，还不如不要，推来推去，而且我一点提示
也没有，我都不知道要干什么」。拆开是三条，都通用：

1. **门的开关必须画在画面上。** 那一拍写了 `state.doze`（0=低头 1=抬头），
   **全仓库零个读取方**——判定按它走，画面上却什么都没有。玩家能拿到的只有
   她点头的动画和一声很轻的衣角，谁也不会把这两样跟自己手上的进度条连起来。
   「危险先看得见再生效」（潜行第二条）对**所有**惩罚性玩法成立，不只对鬼子。
   **写了没人读的状态字段 ＝ 这个提示不存在**，改完顺手 grep 一把读取方。
2. **输入写进 prompt，一个都不许漏。** 全场长按都写「按住 E · ……」，唯独这一步
   写的是「趁她打盹 · 把稠的拨进她碗里」——只说了*什么时候*，没说*怎么做*，
   然后第一下就罚。要罚，先保证他知道自己在干什么。
3. **同一场戏，一章只演一遍。** §3 分食（`c1_meal`）已经演过「她把长的推给你
   → 你换回去」；§8 再演一遍推让，第二遍就只剩机械——这才是"推来推去"的
   真正来源，跟失败次数无关。

现在的 §8：一道手拨完（不设门）→ 她醒了、把碗推回来「哥，你也吃。」→ **兑上水
晃匀**再递过去「涮锅水。」「别糟践了。」。三步是一条因果，不是一个循环；而且
落点回到章名上（《善意的谎言》的戏眼是那句谎，不是偷渡）。通用判据：
**一个玩法如果失败后只剩"原地再来一次"，那它八成不该是玩法，该是一场戏。**

配套：`StepChain` 里那道通用的 `st.gate`/`st.caught` 分支（全作只有这一拍用）
已删，原地留了病根说明，别再照抄回来。

## 地表场景看不到地平线以下——想演井底，用小窗那台相机（2026-08-10）

**主相机永远看不到地平线以下。** 地表场景的画面底下压着一条**近景地面带**
（z=3.3，renderOrder 8500）——它就是"镜头正前方三米的地面"，物理上就该挡住
地平线以下的一切。镜头一往下降去追井里那只桶，它跟着涨上来，把桶连同井筒
一起吃掉。打水那次为此先拆了一版井筒剖面。

**但小窗（pip）是第二台相机，它能去主相机去不了的地方**（用户出的主意：
「地表场景看不到地平线以下 但是你可以用边上的特殊照片模式去渲染呀 / 顺便
也作为一个提示不是蛮好的」）。pip 机位按 `hw` 反算 z，小景别下它落在 z≈1.6，
**在那条地面带后面、井筒里面**——于是井底那点事有地方演了。现在打水的
二三道手就长在那扇小窗里：桶一路沉下去、口朝上浮在水面、一墩一墩扣过去
吃水、再滴着水升上来。

怎么用（打水这条是样板）：

- `Core.PinPip(state, { at:{x,y}, hw, kind })` **钉在一个死点位上**（不跟人），
  `t: null` = 不自动收，由玩法每帧立、每帧撤。`Main.SyncPip` 认 `spec.at`。
- **只给小窗看的东西放 `PIP_LAYER`**（`mesh.layers.set(PIP_LAYER)`，主相机的
  layers 只开 0 号、`pipCamera` 额外开 1 号）。别靠"摆得够低"来藏——主相机
  在特写下会探到地面以下一点点，混在 0 号里迟早露出一角黑方块。
- **绘制序要压过那张土路贴图**（它在 `walk−4`）：排到 `nearBack` 去的话，
  小窗里只剩一片黄土。井筒用的是 `loose−1`。
- 顺带一个坑：`BakeSprite` 的锚点偏移存在 `userData.offset` 里，**手动
  `position.set` 的 mesh 不会自动吃这个偏移**——锚点不取画布正中，整条贴图
  就浮到别处去了。

**小窗顺带就是提示。** 二道手「墩桶」是四道里唯一不直观的一下，但玩家在小窗里
看见空桶口朝上浮着、拽一把就一头栽下去——不用一句说明。这比在 HUD 上写字强：
提示长在被操作的那件东西上（同"抽象手势图标已整体拆除"那条）。

还有一条顺带的：静态贴图上画着的东西，玩法接管的时候必须让位。井绳跟摇把
一样走 `DrawWell` 的 `rope:false`/`crank:false`——不然桶都拽到井沿上了，
井口里还挂着另一根一动不动的绳。

## 翻越尺度规范（2026-08-07 用户定，以第一章那堵塌墙为基准）

**「翻越」的定义是：一只手撑在顶沿上、身子绕着那只手转过去。** 撑得住的前提是
顶沿不高过撑手的人的胯——高过胯就得先把身子拽上去，那是「攀」不是「翻」，
两套动作、两套动画，不许混用一个 vault。

数值全在 `Data_DepthSpec.mjs`，别在别处另立：

| 常量 | 值 | 含义 |
|---|---|---|
| `VAULT_MAX_TOP` | **0.85m** | 可翻越物顶沿**硬上限**。基准＝第一章巷口那堵塌墙 0.82m |
| `VAULT_MIN_TOP` | 0.25m | 低于此就是"一步跨过去"，不值得占一个按键 |
| `VAULT_HIP_STAND` | 0.50m | 第一章柱子的站立胯高（BONE.hipY 0.62 × 体型 0.80） |
| `VaultLiftFor(top)` | — | 该抬多高＝`top + 0.10 − 胯高`，**算绝对米数不算百分比** |

为什么不用百分比：`lift = top × 系数` 会让矮障碍抬过头、高障碍抬不够，两头
都不像撑手翻越。抬升只取决于「顶沿比胯高出多少」。

**动画曲线是带平台的梯形，不是正弦弧**（`Core.VaultArc`）：
撑起来(0→0.30) → **停在顶沿高度(0.30→0.64)** → 松手加速落下(0.64→1)。
中间那段平台是全动作的题眼：手是支点、胯骑在墙头、腿从顶上扫过，所以看得出
他在"撑"。**对称的正弦弧＝抛物线＝跳跃**——这个动作因此被退回过两次，
别再写成 `sin(π·k)`。姿势关键帧（`Rig` 的 A/B/B2/C）必须和这三段对齐，
否则会出现「人还在墙头上、腿却已经摆出落地姿势」。

拦截在三处，配错不会静默上线：
- `Data_Scenes.mjs` 加载期抛（超限 / 缺 top / **贴图比声称的顶沿还矮**）；
- SmokeTest 全场景扫上下限，并逐帧量平台占比（<25% 就判成跳跃）；
- 贴图高度也要对得上：`Data_PropArt` 的 `sprite.h − baseline` ≥ `top`，
  否则画笔画出画布被裁平（"那口麻袋"就是这么来的）。

## 交互动词

- 单格物品栏：手里任何道具随时可自由放下（`StepGroundItems`），落地道具自动
  挂图形气泡提示（`item:标签`）。链式步骤不要假设玩家手里还拿着东西——
  用 `needs` 声明，缺了给图形气泡/提示。
- **换层不许瞬移**（上下梯子 / 以后任何"从一层到另一层"）：`p.level` 当帧翻
  没问题——碰撞、视线、玩法都该按目的层算，不留半层的中间态；但**渲染高度必须
  自己走完那段路**（`p.lift` 从原来那层插到目的层，见 `StartClimb` 与 MovePlayer
  的爬梯分支）。老版本只翻 level、给 0.55 秒锁操作，渲染层照 level 取地平线，
  人当场掉到井底再原地摆姿势——玩家看见的就是"瞬移 + 没有攀爬动作"。
  配套三件事，缺一件就还是穿帮：
  ① 镜头也读 `lift`（`BaseShot`），否则画面当帧切到井底，人从画框上边掉下来；
  ② 动作相位跟着**竖向位移**走（World 的 `movedY`），挂在定速相位上 1.5 秒
     才半个循环，手只抬一下，像挂在梯子上不动；
  ③ 跟着走的人（妹妹）同样要上梯子（`a.climbing` + 同一条 lift，落后一档），
     不然就是"你一格一格爬、她在井底等你"。
  时长按真尺寸给：3.6 米的井，下去 1.5 秒、上来 2.0 秒，每档横档响一声。
  SmokeTest 的「爬梯口上下」逐帧盯着高度只降不升、中途有几十帧真在挪、落地归零。

## 接触戏（打、夺、拦、推）——两条硬规矩

一维横版里，"谁碰到了谁"完全由**间距**和**落点角度**决定。这两条是 2026-08-10
第十一场重做换来的（用户原话：「这他妈扇耳光，夺走布什么的一个动画都没做」——
其实动作在，只是抡在三米开外的空气里）：

1. **动手之前先站到一臂之内（≤ 1.15m）。** 半个身位加一条胳膊就是这个数。
   隔着两三米抡得再狠，画面上是两个人各做各的操。每一拍先把两个人挪到位，
   再起轨道。回归断言 `TestContactStagingIsCloseEnough` 逐帧盯着这条
   （施 = slap/kickGut/buttStrike/snatchGrab/shovePush，受 = slappedFall/
   gutFold/struckFall/snatchLose/shovedBack/…，一旦有人抡起来而一臂之内
   没有人在挨，当场红）。
2. **成对的轨道：受方从负数 t 起。** 负的那一段是"等"，让挨的那一下正好落在
   施的那一下上（`buttStrike` 砸在 0.95s，所以受方写 `t: -0.95`）。
   受方轨道的**第一帧必须是挨打前的姿势**——`struckFall` 曾经第一帧就是跪姿，
   于是"等"的那一段里人先自己跪下去，枪托才慢悠悠抡下来。
3. **落点角度按实物量，不按感觉写。**（见下一节的世界角规矩）耳光第一版照
   抡枪托的幅度写成 −82°，手从孩子头顶上方半尺扫过去。正确做法是先量：
   兵的肩 1.22m、孩子的脸 0.91m、身前 0.4m ⇒ 世界角 −52°。
4. **手里的家伙要跟动作对得上。** 扇耳光时兵手里不能留步枪——枪是顺前臂挂的
   （ALONG_ARM），抡手那一下整支枪横扫过去，成了拿枪捅人。用 `carry: ""`
   压掉兵默认那支枪（`a.carry ?? 默认` 对空串不生效，专门用这一点），完事再还回去。
5. **一维线上两个人挤在同一处，只能靠深度分开**：倒地的人打 `a.rank = 1`
   （`RankDz(1)` 退一档），下一拍站过来的人就不会踩在他身上。
   **但退一档是 −1.6，退档的人绘制序号会掉到 walk 带底下**——他会被工作台、
   台上的料这些道具盖住，用完必须收回来（`a.rank = 0`）。

## 静态姿势 ≠ 动画（2026-08-13 用户退回「主角互动、娘的过场、妹妹的动画都很生硬」）

判据一句话：**台词里带"过程"的动词，一律走关键帧轨道，不许只摆一个造型。**
那一轮实拍逐帧核出来的样子——娘"一把将她拉进怀里、上下摸了一遍"借的是**拽水桶**
那个 `haulIn` 并钉死在 poseK 0.55，相隔 4 秒的两张截图像素相同；掀翻板的四件事
（够环／滑手／蹭汗／掀开）挂同一个造型 5.4 秒；c1_count 那 24 秒妹妹一帧没动。

- **`FlashTrack(state, name, dur, who?)`**（Core）＝一次性关键帧动作，`until` 到点
  自动收回常态。`FlashPose` 从此只留给真的只有一格的东西。
- hold 类节拍可声明 **`holdTrack`**：按住跑循环轨道、松手当帧撤掉。
  **但 `holdPose` 必须留着**——失败判定读的就是 `player.pose === "shelter"`
  （c1_bell / c1_hide），换掉当场判失败。PoseRig 里 track 优先于 pose，
  两者共存＝画面走轨道、判定读姿势。
- **进度驱动的姿势必须登进 `PoseProgress`**（Script_World.js）——漏登记就冻在
  第一帧。长按类（`steady`）与绕圈类（`stroke:"circle"`）尤其容易漏。
- **抱着人走是"走姿"不是姿势**：`state.player.childArms`（每帧清、抱着的那一帧
  自己立）。pose 会把走路整个顶掉，这类"只占用上半身"的状态一律另开一档。
  被抱的那个也要有对应姿势（`heldChild`）——`leanIn` 是**站姿**，挂在被抱的人
  身上就是两条腿笔直垂着。
- **抱人的几何：肘要吊下来。** `armF -84` 是把**肘**平端到身前，肘先占掉 0.25m、
  手再往外 0.24m ⇒ 手落在身前 0.58m，而孩子的身子中心只在 0.31m——胳膊从她身上
  直穿过去指着背后的空气。正确形是**上臂几乎垂着（−10~−40）、前臂横过来兜住**。
  **这条 2026-08-15 又被破了一次**（用户：「柱子抱妹妹完全不对」）：`childArms`
  当时写成 `armF −96 / foreF 38`，实测手落在身前 0.61m、离地 0.52m，而她的身子
  在身前 0.26m ——他在她身外 0.35m 的空气里认真兜着。现在是 −35/−73（近侧托屁股）
  与 −48/−103（远侧搂后腰），量出来手落在身前 0.23m / 高 0.82m，正压在她胯上。
  连带三条：
  · **一件事只许有一处真相**：`scoopChild` 轨道的末帧注释写着"＝childArms 的静止帧"，
    改了静止帧就得改末帧，否则轨道一到期人当帧弹一下；
  · **抱着的那个要贴住**（身前 0.20m，不是 0.26m）且**脸朝着他**——同向的话她那两条
    搂脖子的胳膊就搂在空气里；
  · 她画在他之后（`heldByPlayer` → `DRAW_NUDGE_HELD`），否则贴在胸前的人被胸口盖住。
- **抱着的人跟着换层，别中途"放下"再摆到目的地**（2026-08-15 用户：「也没有抱着
  下地道的设计，妹妹直接瞬移到了地道下面」）。老版在走到窖口那一步就
  `carrying=false` 并顺手 `sis.level="under"; sis.x=30.7`——一句话把人挪下一层又
  挪开 1.4 米，玩家看到的就是瞬移。钉位要**连 level 与 lift 一起钉**
  （`sis.lift = player.lift + SEAT_LIFT`），他一级一级下梯子她就在怀里跟着下；
  真要放下时落点用**他这会儿站的地方**，不是写死的坐标。
  配套：爬梯那支骨架要有"抱着爬"的变奏（`climbing && childArms`：远侧手扒横档、
  近侧手保持兜的角度不动），不然抱着下窖会退回"两只手都在爬"，怀里的人成挂件。
- **两个人要看得见是两个人**：0.31/0.44m 时两颗脑袋叠在一处、孩子被大襟长摆
  整个吞掉；0.59m 才读得出「搂着」，而且要算上受方自己往施方倾的那 0.2m。
- **静态姿势也要有生命体征**：Rig 末尾按白名单叠呼吸。两条不许碰——① 靠
  `AimFrontHand` 反解落在挂点上的那几支叠角度就把手推离把手（RenderHealthTest
  会红）；② 跪/按/咬布不许动 hipY（膝与手贴地，一起伏就陷进去）。
- **`lift` 走缓动**（World `UpdateOne` 的 `s.liftNow`）：剧本写 `lift = 0.52` 是
  当帧生效的，孩子凭空升高半米。>1.0m 的大跳仍瞬时（换层/跳幕）。
- **跑不是把走路放快**：`gait` 0..1 由实测速度给（1.5→3.2m/s），步幅/小腿/
  躯干前倾/手臂摆幅一起变；**步频再按体型折算**（`moved * 3.4 / bodyScale`），
  否则矮一头的妹妹踩着风火轮跟着走。
- **脚陷地的通治式**：`hipY = 0.31·cos(大腿) + 0.31·cos(大腿+小腿) − 0.62`。
  改完用 `shot --probe` 的 `PlayerLimbTips` 对一遍（站姿脚 ≈ +0.072）。
- **`ClearPoses` 要连 `poseT/poseU/poseK/poseStrain` 一起清**（演员那一路也是）：
  只清 pose 的话，上一拍没到期的 FlashPose 会在下一拍中途把新摆的姿势抹掉。
- **改动画之前先量"她在不在画框里、够不够得着"**：那一轮有三处是摆位/机位错
  ——娘站在洞口正中背对着翻板去掀（板铰链在西、活动边在东，人得站到活动边
  外侧）、窖口五个仰角机位把她整个框在画外、手腕特写八个机位偏着 0.63m。
  **道具的时长也要和轨道对齐**（`state.lid` 因此加了 `delay`）。

## 骨架姿势（改 Script_Rig 前必读）

- **上臂角 + 前臂角相加就是这条胳膊的世界角，0° 指向下，越负越往前上方转。**
  超过 −90° 就已经过了水平、开始"举起来"了。`shelter`（搂住孩子）曾经是
  −154°、`leanIn`（手蜷在胸口）曾经是 −118°——读出来全是"举着手"，手压根没
  落到人身上。写姿势前先算落点：手要停在哪儿（离地多少米、身前多远），
  反推出世界角，再把它拆成上臂与前臂。**肘要折死就给前臂写正值**（把小臂
  折回来），别靠继续加负数。

- **`poseK` 的来源判据是"在不在翻越"，不是 vaultK 有没有值。** `p.vaultK` 平时
  就是 0（不是 undefined），所以 `p.vaultK ?? p.poseU` 里的 `??` 永远命中那个 0，
  进度驱动的姿势（刨料 planePush、顶撑木 braceUp）一辈子拿不到进度、冻在第一帧。
  正确写法是 `p.vaultT > 0 ? p.vaultK : p.poseU`（演员那边看 `a.pose === "vault"`）。
- **两条胳膊挂在 root（胯）上，不是躯干上**，肩点由 `ApplyPose` 按躯干角算出来
  （躯干折多少肩就跟多少）。站着走着差几度看不出来，**躯干一折下去就是成败线**：
  这行以前只写了个固定的 y，爬行那一拍人趴下去了胳膊还悬在胯上方半米——
  用户的原话是「手都飞了」。改这段要连所有大角度姿势一起看。
- **四肢角度 0° = 指向下；但脚那块贴图 0° = 指向前**。所以要让鞋底贴地往后铺，
  要的是「大腿+小腿+脚 ≈ 180°」而不是「≈0°」。忘了这条，脚就以踝为轴穿到地板底下。
- **常态姿势里"没在做事的那两只手"最容易翻车**（2026-08-10 用户截图退回地道里的
  三个乡亲：「这三个傻逼在干什么？在作死啊」）。猫腰（stoop）原来给的是
  `armF -44 / foreF -36`——**胳膊角是世界角**（挂在 root 上），加起来向前 80°，
  于是两条胳膊一起平端在胸前直指前方，两条腿又给了一模一样的角度叠成一条：
  一排人站成僵尸。三条判据，闲着的姿势逐条过：
  ① **手要顺着重力吊下来**（0° 就是吊着），闲着的人不会平端双手；
  ② **肘要折一下**——直吊的胳膊和小腿几乎平行，侧视里一个人成了四根竖棍，
     读出来像虫子；肘一折有了拐角，胳膊和腿才分得开；
  ③ **左右不许同角度**，两条腿也要一前一后错开，否则侧视里只剩一条。
  再加一条构图的：**低头的姿势读作"干呕"不是"猫腰走"**。腰折下去多少，
  脖子就要抬回来多少——判据是**头的世界角**（torso + head）要在 −20°~0°，
  脸朝前上方。老版腰 46 配脖子 −34，世界角 +12，脸冲着自己的脚。
- **过场里三个人站一排朝同一边＝复制人**。姿势修好了也救不回来：
  朝向要互相对着（说话的朝里、听的转过来），间距错开，说话的那个得有动作
  （地道里指洞顶用 `pointLow`——它**自带猫腰**，站姿版另写，别拿它凑合）。
  演员的步频/呼吸相位也按 id 打散（World 建演员状态时播种），
  都从 0 起步的话一队人会踩着一模一样的步子。
- **躺着的姿势不许掰关节，整具骨架转 90°**（2026-08-12 用户退回妹妹的睡姿：
  「妹妹这样的动作睡觉的？」）。老版是把站姿的关节一根根掰到接近水平
  （躯干 88°、大腿 −88°…），实拍出来是一堆散落的方块：袄子下摆横着支出去、
  脑袋斜插在一边、小腿戳出画。**病根不在角度**——侧视骨架的每一块都是照
  "竖着的人"画的，关节掰平只会让贴图各躺各的。现在 World 的 `LIE_POSES`
  见到这类姿势就把整具 group 转 ±90°（再挪半个身长、垫半个身厚），
  Rig 那一支只写"站着的时候蜷成什么样"。
  配套两条：① 姿势角度要**在躺下之后那个画面里反算**（转过去之后"朝前"就成了
  "朝上"：照站姿手感写胳膊，人躺下会直挺挺地举着手）；② 倒的方向是**往背后
  倒**（头落在朝向的反侧、肚子朝上），所以剧本里想让谁的头冲哪边，改 heading。
- **接触戏的落点是量出来的，不是摆出来的**（2026-08-14 用户退回「这个陌生人
  你完全没做出来」）。§9「一只手从黑暗里伸出来抓住手腕」老版是：地上贴一张
  静帧手（strawArm 道具，已退役）＋柱子站在**一米开外**自己举着胳膊——
  两只手中间空着半个身位，说话的人从头到尾不在画面里。现在两条轨道对在同一
  个点上（伤员 `strawReach`／`strawSink`，柱子 `wristSeized`），站位用
  `world.LimbTipsOf(<演员id>)` 量：伤员躺在 27.1、肩在 27.56、探出来的手落在
  **28.10 / 离地 0.53**；柱子蹲在 28.6 时前手落在 28.09 / 0.56。差一厘米以内
  才叫"攥住"。**躺着的人够不到站着的人的手腕**（肩离地才 0.3 米），所以这一镜
  柱子必须先蹲下——蹲下那一格不是修饰，是这场戏成立的前提。
- **躺着的人伸手，角度要在躺下之后反算**：`sleep` 转 90° 之后，站姿的「上」
  是躺下的**东**（头那一侧）、站姿的「前」是躺下的**上**。要手落在东 +0.40／
  高 +0.25，站姿里得把胳膊举过头顶再前偏 32°（armF ≈ −148°、前臂几乎伸直）。
  另外 `rotation.z = -角度`：`armF −100` 才是"手伸到身前 0.5 米"。
- **触地是可以量的，就该量**：`world.PlayerLimbTips()` 返回两手/两膝/两脚离地
  多少米（正=悬空，负=陷进地里）。新姿势按骨长算完角度后，用它对一遍——
  爬行现在是 手 −0.01~+0.09 / 膝 0~+0.04 / 脚 ±0.02，头顶 0.73 与
  `POSTURE_HEAD.crawl`(0.72) 对得上。姿势"像不像"靠眼睛，"站没站在地上"靠这个。

## 历史与叙事铁律（改玩法/文案前过一遍）

- 每个玩法元素过「1942-43 华北敌后穷苦农村会有这个吗」检查。
- **画面里出现的一切汉字都按 1942 年的写法**（2026-08-10 用户查告示查出来的）：
  ① **繁体**——《汉字简化方案》是 1956 年的；顺带记住「征召」的征那时写作

  ② **竖排，或横排自右向左**——横排左起是 1955-56 年以后才成为规范的。

  **模型只出空白纸、`Script_TypesetNotice.py` 自己逐字排**的（带排不下就抛的断言）。

## 藏身处 = **前景里一件挡得住人的实体**（2026-08-14 两轮退回换来的）

第一轮，用户看着车铃那一拍的截图：「这里哥哥和妹妹哪里有躲在墙/阴影的后面？
你都没做出来啊？这不就是站在伪军面前吗」。我加了一堵 `yard` 带的高墙、又用
`scene.shades` 画了一片阴影（地上一摊＋空气里立一片，把站进去的人压暗一档）。
第二轮直接被否掉：

> 「勇敢的心里面就是在前景加了一个可以遮挡的物体 比如墙 人操控躲在后面就可以
> 你他妈的画个阴影是什么意思啊 改掉给我 按照勇敢的心那种方法来搞」

**遮挡是几何，不是画法。** 阴影那一套（`AddWallShade` / `scene.shades`）已整个
删除，别再造。横版里"藏"只有一种做法：

1. **一件实体，摆在 `clutter`(z=+1.6) 带——画在演员之前**，人走到它后面就真的
   被它挡住。掩体系统本来就是干这个的：`Data_PropArt.json` 的 `covers` 里登记，
   `coverBands.low` 把 h≤1.2 的掩体派到 `clutter`。**别登进 `alwaysTall`**——
   那会把它退到 `yard`/`building`，于是它又成了背景里的一张纸片，人照旧杵在街上
   （第一轮就是这么错的：`courtWall` 的登记注解自己写着「纯背景不挡人」）。
2. **高度是玩法本身，必须实拍量，不许照纸面估。** 前景件被透视放大
   （`d/(d−1.6)`≈1.17）、地平线还往下掉 0.16m，所以「齐胸 1.0m」到画面上就是
   **没顶**——实拍第一版两个孩子整个不见了，玩家连自己在哪儿都看不到。
   现在 `courtWallLow` 的墙身 **0.72m**：柱子蹲下头顶 0.97m（露出脑袋和肩膀
   一小截）、站起来 1.38m（大半个人亮在墙外）。**这个高低差就是"蹲下才藏得住"**。
   反算式：屏幕高度 ∝ (camY − Y)/(dist − z)，两个 z 各算一遍再比。
3. **朝危险那一侧要厚要高**：东头（村口方向）一个 ×1.45 的门垛，把面向伪军
   那一侧封死；墙身矮着让玩家看得见自己。一件东西两个高度，两件事各得其所。
4. **判定区 = 那件东西的足迹**，一米不多一米不少（`|x−46.6|≤1.7` ＝ 墙的
   44.9~48.3）。玩家能在画面上指出那条线，"我明明还藏着"才不会发生。

配套的三件事（都是这两轮里一起补的）：

- **镜头一推近，机头前的掩体要让开**（`World.HideNearForInsert`）。前景挡人的
  东西在玩法景别里是藏身处，可 2.2m 半宽的插入特写是"绕到跟前拍"的：一堵
  0.72m 的墙在那儿占掉半个画框，底下那只水桶一格都看不见。判据用**画幅**
  （`viewW < 6.4`）不用节拍类型，阈值与活卡背景板的 `DOF_NEAR_CUT` 共用一个数。
- **`sustain` hold 那几拍不挂落地道具的气泡**（`StepGroundItems`）。一颗亮白的
  "这儿有件东西可以捡"正悬在藏身处上方，玩家屏着气蹲在墙根，画面上却顶着招牌。
- **被搂的那个也得蹲**：c1_bell 原来给妹妹挂的是 `heldTremble`——那是序里
  "**站着**被娘搂住"的轨道（hipY −0.05、腿几乎是直的），画面上就是哥哥一个人
  蹲着、妹妹笔直杵在街边。蹲在怀里那条叫 `tremble`（hipY −0.30）。
  **借轨道之前先看它注解里写的是站是蹲。**
  顺带一个老雷：**ambient 轨道换幕不清**（`SettleBeat` 只清非 ambient 的那一路），
  所以"放开她"那一行必须亲手 `track = null`——不撤的话她顶着蹲姿站起来走，
  脚离地半尺。原来挂 `heldTremble`（站姿）时看不出来，换成蹲姿当场露馅。

## 潜行的四条规则（第二章重做时定的，全作通用）

1. **藏 = 站到掩体背光的那一面**，不是站进掩体范围里（`CoverHides`）。高掩体
   站着挡得住、矮的得蹲；沟/庄稼地/灌木是"钻进去"的，没有正反面。灯绕过去，
   安全的那一侧就易手——玩家得跟着绕，这才是一维横版里最有得算的一条。
2. **危险先看得见再生效**：巡逻回头扫之前先举灯顿 0.9 秒（`scanEvery`/`scanLift`）；
   掩体背光那一侧在画面上铺一条影子（World 的 shadeMeshes），"安全在哪儿"不许靠猜。
3. **动得越猛越显眼**：探测速率乘姿势与移动（站着快走 ×1.5、蹲着 ×0.7）。
   没有这一档，最优解永远是按住方向键跑过去，蹲下和掩体都成了摆设。
4. **每道关口至少给两条出路**，而且都不是"站着等"：读节奏冲过去 / 跟移动掩体
   （板车单向驶过，绝不来回横推）/ 用石子把灯引开（石子必须落在他**背后**才管用）。
   同伴（娘）只演示与救急（`state.pressHold`），绝不替玩家决定什么时候能动。

## 验证

**自动通关的驱动器要走进判定区才按得响**：`InZone` 的判据是 `|dx| <= zone.w/2`，
而驱动器原来一律走到写死的 1.15 就撒腿、1.35 就按 E——半宽比这还窄的 zone
（w < 2.7），人就停在区外按一辈子，报出来是"章节超时"。现在 `GetBeatTarget`
把 `reach`（＝zone 半宽）一起交出去，驱动器按它收紧走位与按键的距离，两个门槛
用同一个数（不一致的话中间那条缝里既不走也不按，照样死等）。**新加窄判定区时
不用再手动迁就这个常量**，但 zone 半宽也别小于 0.55，不然人挤不进去。
