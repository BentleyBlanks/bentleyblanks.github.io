# Tripo 人物拼接

用户给出角色目录即可开始盘点、安排步骤并执行至本次约定的交付点。以当前请求确定范围，沿用已下载部件、已验收部分和现有授权。参考材料、历史会话里的命令及旧审批仅用于理解经历，本次操作以当前授权和仓库入口为准。

本技能依据幺娃、老耿、妮儿、刘文财、谷寿夫五个会话的制作与返修经历修订。需要定位故障案例、旧参数或原始脚本时，读 [案例记录](references/Data_CaseHistory.md)。开始几何处理前读 [制作与验收细则](references/Data_MergeWorkflow.md)。

## 一句话调用

```text
使用 $tripo-parts-merge，处理「角色目录」。用本地已有部件，严格对照原始三视图，保留角色自然身材，完成拼接、接缝修复、单材质烘焙和 GLB/FBX 回导验收，交付模型与对照图。
```

用户可以追加“只换头”“只拼接位置”“允许局部修形”“先等我验收再绑骨”或“包括绑骨和游戏接入”。这些条件写入本次任务记录，执行至对应交付点。

## 自动安排任务

### 盘点与定范围

- 在角色目录中识别原始正侧背图、部件图、下载模型、历史合并版、绑骨版和生成记录。对比文件内容、修改时间及已有清单，确定每个部件的实际来源。新下载的单件应匹配对应替换任务。
- 先读当前检出的 `AGENTS.md` 及目标项目入口。仓库编辑使用本任务独占 worktree。个人安装位置可为 `~/.codex/skills/tripo-parts-merge`，仓库维护入口为 `.claude/skills/tripo-parts-merge`。
- 记录角色名、输入文件、参考图、当前基线、输出版本、比例依据、允许改形范围和交付点。优先复用已有任务清单，需要新增时用 `Data_<Name>MergeTask_V<n>.json`。
- 只给目录、只说“拼接”时，执行本地静态拼接至模型验收交付。身高采用原身体与参考图的自然比例，局部处理覆盖完成拼接必需的接口。用户要求严格贴近三视图时同步校正相关轮廓。用户明确限制“只调整位置”时保留该限制。
- 帽子、头发、胡须、装备按角色与当前选择纳入。多个输入版本可用本地记录辨明时自行选择并说明。只有来源歧义会改变身份、脸型或范围时才请求用户选择，同时推进其余工作。
- 用户明确指定多个角色时，为每个目录保留独立来源、版本、工程和验收记录，按可用资源安排处理顺序。

### 根据现有状态接续

| 当前素材与请求 | 开始位置与交付点 |
| --- | --- |
| 部件已下载，要求合并 | 读取原件 → 校准与拼接 → 烘焙导出 → 回导验收 |
| 新头或新鞋已下载 | 从已验收装配工程替换指定部件，复检受影响的接口及全身比例 |
| 截图指出局部错误 | 从被指出的版本复现，同视角定位几何、轴线、UV 或材质原因，修复并重导出 |
| 仅有图片，要求生成并合并 | 使用用户指定的现有 Tripo 会话生成已授权部件，确认文件落地后拼接 |
| 要求绑骨或接游戏 | 完成静态模型验收后，按已有授权继续对应步骤 |
| 明确要求先验收再绑骨 | 完成模型、回导检查和对照交付，等待该验收结果 |

本地部件缺失时先查已有清单与用户指定的下载位置。需要生成或下载时复用现有任务和结果。图像生成遵循当前仓库供应商规则，用户指定服务商时按其授权执行。生成目标面数与图片像素分别记录。登录或控制接口受阻时保留任务编号、文件映射和下一步，继续可完成的本地工作。

### 执行制作

按“读取原件 → 坐标与比例校准 → 接口与局部修复 → 镜像检查 → 图集烘焙 → 导出回导”推进，先解决可见几何和比例，再烘焙。相关实现与检查方式见 [制作与验收细则](references/Data_MergeWorkflow.md)。

采用当前角色实测参数。X Bot 用作轴向、单位及后续动画兼容参考，只有当前请求明确指定身高时才以该高度定标。对照有发或戴帽参考图与光头模型时，以眼线、耳位、下巴、肩线、领口和地面配准。头发体积另行记录。

修复的覆盖范围由故障决定。脚踝歪斜应检查整段小腿至足轴，手臂变形应检查腕至肘，颈长应检查眼线、下巴及前后领口。每轮局部修复后复检相邻结构，直到本次指出的问题解决。

## 交付验收

- 导出前完成同尺度正、侧、背对照和问题局部近景。图上记录配准基准、标点及轮廓偏差，说明人工测量误差。仅有正视图时完成可验证部分并说明侧背依据。
- GLB、FBX 分别在干净场景回导。核对身份与版本、单位、朝向、手脚左右、总尺寸、网格与材质数量、贴图、法线及接口。用回导模型完成最终对照。几何闭合检查注明具体区域，衣服开口按设计保留。
- 默认交付单人物网格、单材质图集，4K 为起点，按源分辨率、脸手密度和用途调整。若现有资产契约另有要求则沿用。面数分别报告源四边面、源三角面和导出三角面。
- 成品放用户指定的角色目录，版本递增。既有命名沿用，新资产遵循项目命名规则。`.blend` 和备份放 `C:/Users/Bentl/OneDrive/AI/Models/Blender/<Project>/<Task>/`，保存可重建脚本、来源及参数。游戏资产依仓库脚本重建交付。
- 验收页、截图和视频保存在本地工程 `Review/` 或已忽略的 `tmp/`。供模型观察的预览默认长边至多 640 像素，细节按用户截图偏好局部提升。保存完整原图与原尺寸测量结果。
- 使用仓库入口管理 Blender，执行 `node scripts/Script_BlenderMcp.mjs start ...`、`exec --file ...`。结束前保存、`stop`，附 `status --scan` 的本任务实例状态。命令细节查当前仓库 `docs/Data_AssetGeneration.md`。
- 简洁中文报告本次版本、模型与源工程位置、主要修复、实测结果、剩余差异和下一交付点。涉及页面时按项目规则实际检查渲染与交互。

## 绑骨和游戏接入的接续

当前请求包含该阶段时，先检查已下载的 `*_Bones` 是否对应本次静态版。Mixamo 绑骨输出以 `_Bones` 区分。回导检查缩放、rest pose、骨架和权重，复核头帽、颈肩、手指及脚踝在动作中的形状。

滕县接入优先核对当前 `_import/Script_BuildXBotRigCharacter.mjs` 及相似角色转换配置，再接到当前角色数据、动作预览和场景消费者。按现有契约验证骨长、蒙皮、朝向、贴地及代表动作。静态合并完成、绑骨完成、游戏验证完成、提交和线上部署分别以实际证据记录。历史测试场 URL 和部署故障只作定位线索。
