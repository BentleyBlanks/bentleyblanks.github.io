# TunnelFront1942 《地火线》轮次记录

每轮 = 设计 → 实现 → 完整游玩 → 独立审查 → 修改或删除 → 再次验证 → 提交 + 部署。
独立审查的五项标准与 verdict 逐轮记录于此。

## R5（2026-07-30）把撤离预览变成真实队列推演

- 撤离预览不再用静态公式猜抵达时间，而是在克隆状态上复用正式移动规则，逐回合推演当前队列、
  通行容量、烟流衰减、已知封堵预警、塌方与改道；`readyTurn` 明确表示进入出口复查窗口，
  不承诺群众必然安全。
- 分开呈现“容量受阻回合”与“出口窗口延迟”，并显示预测出口、首次瓶颈、支护能否真实缓解、
  到达回合的信号覆盖；因此烟在抵达前散去、敌军恢复行动、已知风险触发改道时，预览与正式结算一致。
- 回归锁定两套全压力替代顺序：北线 `伤员→两户乡亲→交通骨干` 与南线
  `两户乡亲→交通骨干→伤员`；同时覆盖全部六种发车顺序的不同时间/拥堵特征。
- 恢复实际缺失的审查接口 `Script_PlayCli.mjs` 与 `Script_AsciiMap.mjs`，可持久化局面并通过
  `new / show / legal / act / end / survey` 完整游玩、查看双层 ASCII 地图、敌军意图、预警与日志。
- 移动端 HUD 按目标、群众、单位检查器、层级控制分区；预览打开时收起目标与群众区。
  桌面及 360×640、375×667、390×844 浏览器实测无横向溢出，按钮不小于 44px、状态可见、
  console error 为 0。Toast 已移入地图栏、禁用指针，并在预览打开时隐藏。
- 冒烟测试 `49/49`；核心预测独立审查通过 1000 组随机队列/烟流/信号/纯度对拍，
  数值压力与移动端复核均为 `SHIP`，无 P0/P1/P2。

### 独立盲审（仅读 README 与 CLI）

- 四局完整路线：北枣窖静掘 2 次可解释失败、1 次胜利；西南苇井快掘 1 次胜利。
  两条胜路均在 T10 撤 5 人、T11 撤 3 人，最终 8/8、群众安全 92。
- ① 核心循环清晰有趣：**PASS**。侦察选线、挖掘支护、批次排队、抢信号窗口与洞口防御因果清楚；
  两次失败分别准确指出“未复查出口”和“信号过期、组织耗尽、入口被封”。
- ② 地上地下都有意义：**PASS**。地下承担土层、开裂、支护、容量与拥堵；地上承担侦察复查、
  出口占压、假迹、伏击与信号，单纯挖通不能获胜。
- ③ 敌军能合理反制：**PASS**。追击、占压、确认入口、封堵与灌烟均有公开因果、预警和反制窗口。
- ④ 存在多种可行策略：**PASS**。北静掘短而有返沙及近口威胁，南快掘长且需更早接通发车，
  两条路线均实玩获胜且取舍不同。
- ⑤ 无重复劳动、无唯一最优解：**PASS**。两条胜路的接通、发车、交通员行程与洞口防御节奏不同，
  批次速度、负载和容量使“快组先发”并非恒定答案。
- verdict：**SHIP**；P0 无，P1 无。P2：单格挖掘和逐格移动略繁琐，未来可评估连续路径执行，
  目前未破坏决策质量。
